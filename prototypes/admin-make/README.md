# 管理后台高保真交互原型

本轮按cece“按照上述改动重新调整原型”的指令，以完整经营任务重组入口。沿用原始Make视觉、Ant Design 6与现有依赖；只用于产品审核，正式frontend/admin、用户H5、接口和数据库未修改。

**当前适用范围：** cece随后要求收口为数字物品管理后台，订单、工厂和物流退出核心范围，并提出完整官方Pro工程迁入Umi。新版从[聚合审核稿](../../docs/proposals/admin-make-rebuild.md)进入；本文件下述长经营原型及53项证据保留为历史参考，尚未按精简方案修改或重新导出，不能作为新版功能范围、视觉或Umi验收。

## 怎样预览

下载[独立HTML](preview.html)，用桌面Chrome/Edge打开，点击“使用演示身份进入”。无需真实管理员账号。源码使用`.mise.toml`的Node版本，安装锁定依赖后运行已有dev/build命令。本轮没有重新上传Figma或公开发布。

合成数据和办理进度保存在当前标签页会话，刷新可继续；兼容已有v5记录，不自动清空。原型演示菜单可显式重置。不要填写真实密码、密钥、订单、地址或个人信息；图片仅在浏览器暂存和关联，不上传服务器。

## 页面组织

| 一级入口 | 内容与用途 |
|---|---|
| 工作台 | 新建发售、继续任务、经营概况；保留库存、配卡及有效触碰统计 |
| 商品与发售 | 发售批次、商品款式、发行档案；先准备款式和当次承诺 |
| 交付与售后 | 全局首次交付任务、换新与转售；与发售内交付使用同一份记录 |
| 物品与芯片 | 数字物品档案、芯片库存与配卡；任务进入可返回同一交付 |
| 系统管理 | 操作日志、系统与环境 |

一次发售用完整页面持续工作，含“概览／商品与发行／销售与封版／订单与交付”。概览分别统计预估、有效销售、最终发行和实物交付，展示规格/履约阶段及本次发行的触碰情况；不是用任务列表替换原统计。销售、生产与交付可以并行。

共用款式编辑及单件首交/售后办理保留1120px居中弹窗，详情保留800px抽屉。分页数据每页最多10条，候选/预览表5条。已关联发售的发行档案直接返回对应发售维护，并禁止删除造成断链。旧销售计划缺发行关联时明确提示，只保留原事实，不按同款猜测发行或覆盖旧数据。

## 建议验收的四组场景

### 1. 从商品准备到多店销售

从工作台点“新建发售”，选择已有商品或“新建商品款式”。保存新款式后自动选中，继续填写本次发售：发行方式、销售预估、当次承诺、有效销量/退款口径、供货/封样引用和交期。

帽子例子选“限时按销量定量”，预估100，设北京时间开始/结束日期。保存后进入本次发售，点“核对商品与发行→确认规则，继续渠道上架”，添加网店A和B的商品引用，各自登记已上架，再开始销售。这里记录外部网店事实，不会自动操作网店。不会提前生成100个物品或芯片。

固定总量与非限定也走同一流程，不按手串/T恤/帽子分支。固定50是数字身份上限，不能把51件确认为有效销售；超额来源可以保留为待核。限时/非限定的预估100不阻断第101件。

### 2. 接单、生产与销售期内交付

在“订单与交付”登记网店、外部订单/明细、起始件次、数量、付款/来源依据、规格与收件安排引用。同一明细多件自动逐件展开；同店相同订单/明细/件次拒绝重复，不同店相同订单号分别保留。可用网店A的80件与B的57件验证137件超过预估。

继续其中一件：投产人工核对→独立保存工厂接单→来货后进入验收。不合格暂停，记录返工依据后重新验收；每轮规格、质量及依据留在历史。异常弹窗取消后不保留待提交草稿。

合格后“为本件建档并关联”，再进入“芯片登记与配卡”。任务会携带目标物品；通过带标记的Webhook/绑定/密钥占位/双链接核验演示后，点“返回本次交付”继续同一件次。逐项检查实体、规格/编号、芯片配置与用户资料，保存品牌发货、实际交付依据。其余订单仍可待生产，不需要先封版。

限时发售封版前稳定身份存在，显示“正式编号待封版”；固定/非限定保持原序号保护。发货/签收不自动启用、建立持有人或扣换新次数。首次认领及当前实体生效的正式路径尚未接通，不能把此步当作用户使用已闭环。

### 3. 多店对账和137件封版

到期后各店实际停售，再登记已停售并进入对账。演示可使用“〔演示〕将业务时间推进到销售期满”，它只改变该原型的业务演示时间，不改认证或芯片计数；可恢复当前时间。

分别核对网店A的80件和B的57件及来源/退款依据。某店未核、件数不一致、待核订单或异常未解决时不能封版；补单或更改核定结论后须重新核对对应渠道。零有效销售不虚构正数发行量。

预览并确认：预估100、最终137并列解释，编号按付款时间、已登记渠道顺序、订单/明细/件次排序一次确定。已准备身份不重建，未准备的订单件次保留正式编号位置；后续从对应任务建档，不能占用别件的编号。封版不会批量虚造137个已准备物品，销售结束/封版不等于全部交付。

### 4. 专业维护、售后和异常恢复

“物品与芯片”保留原查询、连续登记、绑定和配置演示；商品与发行保护、启停、图片/保存异常及未知结果先核对仍保留。首次交付可按阶段、异常/销售待核及关键词定位。刷新保留发售、页签和已保存件次；离开未保存编辑有提示。

“交付与售后→换新与转售”回查和继续原办理。样例第一件当年额度用完，第二件有一次。准备、发货和收到不提前接续；核验后后台明确确认，旧芯片退出，身份/正式编号保持，当前实体唯一，归属及历史对应。该回归使用已有持有人样例，不冒称新首单已完成首次认领后续接售后。

## 演示与正式构建边界

登录快捷进入、Webhook触发/重复/鉴权失败、密钥占位、双链接核验、业务时间推进、触碰事件及异常注入均带“〔演示〕”或“原型演示”标记。正常保存不代表真实接口成功。

本轮起点为[改动前分支版本](https://github.com/ilcece/bumbum/tree/71da87e8fd1db6dabab14d44625bd92bc94f4e82)，Git保留原型和文档基线。若回退，仅恢复本目录及相关文档；先保留当前样例会话，旧版在独立新标签页打开，避免把新限时数据误读为非限定。不自动清空会话，不涉及数据库或芯片恢复。

正式工程不引用本目录。整合时排除fixtures、sessionStorage、假登录/Webhook/密钥/核验和时间推进等演示代码，接入已批准真实能力；未引入新依赖或修改正式API、表结构、芯片安全方案和生产数据。

自然年一次、换新身份不增发、转售不重置额度等已确认规则继续按[D提案](../../docs/proposals/replacement-resale.md)演示。首次启用/归属凭据、资格证据、费用、冻结、跨年及扣减/占用、退款争议仍需定稿；换新完成标“待核对计次”，B清理/C纠错未批准动作不执行。
