# 管理后台高保真交互原型

按cece已批准的信息/功能架构及业务表字段调整，以其2026-11-04上传的原始Make为视觉基准，复用Ant Design 6。仅用于审核：正式frontend/admin、用户H5、接口和数据库未修改。

## 怎样预览

下载本目录[独立HTML](preview.html)，用桌面Chrome/Edge打开，点击“使用演示身份进入”。不需要真实管理员账号。源码包可在Node环境运行：版本见`.mise.toml`，先`npm ci`，再`npm run dev`，或`npm run build`生成dist。`.figma/make`保留导入脚本，但本轮没有重新上传Figma或执行公开发布。

已保存的合成样例及办理进度保留在当前浏览器会话，刷新后可继续。本轮兼容当前v5样例会话；更早版本仍隔离，不自动覆盖；右上角“原型演示→重置样例与办理记录”可显式重置。不要输入真实密码、验证码、密钥、收件地址或个人资料。图片仅在浏览器暂存/预览/保存关联，不上传服务器。

## 页面组织

5个一级入口：工作台、物品管理、芯片管理、操作日志、系统与环境。物品管理含“数字物品／款式资料／发行约定／办理记录”4个二级工作区。实体、持有人、权益和流转在物品详情关联查看，不另建一级菜单。详情抽屉800px；共用资料编辑和换新/转售为1120px居中弹窗，内部滚动、底部操作可达。

类别只在款式维护。登记物品先选择已确认发行约定，自动引用款式和类别；限定/非限定均须关联发行并记录本件序号。限定如#001/100，非限定如#001，不设发行总量上限；原型按每次发行内唯一校验，跨款式共用编号未定。发行草案可保存并单独确认，确认后承诺只读；不自动生成物品、启用、配卡或认领。缺失发行关联的非归档旧物品在核对原发行依据后可补同款发行身份，即使已绑定芯片或已有持有人也适用，已经登记的发行/序号不普通重分配。既有缺关联样例保留为旧数据，不按编号猜测或自动补承诺；正式数据迁移另审。

列表每页上限已改为10条（候选选择保留5条）。芯片按登记时间倒序、同一时间按内部编号倒序；手工/Webhook新增后回首页并保留筛选。若新增不符合筛选，从成功提示查看确切记录。重复回调不新增或改登记时间。

前轮已修正模拟芯片内部编号冲突并启用v5样例；本轮在该版本上兼容升级，不清空已保存记录。

## 建议核对的四组场景

1. **架构、共用资料与发行：** 新建发行草案（限定有总量，非限定无上限），保存后留在当前弹窗“确认发行约定”；在数字物品新建中选择该约定、填写系统编号和本件序号，核对自动引用和连续创建。 进入4个工作区，查询、重置、按类别/状态筛选；维护同款资料时查看受影响物品及已启用数量，核对未保存预览和保存生效提示。草案修改不追改已发行承诺；发行颜色与实体实际颜色分别取值。
2. **日常登记与Webhook配卡：** 芯片手工连续登记；点击“〔演示〕触发Webhook登记”，核对新记录，再试重复回调及鉴权失败。选择发行创建带款式引用的物品后，继续关联、演示密钥准备、受控查看占位、填写递增链接、勾选核对并提交核验样例。关联/核验不自动绑定所有人，不生成真实密钥或操作卡片。
3. **换新、转售与历史：** 物品列表前两件分别为当年额度已用完/仍有一次的限定T恤。可从权益分区发起办理；或从办理记录查看待准备、待发货、运输中、待核验、已完成、取消历史及异常只读样例。记录可跨物品查询、继续，关闭返回原列表并保留条件；准备/发货/收到不提前接续。换新目标尺码在申请选，转售交付尺码在实体准备记录。
4. **加载、空、失败及恢复：** 右上角“原型演示”可切换加载中、读取失败、保存失败/未知、图片失败；通过恢复或核对后明确重试。输入保留、不自动重发，不将失败当空表；用无匹配条件查看空结果。已取消及运输异常记录仅演示只读状态，不开放尚未获批的处置动作。

## 演示控件与正式构建边界

Webhook新回调/重复/鉴权失败、登录快捷进入、样例编号/核验引用填入、密钥占位/递增链接/核验样例、触碰事件添加、加载/失败注入和诊断按钮等，使用“〔演示〕”文字或紫色“原型演示／演示”标记。Webhook触发控件另有data-demo-only标记。正常业务保存/查询按钮沿用Ant Design主次样式，整个应用始终标明样例数据。

正式工程目前不引用本原型目录。后续整合只移植经确认的展示层与交互，演示入口、fixtures、sessionStorage样例、假登录、假Webhook、密钥占位和假核验/诊断均排除；真实Webhook、认证、上传、写卡和审计分别接既有/获批接口，不能把模拟成功移植为正式行为。源码里的演示辅助处理不是后端实现或真实验收证据。

## 已确认与待决边界

自然年一次、首次绑定所有人起具备资格、定期/挂失共享额度、转售不扣减或重置、尺码可调整/颜色受发行约定限制、旧实体不回收、核验交付后由后台明确接续，按[D提案](../../docs/proposals/replacement-resale.md)演示。当前同一数字物品只有一个正式当前实体/芯片和持有人，历史保留。

资格证据、费用、冻结范围/时点、跨年及扣减/占用节点、退款/取消/争议仍待定。换新完成后标“待核对计次”，不擅自选择政策；转售延续既有余额。取消/异常样例不是已批准的取消流程。B清理/C纠错继续显示条件和待审说明，不执行删除、改号、释放关联或复活旧卡；生产图片配套备份恢复门槛保留。

## 本轮规则整改

cece已确认上轮整改规则，现已更新：

- 旧物品缺发行关联时，从“补齐发行关联”核对原发行依据并确认补齐范围；已绑定或有持有人不再一概阻断，物品身份、实体、归属和年度事实保持。已有正确关联可查看，不能普通重分配；归档只读。
- 发行表单去掉手填版本与独立颜色项，颜色条款并入发行说明。保存后留在当前页可确认，自动记录确认标识/时间；列表显示草案/已确认及引用物品数。
- 从未被引用的草案或已确认约定可以确认删除并留审计；曾引用禁删。点击引用件数查看物品。删除未知结果先核对。
- 未配置芯片也显示关联摘要；服装/饰品统一启停，启用核对发行、名称、可用芯片及配置。启停/挂失异常保留状态和输入，核对后明确重试；配卡结果统一标明演示。
- 兼容当前v5样例会话，不清空旧记录；旧颜色文字并入原发行说明。已有历史确认标记保留，未记录确认时间不伪造。
