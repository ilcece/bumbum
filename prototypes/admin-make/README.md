# 管理后台高保真交互原型

仅用于cece审核展示和业务交互，位于独立原型目录，不是正式后台。以2026-11-04上传的《设计项目管理后台.zip》原始Make为基准，保留其应用壳、工作台、芯片/物品列表、查询和登记，按[分支方案](../../docs/proposals/admin-make-rebuild.md)更新详情/编辑、三层字段与实体术语，并增加挂失、换新和后台转售办理。

## 怎样预览

本目录[独立HTML交付件](preview.html)可下载后直接在桌面Chrome/Edge打开，点击“使用演示身份进入”。源码在本目录，Node版本见`.mise.toml`：运行`npm ci`后，用`npm run dev`启动，或`npm run build`生成`dist`静态预览。启动地址以终端输出为准，支持在Figma运行。`.figma/make`四个脚本仅供导入生命周期使用，本任务不执行公开发布脚本。

原型使用浏览器会话内的合成数据，已保存记录和办理进度可在同一标签页刷新后继续；不保存登录密码、验证码或未保存的普通编辑草稿。请勿输入真实凭据、收件地址或个人资料。关闭会话或点“原型演示→重置样例与办理记录”可重新开始。图片仅在浏览器中演示选择、预览、移除及保存关联，不上传服务器。

## 建议核对的四组场景

1. **登录和日常管理：** 空输入反馈、演示身份进入、查询/筛选/分页、关联往返、登记芯片与连续创建物品；项目、UID和编号边界延续既有规则。
2. **物品查看/编辑：** 从物品编号打开详情；编辑普通资料、图片预览/移除/选择，核对用户视角预览；保存、放弃和保留输入。共用款式/发行资料、数字身份、每次交付实体信息分开，当前单件资料不会自动同款共享。
3. **挂失与换新：** 第一件限定物品当年额度已用完，第二件有一次额度。选择第二件申请→候选芯片与样例核验引用→记录发货→记录收到→核验实际交付→明确确认接续。准备/运输/收到不提前激活，换新持有人不变；旧实体保留、旧芯片退出，历史可查。也可先挂失第二件，再进入挂失换新。
4. **后台转售及异常：** 第一件转售给持有人乙，接收人继承当年0次余额，身份/编号保留；旧实体无需回收，旧芯片退出。右上角“原型演示”可切换列表失败、保存失败/未知、图片失败，恢复后核对输入与记录。日志仅为原型操作记录。

## 已确认与待决边界

自然年一次、首次绑定所有人起具备资格、定期/挂失共用额度、转售不扣减或重置、尺码可调整/颜色按发行约定、旧实体不回收，均按[D提案](../../docs/proposals/replacement-resale.md)展示。交付后由后台核验并明确确认正式接续，不以物流签收替代。

费用、资格证明、冻结范围/时点、跨年办理、额度扣减/保留节点、退款/取消/争议仍待定。原型换新完成后标为“待核对计次”，保留原余额事实，不擅自落实某个扣减政策；转售继续继承原有余额。B清理/C纠错仅显示原稿入口与待审说明，不执行删除、改号或释放关联。饰品当前只开放款式编辑，其他已有资料只读；未配置的权益不得当现有能力。

所有认证、芯片准备/核验、物流、权益、审计及诊断都是合成演示，不调用真实业务API，不生成或显示真实密钥，不接支付、不操作实体卡。图中的成功仅说明原型样例变更，不是后端、实卡、生产或人工验收证据。

## 原型验证

`checks/browser_review.py`及`checks/browser_states.py`验证原型业务路径、表单异常与接续前后状态，不是React 19独立组件冒烟。先启动静态预览，再通过命令参数指定预览URL和输出目录；需要Python Playwright及浏览器。原型验证结果见[核心路径记录](checks/evidence/browser-review.json)、[表单与异常记录](checks/evidence/browser-states.json)、[导航/离线/矮窗口记录](checks/evidence/navigation-offline-review.json)。Figma导入及当前交付状态统一见[TODO](../../TODO.md)。正式代码构建等待cece确认原型后再推进。
