# 操作手册与技术参考

目的：cece 从这里找到当前要执行的步骤。每份手册只负责一个能独立完成的任务，按“目的、准备、操作、成功结果、失败排查”编写；同一条启动命令只在本地运行说明维护。

## 操作手册：按顺序使用

| 手册 | 什么时候用 | 当前范围 |
|---|---|---|
| [本地运行](LOCAL_DEVELOPMENT.md) | 首次准备、日常启动、停止、更新依赖和自动检查 | Windows重复启动及停止提示已修复，待复测；其他系统保留命令 |
| [管理员登录](ADMIN_LOGIN.md) | 创建账号、手机扫码、登录、重置或停用 | 已合入 main，cece 已通过本机扫码和登录验收 |
| [芯片登记验收](https://github.com/ilcece/bumbum/blob/feat/chip-registration/docs/CHIP_REGISTRATION.md) | 登录后手动登记、查重、筛选和分页 | 原版核心已验收，项目可空等调整待补测；此工具分支没有芯片页面 |

先在 GitHub Desktop 选对分支，再使用该分支里的手册。已有配置、账号和数据库继续保留；不要因为更新手册重新建环境。Windows三个双击入口在 feat/windows-local-tools，待实机验收；使用方法见本地运行手册，进度见 [待办清单](../TODO.md#windows-验收工具待windows验收)。此分支基于main，不含芯片登记代码；验收芯片请切回 feat/chip-registration。

## 怎样避免手册越积越乱

- 新功能先补已有手册；只有形成独立操作流程时才新增文件，并把入口加到本索引。
- 目前使用现有 docs 目录即可，不把三份手册并成一篇，也不增加目录层级。以后确需分类搬迁，先同步链接，并保留旧入口，避免旧聊天链接失效。
- 手册说明怎么操作，规则仍以 PRD、TECH_SPEC、API_CONTRACT 和 schema 为准，不复制另一套字段或安全规则。
- 每次提交都按 [协作规范](../AGENTS.md#6-验证与交付) 核对代码、文档、分支范围和验证结果；格式检查不能代替人工核对内容。
