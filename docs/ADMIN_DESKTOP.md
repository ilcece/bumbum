# 桌面管理端：Make页面整合验收

用途：把全部桌面管理页面连接到真实功能。只面向桌面浏览器，不适配手机；用户H5、短信认领和所有权功能不开放。当前任务与交付版本见[TODO](../TODO.md)，历史验收和回退基线见[CHANGELOG](../CHANGELOG.md)。仓库合并不代表服务器更新，香港升级另按云手册执行。

## 1. 准备

保留配置、账号和数据库，在GitHub Desktop获取远端、按交付说明选择main或待验收任务分支并拉取，核对交付版本；按[本地运行](LOCAL_DEVELOPMENT.md)停止旧服务后启动，依赖有变化时由已有启动工具安装。统计本身不新增改表，但依赖触碰日志003；先按[本地第11节](LOCAL_DEVELOPMENT.md#11-已有测试库升级触碰记录及后端验收)检查，已完成不重复，未完成先备份升级，不重建数据库。本机和香港数据相互独立，本次不要求更新香港服务器。

使用桌面浏览器，建议窗口宽度至少1024像素。body保留overflow:hidden，窗口高度较小时滚动页面内容区或弹窗内部，不要求滚动整个浏览器页面。登录前展开“检查运行环境”，登录后用顶栏“运行检查”或侧栏“系统状态”。

## 2. 五组验收

| 组 | 操作 | 通过条件 |
|---|---|---|
| 登录会话 | 使用原账号、密码、Authenticator验证码登录；刷新；退出 | 进入工作台，显示会话到期；刷新恢复会话；退出回登录页，管理数据隐藏。错误/锁定按原[登录手册](ADMIN_LOGIN.md)处理 |
| 全部页面与检查 | 依次进入工作台、芯片、物品、所有权、系统状态；点击顶栏运行检查 | 导航正常；工作台数量来自真实库存；触碰统计按第7节验收，所有权页仍未开放；运行检查真实显示通过/失败，可重试 |
| 芯片回归 | 打开登记弹窗，使用未用UID，可填批次；重复登记；筛选、翻页、刷新 | UID归一化、未分配项目、首次来源、批次和重复保护按[芯片手册](CHIP_REGISTRATION.md)；重复不覆盖，成功后可查原记录 |
| 物品与资料 | 创建服装及饰品草稿；打开服装资料弹窗，保存重读、启停、清空可选内容 | 按[物品手册](ITEM_DRAFTS.md)规则执行；数字ID用于请求，编号用于展示；资料不自动启用，启用不被显示为芯片已绑定；无尺码表 |
| 未实现及桌面滚动 | 点通知、设置、导出、更多、绑定所有权/查看流转；缩小桌面窗口高度，查看长表格/资料弹窗 | 未开放操作弹“当前版本暂未实现”，没有假成功或业务写入；页面/表格/弹窗各自可滚动，输入和操作均可到达。编辑后关闭提示放弃，取消继续编辑 |

测试编号已存在时换一个未用编号，不删除现有记录；人工示例数据保留。导出、所有权等功能仅占位，不能因按钮出现就当已实现。工作台统计失败显示读取失败，不显示0；所有权未查询时不伪装成空列表。

## 3. 失败反馈与技术验证

记录所在页面、物品编号或UID、操作、预期和实际提示即可；不发密码、验证码、Cookie、.env或完整日志。保存超时先重新读取核对，不自动重发；资料成功但列表失败分别提示，不能再次创建来补偿列表错误。弹窗处理中不关闭或切页，未保存修改离开先确认。

AI技术验证使用合成账号及专属临时MySQL，覆盖真实登录、芯片/物品接口、保存回滚和故障、桌面矮窗滚动以及未实现操作不发业务请求；没有使用现有业务库或香港服务器。视觉来源为cece上传bumbum.zip，保留管理框架、组件与桌面样式，不执行其.figma脚本，不导入其AI规则或演示业务。

回退界面可回到1d897ad，保留已保存的资料和状态，不通过数据库恢复进行代码回退；回退后依赖按当时锁文件安装。是否提交/推送、合并和部署按会话授权分别处理。

## 4. 诊断编号反馈

遇到程序或数据库失败，保留页面、操作、编号及错误编号即可；没有编号时照常反馈原提示，不自行制造故障。编号只用于排查，不是密码或登录凭证。AI在独立测试环境验证页面与日志编号一致、敏感内容不记录及日志写入失败不影响回滚；cece不需要停现有数据库或修改密码来验收。当前任务状态见TODO。


## 5. 首次绑定物品

芯片行可显示关联物品编号，待绑定且未关联的芯片可打开绑定弹窗。绑定、取消、重复与故障反馈按[芯片手册第4节](CHIP_REGISTRATION.md#4-首次绑定物品验收)独立验收，不把绑定当作写卡或所有权认领。当前任务分支和验收状态见TODO。

## 6. 密钥与配置

已绑定芯片显示“密钥与配置”入口，列表区分密钥已生成及配置已核验。首次本机配置见[本地运行第10节](LOCAL_DEVELOPMENT.md#10-首次准备本机密钥功能)；五组联合验收及真实改卡前提见[真实卡手册第4节](NFC_CARD_VERIFICATION.md#4-密钥与配置联合验收)。与绑定弹窗互斥；批量导出、完整管理页面仍待排期。


## 7. 工作台有效触碰统计

目的：按项目和时间了解已记录的有效触碰。入口为侧栏“工作台”，使用交付分支；与本页上方全局库存分区，库存不受触碰筛选影响。本步不新增迁移，前提见第1节。统计是只读查询，刷新不会新增触碰或消耗凭证；真实触碰产生记录后才会看到次数，不灌入演示数据。

| 验收组 | 操作 | 预期与失败反馈 |
|---|---|---|
| 1. 默认与真实次数 | 登录进入工作台；可按真实卡手册第5节用专用卡完成两次独立有效验证，再点刷新统计 | 默认全部/近7天；已记录的两次增加2次、被触碰物品增加1件（若原已有该物品则件数不再加）。配置核验、旧链接重发、资料GET不增加。零记录是正常空状态，不要求清库或造数据 |
| 2. 项目及日期 | 改选服装/饰品，暂不查询；随后点查询统计，再选近30天或累计并查询 | 修改未查询有提示，旧结果仍标原范围；查询后整组更新，明细回第一页。无数据项目显示0；首条有效记录不称售出或上线日期。全部合计以同一截点比较，真实连续触碰期间不要求先后查询数字固定不变 |
| 3. 明细与关键词 | 输入已有编号/名称点击查询物品或回车；再输入不存在文字，最后清空 | 关键词只影响明细，指标/趋势仍按项目时间；无匹配不把指标归零。默认次数/最近时间倒序，20件一页、边界禁用；样本不足20件不为手工分页灌库，分页由技术测试覆盖 |
| 4. 刷新与错误 | 修改项目/关键词但不查询，点刷新统计；遇到读取失败，核对旧结果标签后重试 | 刷新只用已生效条件，输入不会偷生效；失败不是0，保留旧结果时明确原条件/截至时间。重试使用失败请求，错误编号可用于反馈。数据库故障、超大数字、晚到响应及分页校正由技术注入验证，不要求cece破坏服务 |
| 5. 图表与桌面操作 | 悬浮日柱、Tab聚焦图表、左右键切日，缩小窗口高度后滚动到明细/分页，再退出 | 能读完整日期/次数/今日未结束；body不滚动、工作区可到所有操作；累计很长时横向查看全部日期。退出隐藏管理数据，重新登录按默认查询；芯片/物品/运行检查快捷入口仍可用 |

反馈只需页面、已生效条件、操作和错误编号，不发完整动态链接、凭证、密码或.env。原服装测试卡可以验证正常次数；饰品实际触碰与后台完整认领仍需各自证据，不能把合成测试当实卡通过。首次记录之前没有历史补造；累计不是总读卡计数，也不是独立用户或售后人数。
