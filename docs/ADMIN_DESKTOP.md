# 桌面管理端：实际流程验收

用途：把全部桌面管理页面连接到真实功能。只面向桌面浏览器，不适配手机；用户H5、短信认领和所有权功能不开放。当前任务与交付版本见[TODO](../TODO.md)，历史验收和回退基线见[CHANGELOG](../CHANGELOG.md)。仓库合并不代表服务器更新，当前部署只按杭州手册独立授权执行。

## 1. 准备

保留配置、账号和数据库，在GitHub Desktop获取远端、按交付说明选择main或待验收任务分支并拉取，核对交付版本；按[本地运行](LOCAL_DEVELOPMENT.md)停止旧服务后启动，依赖有变化时由已有启动工具安装。物品/图片后端先按[本地第14节](LOCAL_DEVELOPMENT.md#14-物品与私有图片后端升级)检查005；统计本身不新增改表，但依赖触碰日志003；先按[本地第11节](LOCAL_DEVELOPMENT.md#11-已有测试库升级触碰记录及后端验收)检查，已完成不重复，未完成先备份升级，不重建数据库。本机与杭州目标各自独立，本轮不部署服务器。

使用桌面浏览器，按1280×720或1440×900窗口验收。采用官方管理布局的页面滚动，窗口较矮时可滚动到全部内容，弹窗内部单独滚动。登录前展开“检查运行环境”，登录后从工作台快捷入口或侧栏“系统状态”进入。

## 3. 失败反馈与技术验证

记录所在页面、物品编号或UID、操作、预期和实际提示即可；不发密码、验证码、Cookie、.env或完整日志。保存超时先重新读取核对，不自动重发；资料成功但列表失败分别提示，不能再次创建来补偿列表错误。弹窗处理中不关闭或切页，未保存修改离开先确认。

AI技术验证使用合成账号及专属临时MySQL，覆盖真实登录、芯片/物品接口、保存回滚和故障、桌面矮窗滚动以及未实现操作不发业务请求；没有使用现有业务库或香港服务器。共享登录/导航/概况、芯片与物品完整流程均采用Ant Design官方组件；工作台统计保留原聚合与图表。物品细项见物品手册，人工结论见TODO。本次Make的布局、摘要表格和详情/编辑展示组合已复用；旧Figma交互原型仅供参考。核对详情抽屉与编辑弹窗的字段一致、只读项可读，以及长表单底部保存/取消可到达。

代码回退使用交付说明核对的上一步版本，并按其锁文件安装依赖；保留已保存的批次、资料、状态和关联，不通过整库恢复进行代码回退。是否提交/推送、合并和部署按会话授权分别处理。

## 4. 诊断编号反馈

遇到程序或数据库失败，保留页面、操作、编号及错误编号即可；没有编号时照常反馈原提示，不自行制造故障。编号只用于排查，不是密码或登录凭证。AI在独立测试环境验证页面与日志编号一致、敏感内容不记录及日志写入失败不影响回滚；cece不需要停现有数据库或修改密码来验收。当前任务状态见TODO。

## 7. 工作台有效触碰统计

目的：按项目和时间了解已记录的有效触碰。入口为侧栏“工作台”，使用交付分支；与本页上方全局库存分区，库存不受触碰筛选影响。本步不新增迁移，前提见第1节。统计是只读查询，刷新不会新增触碰或消耗凭证；真实触碰产生记录后才会看到次数，不灌入演示数据。

| 验收组 | 操作 | 预期与失败反馈 |
|---|---|---|
| 1. 默认与真实次数 | 登录进入工作台；可按真实卡手册第5节用专用卡完成两次独立有效验证，再点刷新统计 | 默认全部/近7天；已记录的两次增加2次、被触碰物品增加1件（若原已有该物品则件数不再加）。配置核验、旧链接重发、资料GET不增加。零记录是正常空状态，不要求清库或造数据 |

| 4. 刷新与错误 | 修改项目/关键词但不查询，点刷新统计；遇到读取失败，核对旧结果标签后重试 | 刷新只用已生效条件，输入不会偷生效；失败不是0，保留旧结果时明确原条件/截至时间。重试使用失败请求，错误编号可用于反馈。数据库故障、超大数字、晚到响应及分页校正由技术注入验证，不要求cece破坏服务 |

反馈只需页面、已生效条件、操作和错误编号，不发完整动态链接、凭证、密码或.env。原服装测试卡可以验证正常次数；饰品实际触碰与后台完整认领仍需各自证据，不能把合成测试当实卡通过。首次记录之前没有历史补造；累计不是总读卡计数，也不是独立用户或售后人数。

### 8.1 首次认领未开放时怎样准备售后验收

若测试库没有已有持有人，先按第2组创建一件验证物品、准备并配置首套，打开物品完整详情，从URL取得内部ID。保持生产验证标记开启。在加载**测试应用运行配置**的受控终端或测试容器内，使用自己的现有管理员名执行；只准备合成关系，不调用短信、不证明真实认领、不自动售出：

```bash
python -m core.catalog_testdata --item-id 123 --admin-username 你的测试管理员 --apply
```

123换成该验证物品的实际ID。默认不带apply只检查。命令只接受固定杭州test槽的应用身份，或原本机开发测试库；生产、未知库、未标记物品和已有持有人全部拒绝，不覆盖原关系。输出测试持有人A与接收账户B的ID/名称，刷新详情后即可按第3组换新、转售；转售选择输出的B。账户使用明显测试名称和非真实手机号标记，不联系真实客户；命令不会写生产库。

这些合成账户/关系会计入测试库统计，不当作真实客户或首次认领已交付。删除验证物品按原规则保留另一侧及账户；测试完成后的数据处理另按明确对象执行，不清空整个库。该单件辅助命令保留作明确需要时使用；当前旧验收包已按cece新指令清空，不存在预置持有人，不自动执行本命令。

原单条生产验证删除规则不变：只删当前对象、另一侧保留。整批清理是对明确批次拥有对象的独立操作，不清空数据库。合成历史/配置只用于后台展示与事务验收，不能验证真实短信、实卡与客户交付。
