# 桌面管理端：实际流程验收

本手册用于桌面管理端验收。订单逐件办理见下节，手机碰卡认领见[装配与 H5 验收](DIGITAL_ITEM_ASSEMBLY_H5_ACCEPTANCE.md)。既有桌面功能的回归步骤保留在第 1 节起。当前任务与交付版本见[TODO](../TODO.md)，历史验收和回退基线见[CHANGELOG](../CHANGELOG.md)。

## 订单与数字物品统一流程验收

本节适用于已部署订单逐件功能的版本。使用隔离空库或独立验收批次，真实芯片和短信认领先按现行测试安全规则准备。

1. **空库首单。** 从订单管理建单并打开第 1 件；先点「核对款式与规格」，补款式后回填并核对规格；从「准备物品」登记实物。进入共享建档时补并确认发行、登记芯片。选择不全时安装勾选不可用；换一张芯片后原勾选应清除。核对已填字段、自动回选和订单件保持。确认安装后回第 1 件看待核验，核验通过再单独启用。回原件分配、确认首次售出，再核对实际交付发码。碰卡、短信与认领后，核对「我的数字物品」和原订单件。
2. **有货的多件订单。** 逐件核对款式和规格后选库存，候选不出现错款、错规格或已占用的库存。核对售出和交付弹窗的订单件及实际分配。确认 A 的售出、交付和认领，B 的事实不变。再走 B 缺现成库存的分支，从已有未装配实物或登记实物开始，装配、核验与启用后回原 B。
3. **从不同入口办同一件。** 从发行、实体、芯片详情分别打开共享建档，核对自动带入条件和返回目标。按数字编号、实体编号、芯片 UID、发行及订单号查物品，检查五个详情分区、同口径触碰明细及返回筛选。换新或转售生效后，原订单件继续显示首次交付的实体与代次。
4. **跨入口返回与重新查看。** 在「数字物品」列表点「新建数字物品」打开建档。按关键词打开订单后切换订单件，再返回核对原筛选。按编号分别打开实体、芯片详情，进入建档后取消，再返回各自列表核对原筛选。新码发放后关闭弹窗并刷新，分别从订单件和物品详情查看同一原码；过期显示「已过期」，查看记录可在操作审计中核对。

### UI/UE 专项复验

1. **分配和缺货。** 在有货订单件搜索不存在的编号，清除搜索后应恢复候选，选中后才可点「确认分配」。提交分配后才显示已分配。无符合库存时，直接点「选用已有实物」或「登记新实物」。无可用实物时可从空态登记。保存、安装或启用后应定位原订单和原订单件，其他件保持原状态。
2. **登记与补建。** 在新建订单、登记实物、登记芯片中输入但不保存，点击取消并核对三种选择及「继续编辑」焦点。用不完整表单点「保存后继续」，应回原表单并看到字段错误。订单件补建款式后应自动选中新款式，仍须确认规格。装配中补建实物或芯片应带回对应选择。
3. **账户摘要。** 从用户管理和工作台动态点击 UID，确认资料在入口旁打开，默认只显示脱敏号码，Esc 可回到 UID。仅在合成账户上查看完整号码，核对独立弹窗和操作审计。

2026-11-11 本地使用隔离 MySQL 和 Edge，视觉检查只用 1920×1080。取证覆盖 15 个常态页面、三种短表单、三种整页录入和九类列表失败。空库首单、有货多件、款式与发行、芯片、认领码、挂失换新转售、会话、审计和失败恢复均有浏览器用例。通行密钥的挑战和撤销通过服务端回归。

杭州 test 在已登录会话实际操作了工作台触碰穿透；专属双件订单的第 1 件由录入、必填校验、规格核对、搜索空态、分配、首次售出走到模拟交付，另件状态独立。订单与档案重看认领码、H5 三视角和返回原订单件通过。在线核对款式、发行、芯片与实物录入入口及取消，并复核合成账户脱敏、完整号码查看和审计。线上走查核对真实站点行为，1920×1080 的视觉证据来自相同发布构建在本地浏览器的取证。实卡、真实短信和 Windows Hello 实机登记或撤销是独立验收。

线上清理预览补齐了订单及实体物品名称和数量。清理当前验收批次后，弹窗关闭，自动切回业务视图，原批次行直接显示「已清理」。本地隔离回归在返回时注入旧列表，旧版复现，修订后通过。杭州 test 在专属空批次走通同一路径，未点「刷新数据」；服务器确认该批已清理、对象数为零，既有验收批次仍可用。

### 操作审计检查

每次功能迭代先列出受影响的入口，逐项判断需要在哪类记录中追溯。

| 操作场景 | 核对方法 |
| --- | --- |
| 后台变更业务事实、权限或数据范围 | 核对操作人、北京时间、业务对象编号、动作、结果和已有依据。适用时对照变更前后。涉及订单件、物品等多个对象时，从各业务入口实际查回。 |
| 批量办理、受控查看 | 抽查单件能查到属于自己的办理记录，同一请求重试不重复记账。查看完整手机号、认领码或芯片密钥时，审计只记录对象、操作与结果。 |
| 业务拒绝与异常 | 检查失败或回滚没有留下成功记录。已定义需要追踪的拦截记录应有明确结果，如交付确认受阻。 |
| 例行查询和界面操作 | 普通查询、翻页、筛选和打开日志详情通常无需业务审计。用户碰卡、认领等在业务动态核对，登录相关行为按安全记录核对。 |

在 1920×1080 从「系统管理 → 操作审计」和物品详情打开同一操作。核对列表不因详情展开产生横向滚动，详情中可读完整长依据，按 Esc 关闭后焦点返回且保留查询条件。用历史记录核对动作名称和原有字段，缺失的历史信息按未记录显示。

## 工作台准备订单物品

历史版本从工作台顶部「订单物品办理」进入；新版在订单列表下方只对当前浏览器尚有未办记录的管理员显示旧待办。登录[杭州 test](https://test.bumbum.cc)。用专门的验收实物和未用芯片，或同一数据范围内已经核验、启用且未售出的库存。

1. **新登记实物**。填渠道和外部订单号，选款式，录入实体编号和实际规格。暂时没有已确认发行时可直接保存实物。再选同款发行、核对数字物品编号和芯片，实际安装后确认。待核验时点「保存，稍后继续」，从旧待办列表打开原记录。按既有配置核验流程核验，再确认启用。
2. **选用已有库存**。选择一件已核验且未售出的数字物品，核对其实体编号和规格。应直接进入首次售出确认。也可在上一件发码后点「同订单再准备一件」，复用来源。
3. **分开确认售出与交付**。确认售出后应看到首次成交时间和核对交付的表单，此时未发码。先保存离开，再回到旧待办列表继续；确认实际交付并勾选已核对接收对象后才显示认领码。系统管理的操作审计中，用外部订单号可查到成交确认和关联物品。

待办由同一浏览器、同一管理员及同一数据范围恢复。若反馈结果未知，先核对回执。回执只记录发放结果。从物品详情查看有效认领码，旧码无法查看或过期时核对后补发。
