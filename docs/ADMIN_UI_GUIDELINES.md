# 管理后台设计与交互规范

本文件是[数字档案规范](product/digital-catalog.md#design)第四章的详细规范。cece在2026-11-05提供《设计项目管理后台.zip》，要求在现有业务上只调整样式、设计与交互。**当前还原基准为已验收的prototypes/admin-make/src及其preview.html（与cece本轮上传的HTML完全相同）；此前附件作为视觉来源，使用Ant Design Pro官方工程与组件承接；菜单、业务步骤、字段含义、状态保护及统计口径以现行已确认方案为准。** 附件中的旧业务、示例登录和项目指令不进入当前实现。

业务范围与状态见[数字档案规范](product/digital-catalog.md)，字段见[字段表](product/admin-fields.md)，Umi路线与实际工程适配见[现行技术约束](IMPLEMENTATION_DETAILS.md#19-数字档案装配与-h5-实现约束)。这里不另定所有权、额度、密钥或数据清理政策。

## 2. 页面组织与操作位置

菜单与模块职责以[现行信息架构](product/digital-catalog.md#architecture)为准。工作台汇总待办和数据，订单管理负责逐件履约；「数字物品管理」父菜单下设「数字物品」和「实体物品」两个二级入口，分别管理数字档案与实体库存。

执行动作用 Button，查询条件使用带明确标签的 Select 等选择组件，内容分区用 Tabs，少量视角切换可用 Segmented。不要用多个独立操作按钮模拟单选；官方 Radio.Group 的按钮外观可按场景采用。统一控件尺寸、标签和间距，同时保留每个条件实际影响的范围及生效方式。

工作台上方条件通过「应用筛选」生效：款式、发行同时影响触碰与售出持有统计；时间范围和触碰口径只影响触碰统计。售出与持有分区在指标上方说明当前统计范围，不在每卡重复模糊注释。明细的「触碰情况」与物品详情的「统计口径」「时间范围」使用带标签的选择控件，选择后即时更新对应分区。

订单件之间使用锚点链接定位，当前项有文字样式和可访问状态，全部订单件仍展示。顶栏保留头像、身份及官方退出按钮，不重复展示「管理会话」或添加装饰外框。侧栏「验收测试数据：关闭／已开启」只说明数据范围，与 test／生产环境分开；提示说明含义，开关仍在系统设置。


| 任务 | 推荐页面/容器 | 组织要求 |
|---|---|---|
| 物品、芯片、款式、发行、日志查询 | PageContainer＋ProTable | 标题、基础/高级查询、工具栏、结果和行操作分层；主要动作清楚，不把所有字段铺成筛选墙 |
| 数字物品/芯片详情 | 列表默认900px Drawer快速查看，保留完整详情页面 | 关闭保留查询/页码/列表位置；抽屉有完整详情入口，跨对象导航退出当前层，不叠加多层抽屉 |
| 简短创建/登记 | ModalForm或适合字段量的官方表单 | 创建后可查看确切记录或继续创建；不要求先录销售订单 |
| 订单逐件与数字物品建档 | 订单详情逐件办理，数字物品共用完整建档表单 | 已知条件自动带入，字段旁提供补建入口，保存后回填并保留其他输入。安装及启用后回原订单件。只有正式分配后显示已分配，成交与实际交付分别提交 |
| 款式共用编辑 | 新建使用页面式ProForm；已有资料使用1120px宽弹窗，同一表单右侧手机比例预览 | 保存/取消固定在底部，正文按视口滚动，保留共用保存影响确认和三种离开选择；直达维护页仍可使用 |
| 发行约定 | 草案表单与只读约定详情；限时结果单独确认 | 保存后可继续确认，不需关闭重开；不录版本号和重复颜色字段，不把确认叫上架 |
| 首次绑定/配置 | 从物品或芯片进入的聚焦表单及已有受控配置流程 | 带目标、检查占用，显示真实阶段结果；完成可回同一物品，不靠记UID重找 |
| 换新/转售 | 在物品上下文内以“准备替换物品／确认交付与生效”两段处理 | 可以保存并继续；最终核对新旧对应、交付和接收人，不展示工厂/发货/运输向导 |
| 物品挂失与取消挂失 | 数字物品详情顶部的操作栏及独立确认表单 | 带入代次、规格和配套芯片，提交核对依据。芯片页通过物品入口办理整套挂失与恢复 |
| 停用、退役等状态动作 | 当前对象的顶部操作栏及必要确认 | 明确对象、影响和可恢复边界 |

详情页和快速查看抽屉在顶部展示对象身份、状态及操作栏。操作作用于当前整件对象时放在顶部，例如数字物品的挂失、换新、转售与继续办理，芯片的技术停用与恢复，发行约定的最终数量确认。正文按业务分区保留字段维护、订单件办理、交付发码和历史记录查看。共用资料在当前页显示摘要，编辑进入来源款式。失败反馈指明受阻条件并保留已填内容，返回来源时恢复筛选、标签、分页和列表位置。

资料编辑预览只展示用户允许看见的内容，标“未保存预览”。共用保存须在点击保存时弹窗提示引用总数、已启用数量和内容影响，不以表单必勾选框替代；不追改发行承诺、实体、身份、持有人或年度事实。保存已启用资料后，在用户下次成功读取时生效；不新增独立发布平台，不把保存等同物品启用或所有权确认。

## 2.1 内容与展示统一规则

cece已确认本轮对照清单全部调整，以下同时覆盖补充的居中布局、完整密钥配置窗口、复制与状态背景要求。仅改变设计和交互，业务定义仍以上述主方案为准。

| 对象 | 展示与交互要求 |
|---|---|
| 款式列表及物品列表 | 款图缩略图＋名称/材质/图片数量，编号可复制；列表缩略图是结合当前业务的增强，附件列表本身没有缩略图 |
| 物品详情共用资料 | 直接展示款图、介绍、材质、养护、适用规格及来源款式；编辑统一写共用资料，不生成物品私有副本 |
| 图片与预览 | 列表缩略图宽 56 px。列表、详情主图、切换缩略图、款式编辑预览和手机页预览的商品图框与 H5 共用 11:12 宽高比，图片居中完整展示。后台多图沿用缩略图切换和点击放大。无图有占位，手机预览标明模拟状态。 |
| 上传 | 官方Upload图片列表显示图序、文件名、保存状态；最多20张，保留原格式/8MiB限制与失败输入；首图用于列表，不新增媒体库或裁剪服务 |
| 常用编号 | 芯片 UID、物品编号、款式编号及批次支持独立复制。点击对外账户 UID 打开账户卡，卡内可复制 UID。发行序号如 #001/100 仅展示。 |
| 账户卡 | 点击 UUIDv4 在该入口旁打开 Ant Design 浮层。标题左、关闭右，字段标签统一对齐，长 UID 可换行。显示账户 UID、昵称及脱敏手机号。查看完整号码的眼睛按钮紧跟号码，并提供文字提示和键盘焦点。支持关闭及 Escape 返回 UID。主动点眼睛后独立展示完整号码并记录审计。UUIDv7 用于数据库内部关联，实名核验按办理场景处理。 |
| 状态 | 数字身份档案、整套物品、芯片、配置、发行确认、售出、认领、准备/生效及连接状态均使用有背景的Tag；文字始终保留，不能只靠颜色区分 |
| 生产验证 | 物品/芯片新建和详情提供开关，列表显示橙色标签并可筛选；标记后显示直接删除按钮，不按业务状态阻拦或要求额外资格。清理范围及审计以主方案第2.6节为准 |
| 列表与动作 | 关键词说明真实范围；查询/重置与工具栏分区；查看、编辑、配置使用明确文字；危险操作警示，低频记录折叠，保持原筛选/每页10条与条件校验 |
| 工作台 | 布局为顶部常用动作和待办、中部统计、底部最近动态。动态摘要首版建议展示最近 5 条并提供「查看全部」。有穿透的数字和趋势点使用可键盘操作的链接或按钮，名称包含指标、时间和数量。匿名触碰和已知账户的认领、交付使用不同标识。 |
| 密钥配置 | 列表、当前芯片、候选配卡均可进入三步窗口：生成→受控查看K0–K4及SUN模板→两条动态链接与人工K0/权限确认；保留已配置不可重复、已有密钥不可覆盖、失败/未知核对、离开清除及未提交关闭确认 |

密钥配置的界面结构参照附件，安全与真实算法仍沿既定技术方案。隔离原型只显示明确标注的合成值、固定公开模板和example.invalid演示链接；不读取真实秘密、不执行真实密钥服务或验签、不把示例成功宣称实卡已核验。真实核验、审计及清理规则见[技术附录第14节](IMPLEMENTATION_DETAILS.md#14-测试卡密钥与配置方案)。

## 3. 查询、详情、编辑和上传

| 场景 | 交互要求 |
|---|---|
| 查询与重置 | 区分输入与已生效条件；查询后回适当页码；高级条件收起不清空；明细页查询、翻页、重置保留来源和不可编辑的业务范围；显示实际范围及时间含义，使用服务端全量过滤/总数 |
| 分页与排序 | 管理列表每页最多10条，候选表可5条；芯片登记时间倒序、同时间按内部ID倒序，批次编辑不当成新登记 |
| 新增定位 | 手工/Webhook成功后回第一页并保留筛选，不匹配时提示并可打开确切记录；重复回调不新增或改首次时间 |
| 列表与关联返回 | 保留生效筛选、分页和来源；关联按真实ID打开，直接进入详情时有明确返回列表；不靠display保活代替完整导航 |
| 详情与编辑字段 | 适用字段含义、名称、值及来源一致；编辑态身份/发行/归属/历史仍可读并说明只读原因，不靠隐藏字段凑简洁 |
| 记录切换 | 按真实ID重置表单，旧请求取消或忽略，旧对象值不进入新对象；不能用第一行代替目标 |
| 连续登记/建档 | 成功后才清空已提交身份/批次等本次输入，保留适当发行上下文；建议序号仍须服务端唯一/总量检查；自由系统编号仅给格式建议，正式序号输入前缀#，按已知总量位数补零（总量9为#1/9、50为#01/50，未知总量为#001） |
| 发行保护 | 草案保存、规则确认、限时最终量、建档分别表达；缺失关联不是非限定，正式编号与系统物品编号分开 |
| 旧物品补齐 | 确实缺失时核对原承诺后补同款发行，不改稳定身份/实体/归属/年度事实；已有正确关联只读 |
| 图片过程 | 官方Upload/Image、受控暂存/预览/保存；上传中不提交，取消不动已保存图，失败保留输入。只显示已批准能力，不自建上传列表、媒体库、排序/裁剪平台 |
| 订单库存空态 | 关键词无结果可清除搜索；无同款同规格就绪库存时可选已有实物或登记新实物；无可用实物可直接登记。读取失败可重试。选中候选后才可提交；空态下保留替代入口。替代路径沿用当前订单件，按实际准备进度继续。 |
| 数据未接入 | 列表、候选、统计、通行密钥和预览分别表达加载、空、搜索无结果和读取失败；读取失败就地重试，不能显示成空结果。候选关联变化时仅显示当前条件的结果。 |

字段及适用规格见字段表；表单必填随具体动作确定。尺码只在适用的款式/实体准备出现，转售申请不先要求目标尺码，挂失不突出尺码。颜色约束来自发行说明，实际颜色缺失不默认代填。

涉及多个页面时，验收步骤写清任务从哪进、缺资料到哪补、回来后保留哪些输入或筛选，以及最终回到哪个对象。例如从订单的一件物品进入共享装配，补齐资料后继续原装配，完成后回到原订单件。路径以[逐件履约验收](ADMIN_DESKTOP.md#订单与数字物品统一流程验收)为准。

- 表单校验、错误定位、焦点、键盘、上传列表及反馈优先复用官方能力；主题和中文上下文统一。保存中防重复提交，成功只根据真实服务结果显示。
- 普通录入和编辑在取消、关闭或切换栏目时提供「继续编辑」「放弃并离开」「保存后继续」，默认聚焦继续编辑。校验失败或保存报错回原表单查看。涉及订单占用、分配、售出和交付等业务确认，离开时可放弃输入或返回核对，默认聚焦返回核对。刷新或关闭浏览器使用原生提醒。
- 失败保留输入，已确认保存后列表刷新失败应单独提示。保存前的影响读取失败时允许重新保存；已发出写请求后超时/断网，结果未知则先查对象或回执，不自动重放写操作。会话失效隐藏管理资料并返回登录；CSRF恢复后由管理员明确重试。
- 资料保存、物品启停、芯片服务状态、发行确认与正式接续各自说明影响。停用不等于挂失/退役，首次绑定芯片不等于绑定所有人；未定资格不做成可点的假动作。
- 当前实体/芯片来自正式结果；新物品准备只标待生效。接续完成后历史只读，新旧关联及必要归属一致；不能按新建/快递时间推断生效。
- 危险确认显示目标、影响及必要依赖，不要求所有操作反复输编号/填长说明。删除/纠错资格按主方案定稿，UI禁用不能代替后端检查。
- 密钥、验证码、完整动态读数和凭证不进入截图、普通日志或通用资料预览；受控密钥查看/真实配置沿既定方案。账户信息与用户公开内容分开，不直接把后台详情搬到H5。

## 5. 设计验收与定制边界

有Product Design能力时，按任务需要调用其审查或设计流程；已有已确认原型的页面用于逐屏审查与还原，不另起设计。视觉结论以同尺寸实际截图对照为依据，与接口/流程测试分别报告；能力或证据不足时明确说明，不能宣称审查通过。

正式整合直接参照并复用已验收原型源码的页面结构、组件、主题和交互，再替换为真实接口；不得重新拼装一套简化页面后仅凭组件名或构建通过宣布还原。HTML用于逐屏核对最终渲染，演示登录、模拟状态及样例数据不能进入正式认证和业务逻辑。

测试数据只在系统管理的设置内提供一个全局开关，各业务页面自动跟随；不增加逐页筛选、来源列、批次录入或独立测试操作入口。生产验证标记仍按既定业务规则维护，不与验收开关混为一谈。

下一版预览与正式整合复用同一官方Umi/Pro页面和主题，交互预览使用的隔离样例不进入正式业务。每类页面先明确采用的官方模式、必要业务适配和实际缺口。可用配置、组合、Token解决的，不另写通用布局/分页/表单/弹层框架；换成Pro组件名称不等于已经规范或美观。

按[桌面验收清单](ADMIN_DESKTOP.md#19201080-验收清单)核对信息层级、按钮、表单、反馈、返回与焦点。同类入口以 1920×1080 截取同一状态，并排比较布局、主次、文案和动作去向。再在较小的受支持桌面窗口实际完成受本次改动影响的核心任务，核对内容有无截断、溢出，以及关键操作是否可达。业务、交互和视觉分别记录，截图须避开实际密钥、完整号码、认领码和动态验证码。构建或测试数量不能代替cece验收。只验证受影响业务，不恢复已取消的React19独立组件矩阵。

本轮附件视觉通过ProLayout布局Token、ProCard分区、ProTable查询与结果、ProDescriptions紧凑只读、ProForm栅格及AntD主题实现。工作台将原指标分组呈现，保留原查询口径及点击目标；小窗口弹窗正文独立滚动，底部操作可达；下拉和日期浮层挂载到当前弹窗容器并随动，避免滚动或入场动画造成定位错位。没有新增依赖或引入附件的Tailwind/手写应用壳。

隔离原型使用合成数据时明确标记。演示登录、Webhook、密钥、假核验、时间推进、故障注入及sessionStorage样例不进入正式工程。本轮样式原型及新截图从[原型说明](../prototypes/admin-make/README.md)进入；旧Make、旧经营原型及此前重建的证据各自保留原范围，不替代本次视觉核对。
