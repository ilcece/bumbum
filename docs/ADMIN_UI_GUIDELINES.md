# 管理后台设计与交互规范

本文件是[管理后台重构方案](proposals/admin-make-rebuild.md#design)第四章的详细规范，专门维护页面和交互规则。**目标以Ant Design Pro官方工程、页面组织及组件规范为准；原Make不再是必须复刻的像素基准。** 保留已确认的业务保护、品牌识别与官方组件优先原则；整体方向现已通过审核，按本轮授权重建隔离原型。

业务范围与状态见[主方案](proposals/admin-make-rebuild.md)，字段见[字段表](proposals/admin-rebuild-fields.md)，Umi路线与实际工程适配见[工程说明](proposals/admin-rebuild-implementation.md)。这里不另定所有权、额度、密钥或数据清理政策。

## 1. 视觉与官方工程基线

| 方面 | 新版建议 | 验收应看到什么 |
|---|---|---|
| 应用框架 | 完整Umi Max/Ant Design Pro的布局和路由组织，使用ProLayout、PageContainer及官方管理员菜单 | 统一标题、面包屑、侧栏、顶栏身份与退出；没有平行手写应用壳 |
| 组件体系 | ProComponents承载后台模式，AntD承载基础控件 | 查询、表格、详情、表单和反馈统一，不混用另一套控件或大范围覆盖内部CSS |
| 主题 | 以官方浅色主题为基础，品牌主色#1677ff、字体/圆角/间距由主题Token集中配置 | 正文、数字、状态、链接、弹窗及通知一致；不为每页配一套颜色/字号 |
| 内容布局 | 遵循官方页面容器和Grid，标题/查询/结果层级明确 | 合理留白和密度，短字段不过度拉宽、长说明不压成窄列，状态不堆满卡片 |
| 信息主次 | 主体先显示物品身份、状态和关键关联，业务详情按分区展开 | 稳定编号和当前事实易找；低频维护不占顶部主要区域 |
| 尺寸与响应 | 根据字段量与任务选官方容器，支持1280×720及1440×900桌面 | 主内容与弹层有合理滚动、按钮可达，表格必要时内部横向滚动，避免整页左右漂移 |
| 旧Make尺寸 | 原248px侧栏、800px详情、1120px大弹窗等仅作历史参考 | 不为复制原稿尺寸牺牲官方布局，也不把它们说成Pro强制标准 |
| 品牌与素材 | 保留BUMBUM标识和必要商品图片，移除模板演示装饰、外部背景图与无关入口 | 管理任务清楚，无AI/地图/多语言/营销等未批准功能 |

官方参考：[Ant Design设计原则](https://ant.design/docs/spec/introduce-cn)、[组件](https://ant.design/components/overview/)、[主题](https://ant.design/docs/react/customize-theme/)、[Ant Design Pro](https://github.com/ant-design/ant-design-pro)、[ProComponents](https://procomponents.ant.design/components/)。具体API按实施时锁定版本使用，文档示例不代表已安装或通过验证。

## 2. 页面组织与操作位置

目标菜单按主方案“工作台／款式与发行／数字物品／芯片管理／系统管理”。不再以新建发售、销售订单或交付阶段组织后台。用户与历史实体从物品和必要统计明细关联查看，不扩展CRM或单独实体录入模块。

| 任务 | 推荐页面/容器 | 组织要求 |
|---|---|---|
| 物品、芯片、款式、发行、日志查询 | PageContainer＋ProTable | 标题、基础/高级查询、工具栏、结果和行操作分层；主要动作清楚，不把所有字段铺成筛选墙 |
| 数字物品/芯片详情 | 主详情采用页面＋ProDescriptions/分组Card；跨对象快速核对可用Drawer | 当前对象可直达/刷新；只读信息和动作分开，来源可返回；同类任务不每页自创一种容器 |
| 简短创建/登记 | ModalForm或适合字段量的官方表单 | 创建后可查看确切记录或继续创建；不要求先录销售订单 |
| 款式共用编辑 | 页面式ProForm，分组展示；需要时右侧商品资料预览 | 说明影响引用物品；规格按适用显示，图片使用Upload/Image；字段多时不塞进矮小弹层 |
| 发行约定 | 草案表单与只读约定详情；限时结果单独确认 | 保存后可继续确认，不需关闭重开；不录版本号和重复颜色字段，不把确认叫上架 |
| 首次绑定/配置 | 从物品或芯片进入的聚焦表单及已有受控配置流程 | 带目标、检查占用，显示真实阶段结果；完成可回同一物品，不靠记UID重找 |
| 换新/转售 | 在物品上下文内以“准备新绑定／确认接续”两段处理 | 可以保存并继续；最终核对新旧对应、交付和接收人，不展示工厂/发货/运输向导 |
| 停用、挂失、退役等状态动作 | 相关分区的独立动作与必要确认 | 明确对象、影响和可恢复边界，不在普通编辑下拉框随意改状态 |

物品详情按“身份与发行→共用商品资料→当前实体/芯片→持有人与权益→必要历史”阅读；相关动作靠近所属信息。普通维护不改归属/历史；页面不在顶部堆挂失、换新、转售等全部生命周期按钮。

资料编辑预览只展示用户允许看见的内容，标“未保存预览”。共用保存提示引用总数、已启用数量和内容影响；不追改发行承诺、实体、身份、持有人或年度事实。保存已启用资料后，在用户下次成功读取时生效；不新增独立发布平台，不把保存等同物品启用或所有权确认。

## 3. 查询、详情、编辑和上传

| 场景 | 交互要求 |
|---|---|
| 查询与重置 | 区分输入与已生效条件；查询后回适当页码；高级条件收起不清空；显示实际范围及时间含义，使用服务端全量过滤/总数 |
| 分页与排序 | 管理列表每页最多10条，候选表可5条；芯片登记时间倒序、同时间按内部ID倒序，批次编辑不当成新登记 |
| 新增定位 | 手工/Webhook成功后回第一页并保留筛选，不匹配时提示并可打开确切记录；重复回调不新增或改首次时间 |
| 列表与关联返回 | 保留生效筛选、分页和来源；关联按真实ID打开，直接进入详情时有明确返回列表；不靠display保活代替完整导航 |
| 详情与编辑字段 | 适用字段含义、名称、值及来源一致；编辑态身份/发行/归属/历史仍可读并说明只读原因，不靠隐藏字段凑简洁 |
| 记录切换 | 按真实ID重置表单，旧请求取消或忽略，旧对象值不进入新对象；不能用第一行代替目标 |
| 连续登记/建档 | 成功后才清空已提交身份/批次等本次输入，保留适当发行上下文；建议序号仍须服务端唯一/总量检查 |
| 发行保护 | 草案保存、规则确认、限时最终量、建档分别表达；缺失关联不是非限定，正式编号与系统物品编号分开 |
| 旧物品补齐 | 确实缺失时核对原承诺后补同款发行，不改稳定身份/实体/归属/年度事实；已有正确关联只读 |
| 图片过程 | 官方Upload/Image、受控暂存/预览/保存；上传中不提交，取消不动已保存图，失败保留输入。只显示已批准能力，不自建上传列表、媒体库、排序/裁剪平台 |
| 数据未接入 | 用户/归属指标未接入显示未接入，加载、空、无结果、读取失败分别表达；不拿模拟0或成功动画填空 |

字段及适用规格见字段表；表单必填随具体动作确定。尺码只在适用的款式/实体准备出现，转售申请不先要求目标尺码，挂失不突出尺码。颜色约束来自发行说明，实际颜色缺失不默认代填。

## 4. 保存、返回、状态与安全反馈

- 表单校验、错误定位、焦点、键盘、上传列表及反馈优先复用官方能力；主题和中文上下文统一。保存中防重复提交，成功只根据真实服务结果显示。
- 未保存离开普通表单提供保存后继续、放弃后继续、取消离开；刷新/关闭使用浏览器原生提醒。危险操作不自动执行“保存后继续”，须返回原确认步骤重新核对。
- 失败保留输入，已确认保存后列表刷新失败应单独提示；超时/断网结果未知先查对象或唯一编号，不自动重放写操作。会话失效隐藏管理资料并返回登录；CSRF恢复后由管理员明确重试。
- 资料保存、物品启停、芯片服务状态、发行确认与正式接续各自说明影响。停用不等于挂失/退役，首次绑定芯片不等于绑定所有人；未定资格不做成可点的假动作。
- 当前实体/芯片来自正式结果；候选准备只标准备中。接续完成后历史只读，新旧关联及必要归属一致；不能按新建/快递时间推断生效。
- 危险确认显示目标、影响及必要依赖，不要求所有操作反复输编号/填长说明。删除/纠错资格按主方案定稿，UI禁用不能代替后端检查。
- 密钥、验证码、完整动态读数和凭证不进入截图、普通日志或通用资料预览；受控密钥查看/真实配置沿既定方案。账户信息与用户公开内容分开，不直接把后台详情搬到H5。

## 5. 设计验收与定制边界

下一版预览与正式整合复用同一官方Umi/Pro页面和主题，交互预览使用的隔离样例不进入正式业务。每类页面先明确采用的官方模式、必要业务适配和实际缺口。可用配置、组合、Token解决的，不另写通用布局/分页/表单/弹层框架；换成Pro组件名称不等于已经规范或美观。

按主方案四组任务检查：信息层级、主次按钮、表单宽度/密度、合理留白、状态/错误、关联返回、两种桌面窗口、焦点和操作可达。应先查看实际截图再判视觉结果，构建或测试数量不能代替cece验收。只验证受影响业务，不恢复已取消的React19独立组件矩阵。

隔离原型使用合成数据时明确标记。演示登录、Webhook、密钥、假核验、时间推进、故障注入及sessionStorage样例不进入正式工程。本轮仅更新规范，未重做原型或声称已有新截图；原Make和旧经营原型的尺寸/测试证据保留作历史。
