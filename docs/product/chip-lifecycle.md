# 芯片生命周期：登记、首次绑定与配置核验

适用范围：本仓库已交付的芯片业务规则，含A的查询、详情及批次维护增量；不代表已验收、合入main或部署。尚未交付的A物品和图片规则以及B/C/D仍在[独立提案](../../PRD.md#6-独立改动提案)，不由本增量开放权限。任务看[TODO](../../TODO.md)，验收/合并证据看[CHANGELOG](../../CHANGELOG.md)，逐接口实现范围看[API概览](../../API_CONTRACT.md#04-当前能做到哪一步)。

原功能定位：F1-01对应第1节，F1-03对应第2节，F1-05/F1-06对应第3节。

## 1. 芯片登记与首次来源

场景：管理员先登记真实芯片身份，之后再建立物品关联与配置；登记不证明防伪、所有权或可出厂。管理员认证与通用页面保护见[后台规范](admin-management.md#1-管理员与操作权限)。

当前支持管理网页手动填写UID，可暂不分配项目，批次可空；重复登记不分配、清空或覆盖原项目。仅当原记录已有项目且本次明确选择另一个项目时拒绝，并说明原记录未修改。手动登记不代表 F1-01 的真实扫描验收通过，检查步骤见 [芯片登记验收](../CHIP_REGISTRATION.md)。

扫描和首次来源的既有验收记录见CHANGELOG。流程为单台手机用NFC.cool先批量写固定文本cece，再批量读卡；App自动保存并回调，无需逐张点保存。真实样品登记和重扫去重证据见[历史记录](../../CHANGELOG.md)。手机仅开启NFC触发，使用已有管理员名及独立扫码密码；新增登记为未分配，重复扫描保留原资料，记录凭证归属和来源。失败后人工重扫，不做离线队列、实时推送、绑定或后台自动写卡。

完全未写内容的卡在既有实测中无回调，不作为已通过能力。登记使用真实7字节UID；已开启随机UID/SUN的卡不按随机编号登记，也不在本接口解密。测试环境建议及第三方证据见[技术说明第2.5节](../../TECH_SPEC.md#25-手机扫描后自动登记)。

芯片记录只维护首次登记来源，后台列表显示“手机扫描／网页手工／历史未知”。不保存或展示扫描内容、手机时间；重复登记不改变首次来源及原资料。来源由后台根据入口确定，手机或网页不能自行指定。

芯片查询使用Ant Design官方查询表单和分页，默认每页20条；关键词覆盖UID、关联物品编号和名称，展开条件包括批次、首次来源、关联有无、密钥生成、配置核验、登记/更新/核验日期。日期按北京时间包含起止日，服务端完整过滤后计数分页；关键词匹配来源可区分。列表不自动轮询，扫描后按[登记手册](../CHIP_REGISTRATION.md)主动查询；异常时区分网络未到达、认证拒绝和业务拒绝，不把登记成功当作芯片已配置。

验收：网页手动登记与真实手机回调分别检查；相同真实UID重复登记不新增、不覆盖原项目/批次/首次来源，认证失败不入库；空白卡、随机UID不冒充通过。速度目标及旧计时口径差异见[共用质量目标](../../PRD.md#4-共用质量目标与安全边界)。

芯片详情和编辑共用同一份业务字段：UID、项目、状态、批次、首次来源、关联物品及名称、密钥生成、配置核验时间、登记和更新时间。详情全部只读，编辑仅开放批次补录/修改/清空（去首尾空白、最多64字符），其余字段保留只读值及原因；不开放秘密或内部诊断。批次不变时不重复记审计，保存失败不保留半次修改。

关联物品是引用，按接口返回的真实item_id读取只读详情，可返回原芯片；失效或不存在时说明原因，不跳到其他记录。查询和页码放安全站内URL；返回保留已提交条件，刷新/前后退不丢查询。创建成功保留项目、清空UID和批次，提供查看确切新/原记录入口，原列表条件不改变；关闭后按原条件刷新。

普通未保存修改离开时可保存后继续、放弃继续或取消，提交中阻止离开和重复写入；刷新/关闭使用浏览器原生提醒。保存回执丢失先按ID核对，不能自动重放；CSRF更新后仍需手动提交，401隐藏管理资料。记录保存后不再匹配原查询时列表按原条件展示，页面提示可调整查询。详情/编辑/返回验收见[芯片手册](../CHIP_REGISTRATION.md#2-按顺序验收)。

## 2. 首次绑定物品

两项目共用首次绑定规则，允许绑定非归档物品；当前不提供解绑/换绑。该关联不是用户认领，绑定不会自动写卡或生成密钥。

**目标与范围**

管理员能把一枚已登记、待绑定芯片关联到一件已创建物品，并在芯片列表查到结果。这是实体芯片与数字档案的关联，不是用户认领，不触碰或改写真实卡，也能验收后台关联是否正确。

- 从芯片列表进入确切记录详情，再打开绑定弹窗；复用物品查询，不改变首次绑定检查。
- 两项目使用同一绑定规则；服装为主要操作场景，同时验证饰品项目匹配及跨项目拒绝，不增加饰品资料编辑或用户页。
- 只做首次绑定和结果查询；绑定动作本身不执行解绑、换绑、批量绑定、芯片启停、密钥、写卡、用户查看、所有权或自动编号；后续已交付的密钥和用户查看分别按对应规范操作。
- 已有归档或停用数据仍保留；当前不提供删除入口，不把占位按钮显示为已实现。

**解绑、换绑为什么后置**

现行首次绑定只建立正确关联并能查回。解绑会改变已有关系，还需明确解除后项目、密钥、写卡记录、用户访问和所有权如何处理；换绑还要保证旧关联解除与新关联建立同时成功，不能出现旧关联已丢失、新关联却未建成。

这是交付顺序的取舍，不是功能做不了，也不表示所有解绑都必须等到完整流转后台。代价是现行版本发生误绑定时，管理员不能自行纠正，所以必须使用专用样例并在确认前核对双方编号。真实试用前需明确受控纠错办法；若优先需要纠正尚未写卡、尚未被用户认领的关联，可另出范围受限的解绑小步，不默认开放已写卡或已认领物品的自由换绑。

**正常操作流程**

1. 登录后，在芯片列表找到目标UID，点击“查看详情”后打开“绑定物品”。只有芯片处于“待绑定”且未关联物品时可操作；其他状态入口不可用，保留关联摘要，不提供快捷换绑。
2. 弹窗顶部只读显示芯片UID、当前项目、批次和状态；项目未分配明确显示“绑定时按目标物品确定”。
3. 输入物品编号或款式编号，点击查询；关键词按已有物品查询功能做包含式匹配，不承诺名称搜索。项目已确定时按对应项目查询；未分配时可选择服装或饰品。候选排除已被任何芯片关联的物品，原芯片停用或丢失也仍算占用；总数和分页按排除后结果计算。每页20条，可翻页，不加载全库，不轮询；普通物品管理列表仍显示所有符合其筛选条件的物品。
4. 候选行展示项目、物品编号、款式编号、名称（未填写则标明）和状态；明确单选，不自动选择第一条。查询条件改变或换页时清除旧选择；再次查询前标明列表仍是上次结果并禁止确认，避免误绑未生效筛选。新查询失败时旧结果不可选。候选列表不承诺全部可绑定，最终以后端提交时检查为准。
5. 选择后，在同一弹窗显示完整芯片UID、目标项目及物品编号的确认区，并提示“绑定不等于写卡；本版本暂不提供解绑或换绑”。管理员勾选已核对后才能点击“确认绑定”；仅为操作确认，不新增认证步骤。
6. 只有后端确认保存成功，才关闭弹窗并显示含UID和物品编号的成功卡片。芯片列表清除项目/状态筛选，以该完整UID查询第一页，显示“已绑定”、已确定项目及物品编号；列表刷新失败单独提示，不能把已经成功的绑定改报失败或再次提交补偿。

候选查询只是协助选择，不预先占用物品。确认前的勾选在更换选择或查询后清除。取消弹窗不保存；已选择目标时关闭须确认放弃，查询文字不持久保存。提交中禁用重复提交、关闭及切换；浏览器异常退出不保证恢复输入。页面不自动重发绑定请求。

**业务规则与操作限制**

| 情况 | 规则与结果 |
|---|---|
| 芯片与物品 | 都必须已登记或创建；绑定时不自动新建。页面展示芯片编号与物品编号，管理员核对后选择 |
| 选择与确认 | 必须选择一个明确的目标物品并确认双方编号；未选择不能提交。绑定表单不允许另行修改项目、状态或登记来源；项目按既定规则确定 |
| 芯片条件 | 必须为“待绑定”且未关联物品；已绑定、停用或丢失的芯片不能直接绑定，不提供恢复或强制覆盖操作 |
| 项目 | 芯片未分配时，首次绑定按目标物品确定；已有项目必须匹配，不能通过绑定更改项目。确认区显示项目变化 |
| 物品状态 | 允许草稿、启用和停用物品，拒绝归档物品。无需先有名称/图片或启用；这是建立关联，不代表可以面向用户使用 |
| 物品已有关联芯片 | 拒绝，包含其原芯片处于停用或丢失状态的情形，不抢占、不自动解绑 |
| 重复请求 | 已绑定即按已有规则拒绝，包括同一芯片重复绑定同一物品；不改原关系，不重复记录成功变更，不做“重复也返回新增成功” |
| 绑定成功 | 仅保存必要绑定/项目/状态和更新时间、对应操作记录；芯片转为“已绑定”。不改物品状态、资料、首次来源、批次、UID、原密钥、写卡时间或计数器，不新增所有权 |
| 绑定失败 | 项目、关联、状态和成功变更记录一起撤销；未知提交结果须先查询核实，不能依据超时断言未保存 |
| 同时提交 | 多人抢同一物品或同一芯片时，只能一个请求建立关联；其他请求明确拒绝，不能产生一物多芯片或部分项目分配 |

物品已启用不代表绑定后就可验证。未来用户验证仍必须检查物品、芯片、密钥及写卡配置的当前状态。实现时必须保留已有资料，不能通过清空或重建数据完成升级；具体保存及升级方案在技术文档中核对。

**异常与反馈**

- 参数错误、记录不存在、重复绑定、项目冲突、目标已被占用和状态不允许分别提示；沿用已有业务规则，不显示内部程序或数据库报错。发生争抢时提示重新查询当前关系，不自动选择其他物品。
- 登录失效按现有流程隐藏管理数据；页面防冒用校验失效提示刷新页面后重新核对提交，不自动刷新并重发。
- 网络超时或响应不可读提示“结果尚未确认，请按此UID查询”；可确认已保存才显示成功，可确认未绑定后才由管理员重新选择提交。查询失败继续提示未确认，不伪装成未绑定。
- 可确认的业务拒绝保留当前选择供核对；重新读取发现已失效时禁止提交。后端验证永远优先于打开弹窗时的旧状态。
- 真实误绑定没有自助纠错入口：保留UID、物品编号、操作时间和错误编号（若有）反馈；停止对该芯片后续写卡，不在聊天指示改库。技术方案与测试用例不能绕过该边界。

**人工验收与技术验证**

| 验收组 | 操作与通过条件 |
|---|---|
| 正常绑定与结果保留 | 未分配项目芯片绑定服装草稿，确认区显示项目；成功后芯片为“已绑定”且关联正确，物品仍为草稿。刷新及重新登录后关系仍在 |
| 已确定项目及候选选择 | 同项目正常绑定；饰品执行相同通用规则。芯片已确定项目时只列对应项目；查询、分页、更换条件后不会沿用旧选择；归档不可绑定。绕过页面跨项目提交由技术测试验证拒绝且不改原资料 |
| 重复与状态保护 | 可用两个提前打开的窗口验证同芯片重复提交拒绝；另一芯片抢同物品拒绝。停用或丢失的芯片不允许绑定，不自动覆盖或恢复；人工环境缺少状态样本时由隔离技术测试覆盖，不要求cece改库造数据 |
| 取消与异常 | 取消不改数据；登录失效、防冒用校验失败及超时处理符合上述规则；成功与随后列表失败分别提示。故障模拟由AI在独立临时环境覆盖，cece无需破坏现有服务 |
| 原流程回归与边界 | 登录、登记及去重、物品创建/资料/启停仍可用；绑定不生成密钥、不改变登记来源或写卡记录，不显示用户所有权已绑定 |

多人争抢、操作记录与业务修改一起保存或撤销、提交时再次核对登录、绕过页面的非法操作及不同失败提示，由独立测试环境的自动检查覆盖。人工样例绑定会保留，优先用专用样例，不能因为没有解绑入口就清空数据库。人工操作位置见[桌面管理端手册](../ADMIN_DESKTOP.md)；故障和竞争场景按隔离技术检查执行。

## 3. 密钥查看与实卡配置核验

管理员先完成芯片与物品绑定，再生成密钥、确认查看并按操作手册配置测试卡，最后提交两次独立触碰取得的链接进行核验。两个项目使用同一套操作；暂不做批量导出和完整密钥管理页面，需求保留在TODO待排期。

页面明确区分“密钥未生成／已生成”和“配置未核验／已核验”。生成密钥不会写入卡片；已有密钥不允许覆盖。查看前说明其中一把钥匙影响同版本全部芯片，并要求主动确认；关闭弹窗或退出后不保留展示内容。

配置完成须同时满足：两次读数属于该芯片、防伪检查通过、读取序号递增，并由管理员确认管理认证及文件权限已经人工核对。系统核验与人工确认分开记录。成功不自动启用物品，不代表用户手机资料页或防重放功能已经验收；错误和未知结果不得显示假成功，重复确认不能重置既有记录。

人工验收按生成保护、受控查看、实卡配置核验、错误/重复保护及双卡对照五组执行，见[真实卡手册](../NFC_CARD_VERIFICATION.md#4-密钥与配置联合验收)。技术规则集中在[技术附录第14节](../IMPLEMENTATION_DETAILS.md#14-测试卡密钥与配置方案)，精确请求及错误在API，不在产品需求重复字段。

查看密钥须先二次确认，记录操作者、芯片、时间与访问来源指纹，不保存原始IP。明文展示不缓存、不写本地存储；服务端仍核对登录与权限。K1是该版本全局共享秘密，其影响不局限于当前单卡；已有密钥不得覆盖。精确保护规则只在[技术附录](../IMPLEMENTATION_DETAILS.md#5-限制重试与记录操作)维护。

## 4. 未交付动作与专用处理

芯片临时停用/恢复仍属既定后续需求，不能把物品启停当作芯片启停；规则入口见[后续范围](../../PRD.md#3-既定后续范围与未验证候选)。身份错填、误绑定及生产验证数据清理见 [清理与纠错方案](../proposals/admin-make-rebuild.md#26-清理纠错和旧资料补齐)，挂失、换新与转售见 [核心流程](../proposals/admin-make-rebuild.md#flows)。这些动作走专用入口，实际交付范围以 [接口概览](../../API_CONTRACT.md#04-当前能做到哪一步) 为准。
