# 后台管理：日常操作、资料与统计

适用范围：仓库已纳入的后台规则，包含批准A改版的已实现部分；是否已验收、合入main或部署以TODO和CHANGELOG为准。待改行为在[独立提案](../../PRD.md#6-独立改动提案)审核，不能用提案覆盖这里的现行行为。任务看[TODO](../../TODO.md)，验收/合并证据看[CHANGELOG](../../CHANGELOG.md)，逐接口实现范围看[API概览](../../API_CONTRACT.md#04-当前能做到哪一步)。

原功能定位：F1-09对应第1节，F1-02对应第2–3节；工作台有效触碰口径见第4节。

## 1. 管理员与操作权限

管理员负责登记、建档、维护和查询；芯片绑定、密钥与实卡流程见[芯片生命周期](chip-lifecycle.md)，用户网页见[服装触碰](fashion-touch.md)。后台面向桌面Chrome／Edge，手机管理端不在当前范围。

一个表单填写账号、密码和Authenticator六位验证码，全部通过才登录；首次设置和丢失后重置通过受控服务器命令完成，不提供注册、找回密码、网页设置或备份码。同一时段验证码不能重复使用，连续失败暂锁；退出、禁用或重置验证器后旧会话失效。网页来源和防冒用检查不能因换组件取消，秘密不存浏览器本地存储。操作步骤见[管理员登录](../ADMIN_LOGIN.md)。

## 2. 物品草稿创建与列表

管理员用草稿建立一件真实物品的身份，为资料维护和首次绑定准备对象；创建不自动编号、启用、写卡或生成密钥。项目必选服装/饰品；物品编号全系统唯一，去首尾空白后为FASH-YYYY-NNNNNN或JEW-YYYY-NNNNNN，半角大写前缀对应项目、4位年份和6位序号；小写、全角或其他Unicode数字拒绝，0000/000000格式允许但不推荐，不据此判断实际生产年份。款式可空、可重复，去首尾空白后最多64个字符。

列表通过Ant Design Table、查询Form及内置分页，常用条件为关键词、项目、状态，关联芯片及创建/修改日期按官方模式展开；关键词查编号、款式、所属项目资料名称和关联芯片UID，并说明命中来源。停用/丢失芯片仍占关联，查询可见不等于可绑定。日期按北京时间包含首尾日，非法范围拒绝；完整服务端过滤和计数后分页，默认20条、超页回有效末页，不仅过滤当前页。空库、无匹配和读取失败分别提示，不用旧结果或0冒充本次查询。

“创建物品”打开官方Modal与Form组合，创建成功显示确切编号，保留项目、清空已提交编号/款式供连续创建；原列表条件不改，另提供查看/完善本次实际返回ID的入口，不靠最新第一行猜目标。原编号重复明确拒绝，不覆盖记录，创建与审计一起成功或失败。成功后列表刷新失败不把已创建改报失败；回执未知先按完整业务编号核对，查不到也不自动重发。

已提交条件和页码放URL，返回位置与滚动放安全站内路由state；刷新与浏览器前后退保留工作上下文。未提交查询不偷偷生效，密码、凭证和编辑草稿不进入URL或持久存储。创建/编辑离开保护见第3节；操作与人工验收见[物品手册](../ITEM_DRAFTS.md)。

## 3. 服装基础资料编辑与启停

列表按真实ID打开详情，详情与编辑共用同一份适用业务字段定义：物品编号、项目、款式、状态、关联芯片/状态/密钥及核验摘要、创建/修改时间，以及所属项目已有资料。无值明确显示未填写/未关联；关联是可点击引用，按ID打开芯片并保留来源及列表上下文，不能用关键词第一行代替。秘密与内部诊断字段不展示。

编辑仅放开款式和服装的名称、介绍、材质、养护、图片；物品编号、项目、状态、关联、时间与配置只读，尺码表只读保留，不能随普通保存写回或清空。饰品只改款式，已有名称/介绍/材质/寓意/图片仍只读，不新增资料模板；归档完全只读。只读使用官方文本/描述与链接，不把所有字段变成禁用输入框。款式及服装资料一次原子保存，失败不留部分修改；仅改款式无需创建名称，无修改不发送保存请求，状态仍独立。

服装资料改变时名称须去首尾空白后1–128字符，介绍4000、材质256、养护2000字符，可空，保留内部换行，按普通文字展示。省略整份profile表示不改资料；提交时只替换明确五项可编辑字段，清空可选文字或图片表示移除内容。多人编辑以最后成功保存的整份可编辑资料为准，不新增版本冲突合并。完整接口、格式及图片数量限制见[API第4节](../../API_CONTRACT.md#4-管理物品)。

图片使用官方Upload选择本地文件并展示真实状态，最多20项，兼容保留原外部图片。必须先有确切物品ID；上传成功仅暂存，只有保存资料才关联，取消编辑不改已保存图片。上传中不提交或离开，允许移除取消本张请求，晚到响应不恢复已移除项；失败保留反馈并可明确重试/移除，未知回执先核对状态，不自动重新上传或关联。预览和移除使用官方交互；排序、裁剪和媒体库不在本次范围。格式/像素/保留期与受控读取见[图片契约](../../API_CONTRACT.md#41-私有图片上传暂存与读取)，不在页面承诺原图保存或匿名永久地址。

关闭、切换、关联跳转、导航或返回时，有未保存输入选择保存后继续、放弃继续或取消；上传/保存处理中拒绝离开，浏览器关闭/刷新使用原生提醒，不承诺异常退出恢复。读取失败不能当空资料保存；保存超时先按确切ID核对，输入保留，不自动重发。登录失效隐藏管理资料；CSRF失效只更新会话，等待明确重提。保存成功按原条件刷新列表，若记录不再匹配可调整查询，不暗改条件或将刷新失败改报保存失败。

服装启用/停用在独立受控操作区明确确认；未保存时先选择保存/放弃/取消，再确认状态动作，不隐式保存。草稿或停用须已有有效名称才能启用，启用可停用；相同目标幂等，不开放退回草稿、归档或恢复归档。资料、关联与历史保留，启用不证明芯片绑定/写卡/防伪完成；用户资格及停用效果沿用[服装触碰规范](fashion-touch.md#2-手机资料页与持续查看)。生产上传默认关闭，实际配套备份、恢复和部署前提仍由运行手册落实；到期媒体技术维护不授予B数据删除权限。

## 4. 工作台有效触碰统计

本节定义统计目标、统计口径、页面布局和交互；接口契约见 API_CONTRACT 第 8 节，实现机制见[技术附录第16节](../IMPLEMENTATION_DETAILS.md#16-工作台有效触碰统计技术方案待审核)。当前可用范围以 API_CONTRACT 第 0.4 节为准，任务状态与验收证据见 TODO 和 CHANGELOG。只读桌面管理网页；共享框架采用Ant Design，保留现有统计聚合与图表行为，不扩展统计口径或整套设计系统。

**目标与范围**

让管理员回答：所选时间内有多少次有效触碰、涉及多少件物品、每天的变化怎样、哪些物品被触碰及最近何时被触碰。覆盖服装和饰品，可选全部项目或单一项目。第一版不能判断触碰者是谁，也不能判断物品是否已经卖出。

一次有效触碰，是服务器通过完整验证、接受新读数并成功保存的事件。不直接采用芯片内部计数器数值或差值；同一读数重复请求、刷新或并发只计一次。后台配置核验、失败请求、重复获取资料不计入；验证成功后资料未加载完成，也已算一次有效触碰，因此该指标不等于资料页浏览量或看完次数。

**页面位置与布局**

沿用侧栏“工作台”，登录后可直接查看；不新增一级导航、独立统计后台或弹窗。页面从上到下为：

| 区域 | 本期内容 | 范围与交互 |
|---|---|---|
| 页面标题 | 保留现有问候及工作台入口 | 文案说明可看库存与有效触碰情况 |
| 全局库存概况 | 芯片总数、待绑定芯片、数字物品数 | 显式标注“全局库存”；保留刷新概况，不受下方触碰筛选影响；移除未接入的有效所有权数字占位 |
| 快捷操作 | 登记与查询芯片、维护物品资料、检查运行环境 | 保留现有真实入口，不增加统计专用快捷按钮 |
| 有效触碰统计 | 项目、时间、查询统计、刷新统计 | 筛选只作用于本区域；显示当前已生效条件、具体起止日期和数据截至时间 |
| 指标卡片 | 有效触碰次数、被触碰物品数 | 两项均为所选项目与时间范围；不可点击，不增加钻取入口 |
| 每日趋势 | 每日有效触碰次数柱状图 | 替换先前未实现的入库趋势占位；不再保留查看详情的未实现按钮 |
| 物品触碰明细 | 关键词查询、表格、分页 | 只列所选范围内发生过有效触碰的物品；关键词只影响本表 |
| 口径说明 | 计数规则、历史覆盖起点 | 常驻简短说明，不要求靠悬浮才能发现指标限制 |

采用官方布局的页面滚动方式。桌面矮窗口可滚动到趋势、明细和分页，不把按钮或提示裁掉；表格必要时在自身区域横向滚动，不新增明细表内的竖向滚动层。

**项目、时间与刷新**

- 初次进入默认“全部项目＋近7天”，自动查询第一页，不需要再点查询；不使用模拟数据填充未返回的区域。
- 项目选项为全部项目、服装、饰品，不按数据库数字编号展示。某个项目无记录时仍可选择，不能隐藏或用另一个项目的数据代替。
- 时间选项为近7天、近30天、累计。近7/30天含今天，按北京时间自然日划分；今天只统计到本次数据截至时间，不声称整天已结束。
- 例如在10月27日查询近7天，日期范围是10月21日至27日，而非往前滚动168小时。累计涵盖所选项目全部已记录的有效事件；不推算首次记录之前的数据。
- 修改下拉选项暂不发请求，显示“筛选条件已修改，点击查询统计生效”；旧内容仍标示原先已生效条件，不把新下拉值当作旧数字的标签。改回原条件后提示消失。
- 点击“查询统计”后提交项目与时间，清空明细关键词并回第一页；成功后卡片、趋势、明细和数据截至时间一起更新。
- “刷新统计”只按当前已生效的条件重新获取，不提交尚未查询的下拉选项或关键词，保留已生效明细关键词和页码。没有待生效改动时也不自动轮询。
- 查询或刷新期间显示对应动作的加载状态，暂时禁用本区域的重复请求与翻页；不阻塞退出登录或其他页面导航。离开后返回，重新使用默认条件查询，不持久保存筛选条件。
- 全局库存的“刷新概况”仅刷新库存；触碰区域的“刷新统计”仅刷新触碰。两个区域分别显示反馈，避免一个成功掩盖另一个失败。

**指标与趋势**

| 内容 | 展示规则 |
|---|---|
| 有效触碰次数 | 本范围内有效事件总数；显示完整整数，可用千位分隔，不用四舍五入的“万”代替精确值 |
| 被触碰物品数 | 本范围内至少有一次有效触碰的不同物品数量；同一物品触碰两次，次数为2，物品数为1 |
| 每日趋势 | 一天一根柱；近7/30天补齐没有事件的日期并显示0，不能把缺失或失败响应补成0 |
| 全部项目 | 展示两个项目合计趋势；切换单项目后展示该项目，不额外增加多系列对比或饼图 |
| 日期与数值提示 | 鼠标悬浮或键盘聚焦某一天，可读出完整日期、星期和有效次数；今天标注“今日未结束” |
| 累计趋势 | 从所选项目首条有效记录所在日到今天，按天呈现并补零；日期标签随宽度减少显示密度，不能无提示截掉较早数据 |

没有有效记录时，卡片显示0；趋势区显示“所选时间暂无有效触碰记录”，近7/30天仍可展示全零日期基线，不画假走势。指标区注明“非独立用户数、非售后专属统计”。

**物品触碰明细**

| 列 | 展示规则 |
|---|---|
| 项目 | 服装或饰品；全部项目查看时用于区分，单项目也保留 |
| 物品编号 | 完整业务编号；不显示芯片内部编号、读取计数器或密钥 |
| 名称 | 当前名称；没有名称显示“未填写”，仍可按编号识别；长名称允许换行，不因截断而无法读全 |
| 有效触碰次数 | 当前项目与时间范围内该物品的次数，与上方使用同一计数口径 |
| 最近触碰时间 | 当前所选范围内最近一次有效触碰，显示北京时间，精确到秒 |

- 默认按次数倒序；次数相同按最近触碰时间倒序，再按物品编号稳定排序。第一版不增加点击表头改排序。
- 一行一件物品，不列出未发生触碰的库存。物品后来停用或归档仍保留历史；未来换绑不迁移既有归属。第一版无“从未触碰物品”清单或触碰率，避免提前引入未定义的分母。
- 关键词支持物品编号或当前名称的模糊匹配，去首尾空白，最多128个字符；超长就地提示，不发送请求。输入不自动查询，点击“查询物品”或按回车才生效；输入改动后说明尚未查询。
- 关键词区明确标注“仅筛选下方明细，不影响上方指标与趋势”。生效后显示当前关键词；点击“清空”时清空关键词、回第一页并查询，不改变已生效项目和时间。明细查询与清空都不提交上方尚未查询的项目或时间选项。
- 每页固定20件，不增加页大小选择；显示“共N件／第X页，共Y页”，上一页和下一页在边界禁用。空列表显示“共0件”，不显示第1/0页。
- 关键词查询回到第一页；翻页保留已生效项目、时间及关键词，不能顺便提交未查询的输入。若刷新后当前页超出范围，自动回到有效末页并提示已调整；无结果回到空列表。
- 明细查询、清空、翻页也会获取同一时点的整组统计。关键词本身不改变卡片口径；这期间若发生新有效触碰，卡片和趋势可随新数据同步变化，数据截至时间同时更新。各次查询/翻页是新的时点，排名可随新增触碰变化；第一版不提供跨页冻结报表。
- 本期行不可点击，不增加物品详情弹窗、逐次触碰日志、导出、删除或手工修改次数入口。

**数据时间与保留**

显示“当前统计：全部项目／近7天／实际日期区间”和“数据截至：年月日时分秒（北京时间）”。同一组卡片、趋势和明细采用同一次成功查询的数据，不能混用不同项目或时点的结果。

有历史记录时另显示所选项目“首条有效记录时间”；没有记录显示“尚无有效记录”。累计无记录时不虚构起始日期。首条记录不是系统上线时间或交付时间，不能用它推算更早的行为。名称按当前资料显示，项目和物品归属按触碰发生时保留；后续修改资料、停用或归档不减少累计次数。恢复了更早的数据库备份则需另行核对数据覆盖，本期不承诺跨数据库恢复仍能补回丢失事件。

**加载、空状态与失败**

| 场景 | 页面行为 |
|---|---|
| 首次加载 | 卡片显示加载占位，趋势和明细显示正在读取；不显示0或上次会话数字 |
| 查询新条件中 | 可保留上次内容并标注原范围与“正在更新”；成功后整组替换，不让旧数字套上新项目标签 |
| 统计读取失败 | 显示“触碰统计读取失败”和重试、错误编号（后端提供时）；首次不展示数字，已有结果则明确标为上次成功结果及原截至时间 |
| 重试 | 重试刚才失败的那一组条件；成功才把新条件标为生效。失败条件与上次成功条件不同时，页面同时说明，不能让人误以为新条件已查询成功 |
| 范围内没有事件 | 卡片为0、趋势无事件提示、明细为空；不是错误，不弹成功或失败Toast |
| 仅关键词无匹配 | 保留上方正常指标与趋势，明细提示“没有匹配的物品”，提供清空关键词；不把全局触碰次数改成0 |
| 库存失败、触碰成功或反之 | 失败区域单独提示；成功区域正常展示，不显示整页假成功或假零值 |
| 登录失效 | 清除库存和统计展示，回登录；重新登录后重新查询，不保留前一个登录状态下的数字 |
| 连续操作或离开页面 | 禁止重复提交；离开后的旧响应不能覆盖新页面，不能在退出后重新显示统计内容 |

**本期不做**

不区分售前/售后，不做独立用户数、停留时长、转化率、触碰率、无触碰库存、逐次日志、下载报表、复杂筛选、自选日期、自动轮询或手工改数。交付标记与售后统计继续按[对应规范](../../PRD.md#3-既定后续范围与未验证候选)单独排期。数据准备依赖触碰验证后端及其日志升级；统计页面完成不代替真实卡、公网用户页或销售链路验收。

**五组验收**

1. 数字与范围：同一物品两次独立有效触碰显示2次/1件；配置核验、重复或失败不增加。两个项目分别与全部汇总正确，无记录项目显示0，停用后历史仍在。
2. 筛选与查询：默认全部/近7天；修改未查询不改变结果标签；查询切换项目/时间并重置明细；关键词只影响明细，回车、清空、20件分页和排序正确。
3. 趋势与日期：北京时间边界和含今天的7/30天准确，零日期补齐，今日未结束标识正确，累计不截掉早期记录；悬浮/聚焦可读当天数值。
4. 刷新与故障：刷新保留已生效条件，未查询输入不偷生效；同一组结果及截至时间一致。初次失败不是0，上次结果保留时有清楚标签，重试恢复，关键词空结果与全局无事件区分。
5. 页面与权限：桌面矮窗口能滚动到所有内容，快捷入口可用、库存不受触碰筛选影响；退出/会话失效清除数据，旧请求不回填。真实事件与专属临时库构造数据分别记录，不用模拟页面冒充已接入。

## 5. 桌面页面与反馈

共享登录、导航、概况和芯片流程采用Ant Design 6官方组件，图表与既有统计聚合保留；物品列表、详情/编辑、连续创建和Upload采用同一官方组件体系，字段规则见上文。本次Make的布局与展示组合用于实现，旧原型仅供参考；业务字段、权限与接口以本规范为准。详情使用抽屉、编辑使用弹窗，操作栏可持续到达。管理端只面向桌面浏览器；手机H5独立维护。登录仍使用账号/密码/Authenticator同一表单，不新增注册或恢复权限。

日常菜单列工作台、芯片、物品和系统状态；未交付的所有权、设置和通知不列为日常入口。工作台库存与触碰统计按第4节展示；请求失败不填0，不据当前页推算全库，不保留演示数量。运行检查从工作台或系统状态进入，只说明真实连接结果。未交付的所有权、导出、纠错或归档不作为日常操作入口。

芯片查询、详情、批次及安全返回按[芯片规范](chip-lifecycle.md#1-芯片登记与首次来源)执行；物品创建、资料、图片及启停按第2–3节。普通字段的保存不与绑定、状态或密钥操作混为一次提交。

采用官方布局的页面滚动，表格按需横向滚动、弹窗内部滚动，矮窗口能到达全部操作；弹窗保留焦点、Escape及关闭确认，处理中不能离开或重复提交。加载、成功、空结果和失败分开；失效会话隐藏管理资料，刷新通过会话恢复，不存本地登录秘密。芯片普通未保存输入提供保存后继续/放弃继续/取消；绑定/密钥保持原受控确认，不能由离开弹窗自动提交危险动作。

人工验收五组见[桌面管理端手册](../ADMIN_DESKTOP.md)：登录会话；全部导航和运行检查；芯片回归；物品与服装资料启停；未实现提示及桌面滚动。页面整合不改变既有业务规则或部署方式；所用框架、组件与版本由对应技术文档维护。
