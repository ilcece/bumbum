# 后台管理：日常操作、资料与统计

适用范围：仓库已纳入的后台认证、逐件订单办理、桌面交互与工作台规则；是否已验收、合入main或部署以TODO和CHANGELOG为准。未决政策在[独立提案](../../PRD.md#6-独立改动提案)审核，不能用未决条款覆盖这里的现行行为。任务看[TODO](../../TODO.md)，验收/合并证据看[CHANGELOG](../../CHANGELOG.md)，逐接口实现范围看[API概览](../../API_CONTRACT.md#04-当前能做到哪一步)。

后台按[数字档案规范](digital-catalog.md)和[新版四组验收](../ADMIN_DESKTOP.md#8-新版数字档案后台四组验收)承接款式/发行、整套物品与统计；API实际范围见第11节，现行基础认证/安全要求保持。旧页面名称及单件资料维护仅用于缺失发行的历史兼容，不覆盖新共用模型。人工验收、main合并和部署分别以TODO为准。

阅读顺序：第1节是登录权限，第2节先讲当前订单办理，再明确旧单件接口的兼容边界；第3节仅供旧单件资料接口，第4–5节是当前工作台及桌面交互。详细字段统一见[业务字段](admin-fields.md)。

## 1. 管理员与操作权限

管理员负责登记、建档、维护和查询；芯片绑定、密钥与实卡流程见[芯片生命周期](chip-lifecycle.md)，用户网页见[服装触碰](fashion-touch.md)。后台面向桌面Chrome／Edge，手机管理端不在当前范围。

一个表单填写账号、密码和Authenticator六位验证码，全部通过才登录；首次设置和丢失后重置通过受控服务器命令完成，不提供注册、找回密码、网页设置或备份码。同一时段验证码不能重复使用，连续失败暂锁；退出、禁用或重置验证器后旧会话失效。网页来源和防冒用检查不能因换组件取消，秘密不存浏览器本地存储。操作步骤见[管理员登录](../ADMIN_LOGIN.md)。杭州test另支持已配置的通行密钥；该可选入口不改变原密码/验证器的认证要求。

## 2. 物品草稿创建与列表

### 订单履约与数字物品

订单管理保存逐件履约所需的外部订单号和原购买信息。订单件可以登记新实物、选未装配实物，或选已核验并启用的数字库存。系统分别记录实物准备、分配、首次成交、实际交付及认领。保存后从同一订单件继续，多件订单各自推进。原成交、交付代次和必要审计可从数字物品档案回查。

数字物品档案集中维护身份、发行、实物与芯片、订单与交付、持有人、权益及历程。独立实体列表服务库存。授权、菜单和交互以[全局方案](digital-catalog.md#flows)及[验收清单](../ADMIN_DESKTOP.md#订单与数字物品统一流程验收)为准。

### 工作台准备订单物品

旧版从工作台建立本浏览器待办。新版订单页只为该浏览器保留尚未完成的旧待办。新实物先选款式，登记独立实体编号和实际规格。可先保存实体，再选择同款已确认发行。安装时核对实体、芯片及发行编号，数字身份与安装关系在同一次提交保存。配置核验通过后，由管理员另行确认启用。

选用已有库存时，仅展示已安装实体、已核验、已启用、未售出且没有持有人或认领码的数字物品，直接进入首次售出。成交确认记录有依据的北京时间和「渠道＋外部订单号」。同订单多件可逐件办理，共用来源引用。只有实际交付并核对接收对象后，才发放一次性认领码。售出确认时不发码。

「保存，稍后继续」按管理员、浏览器和当前业务数据或测试批次保存待办。已登记实体、装配、售出及发码结果由服务器保存，恢复时以服务端为准。结果未知时先查原请求回执。回执只记录发放结果。管理员可从物品详情或已交付订单件查看有效认领码，查看留审计。旧码无法查看或过期时核对交付后补发。

成交来源保存在物品的售出依据与操作审计。可在操作审计用外部订单号查询，关联到各物品档案。操作步骤见[桌面管理端验收](../ADMIN_DESKTOP.md#工作台准备订单物品)。

### 旧单件接口兼容

以下创建及资料维护描述仅对应旧单件接口与历史回归，不是新版数字物品菜单的建档流程。新版从发行、实体、芯片及订单进入[共享建档](digital-catalog.md#flows)。

管理员用草稿建立一件真实物品的身份，为资料维护和首次绑定准备对象；创建不自动编号、启用、写卡或生成密钥。项目必选服装/饰品；物品编号全系统唯一，去首尾空白后1至32字符且不含控制字符，不限制格式；FASH-YYYY-NNNNNN或JEW-YYYY-NNNNNN仅作建议，不从编号推断类别或实际生产年份。款式可空、可重复，去首尾空白后最多64个字符。

列表通过Ant Design Table、查询Form及内置分页，常用条件为关键词、项目、状态，关联芯片及创建/修改日期按官方模式展开；关键词查编号、款式、所属项目资料名称和关联芯片UID，并说明命中来源。停用/丢失芯片仍占关联，查询可见不等于可绑定。日期按北京时间包含首尾日，非法范围拒绝；完整服务端过滤和计数后分页，默认20条、超页回有效末页，不仅过滤当前页。空库、无匹配和读取失败分别提示，不用旧结果或0冒充本次查询。

“创建物品”打开官方Modal与Form组合，创建成功显示确切编号，保留项目、清空已提交编号/款式供连续创建；原列表条件不改，另提供查看/完善本次实际返回ID的入口，不靠最新第一行猜目标。原编号重复明确拒绝，不覆盖记录，创建与审计一起成功或失败。成功后列表刷新失败不把已创建改报失败；回执未知先按完整业务编号核对，查不到也不自动重发。

已提交条件和页码放URL，返回位置与滚动放安全站内路由state；刷新与浏览器前后退保留工作上下文。未提交查询不偷偷生效，密码、凭证和编辑草稿不进入URL或持久存储。创建/编辑离开保护见第3节；操作与人工验收见[物品手册](../ITEM_DRAFTS.md)。

## 3. 服装基础资料编辑与启停

本节仅维护旧单件接口的兼容约束，适用于缺失发行的历史资料；新版共用内容从款式维护，数字物品通过已确认发行引用，不在详情另设同一份内容编辑。

列表按真实ID打开详情，详情与编辑共用同一份适用业务字段定义：物品编号、项目、款式、状态、关联芯片/状态/密钥及核验摘要、创建/修改时间，以及所属项目已有资料。无值明确显示未填写/未关联；关联是可点击引用，按ID打开芯片并保留来源及列表上下文，不能用关键词第一行代替。秘密与内部诊断字段不展示。

旧单件文字编辑仅放开款式和服装的名称、介绍、材质、养护；图片统一在新版共用款式维护；物品编号、项目、状态、关联、时间与配置只读，尺码表只读保留，不能随普通保存写回或清空。饰品只改款式，已有名称/介绍/材质/寓意/图片仍只读，不新增资料模板；归档完全只读。只读使用官方文本/描述与链接，不把所有字段变成禁用输入框。款式及服装资料一次原子保存，失败不留部分修改；仅改款式无需创建名称，无修改不发送保存请求，状态仍独立。

服装资料改变时名称须去首尾空白后1–128字符，介绍4000、材质256、养护2000字符，可空，保留内部换行，按普通文字展示。省略整份profile表示不改资料；提交时只替换明确五项可编辑字段，清空可选文字或图片表示移除内容。多人编辑以最后成功保存的整份可编辑资料为准，不新增版本冲突合并。完整接口、格式及图片数量限制见[API第4节](../../API_CONTRACT.md#4-管理物品)。

图片统一使用款式的官方Upload与预览，最多20项，先保存款式再上传，保存资料才发布关联。旧单件上传、图片读取、外链保留和旧域名映射已退役；旧物品可保留文字，图片为空，核对款式/发行后重新上传。不接受任意外链，不将旧物品私有图直接借给新款式。格式/像素与当前资格读取见[图片契约](../../API_CONTRACT.md#113-共用图片与统计)，旧文件清理前的配套备份见[测试重建手册](../HANGZHOU_DEPLOYMENT.md#12-验收批次007与测试数据重建)。

关闭、切换、关联跳转、导航或返回时，有未保存输入选择保存后继续、放弃继续或取消；上传/保存处理中拒绝离开，浏览器关闭/刷新使用原生提醒，不承诺异常退出恢复。读取失败不能当空资料保存；保存超时先按确切ID核对，输入保留，不自动重发。登录失效隐藏管理资料；CSRF失效只更新会话，等待明确重提。保存成功按原条件刷新列表，若记录不再匹配可调整查询，不暗改条件或将刷新失败改报保存失败。

服装启用/停用在独立受控操作区明确确认；未保存时先选择保存/放弃/取消，再确认状态动作，不隐式保存。草稿或停用须已有有效名称才能启用，启用可停用；相同目标幂等，不开放退回草稿、归档或恢复归档。资料、关联与历史保留，启用不证明芯片绑定/写卡/防伪完成；用户资格及停用效果沿用[服装触碰规范](fashion-touch.md#2-手机资料页与持续查看)。生产上传默认关闭，实际配套备份、恢复和部署前提仍由运行手册落实；到期媒体技术维护不授予B数据删除权限。

## 4. 工作台有效触碰统计

工作台按办理、使用、跟进和经营事实组织数据。按日处理任务时先看数字物品的办理阶段，观察 NFC 使用时用同一组条件横向比较频次、覆盖和重复使用。完整操作见[桌面验收](../ADMIN_DESKTOP.md#7-工作台有效触碰统计)，接口见[统计查询契约](../../API_CONTRACT.md)。

| 区域 | 指标与入口 | 统计范围 |
|---|---|---|
| 待办与可分配库存 | 待装配、待核验、待交付、待认领、可分配。整卡打开带对应办理阶段的数字物品列表 | 数字物品当前状态，业务或当前测试批次。服务端用同一个互斥阶段判断计算卡片件数、列表总数和每行阶段 |
| 使用覆盖与频次 | 有效触碰次数、被触碰物品数、重复触碰物品数并排比较。补充每件被触碰物品平均次数及北京时间日趋势 | 相同触碰口径、时间、款式、发行、数据来源和统计截点。重复按同一数字物品至少两次计算，平均值以被触碰物品数为分母。没有被触碰物品时平均值显示「—」 |
| 售出后跟进 | 所选时段售出后零触碰、成交时间待核对。整卡打开对应物品明细 | 售出后的口径专用。零触碰要求已有首次成交时间，在选定时间内没有成交后有效事件。缺少首次成交时间的已售物品单独列示，等待核对成交事实 |
| 售出与持有 | 已确认售出物品、已有持有人物品、当前持有人。下方可查看持有关系明细 | 按当前数据范围、款式和发行查询。触碰时段只作用于触碰相关统计。当前持有人按账户去重 |
| 最近用户动态 | 有效触碰、认领、首次交付、换新与转售等事件的最近记录 | 当前数据范围。位于工作台底部，可进入完整业务动态 |

一次有效触碰是服务器通过完整验证、接受新读数并成功保存的事件。后台配置核验、失败、重放和刷新资料均排除。事件按发生时的数字物品与芯片记录，跨历代芯片按稳定数字身份汇总。匿名触碰按事件记录。手机页载入、认领和首次成交分别由各自的业务事实记录。

默认展示「售出后的有效触碰」及近 7 日，售出后按首次成交时间逐次比较。全生命周期也纳入售前的有效触碰。近 7/30 日含当天，按北京时间自然日计算并展示本次截至时间。应用筛选后同步更新次数、覆盖、重复和趋势。点击次数进入逐次动态，点击件数进入逐件明细，均携带已生效条件和截点。工作台卡片优先服务可直接办理或核查的入口，芯片配置等技术状态在芯片管理查阅。

工作台、物品详情和全部动态统一使用可点击的物品编号。进入物品详情后可回到来源列表并保留筛选；在当前详情点击本件编号时定位到详情顶部。有效触碰显示触碰时登录账户的公开 UID，点击复用账户卡。未登录的新触碰显示「匿名访客」，历史记录无法核对账户时显示「身份未记录」。识别触碰账户不改变物品持有关系。

## 5. 桌面页面与反馈

正式后台使用 Umi Max、Ant Design Pro 和 AntD 6。当前路由提供工作台、订单管理、数字物品、实体物品、款式与发行、芯片管理、用户管理和系统管理八个菜单入口，具体职责见[数字档案的信息架构](digital-catalog.md#architecture)。系统管理中保留设置、通行密钥、测试数据与运行检查；不再以旧四菜单清单判断功能是否可用。

物品、订单、芯片等详情使用各自的站内路由；编辑及受控动作按[设计规范](../ADMIN_UI_GUIDELINES.md)选择弹窗、侧栏或独立页面。不要把“详情必须抽屉、编辑必须弹窗”作为通用限制。页面显示服务端实际可执行动作，不提供未实现的通用改号、身份纠错或归档恢复入口。

列表使用服务端筛选、总数和分页，关联跳转按确切记录保留来源与查询条件。普通字段保存、发行确认、装配、启停、发码、密钥核验和接续各自表达结果，不隐式合并为一次提交。请求失败不填0，不用演示数量填充真实页面；登录、受控查看及安全检查不因组件迁移取消。

采用官方布局的页面滚动，表格按需横向滚动、弹窗内部滚动，矮窗口能到达全部操作；弹窗保留焦点、Escape及关闭确认，处理中不能离开或重复提交。加载、成功、空结果和失败分开；失效会话隐藏管理资料，刷新通过会话恢复，不存本地登录秘密。芯片普通未保存输入提供保存后继续/放弃继续/取消；绑定/密钥保持原受控确认，不能由离开弹窗自动提交危险动作。

操作与回归从[桌面管理端手册](../ADMIN_DESKTOP.md)按当前功能进入。历史五组只保留原验收范围；新版订单、工作台、操作审计及同类交互按手册对应章节验证。框架与依赖版本由实际清单及技术文档维护。


## 6. 验收入口与变更边界

当前功能的通过条件随本规范、数字档案及用户H5分别定义，不另建一套用户故事验收。实际操作见[物品维护](../ITEM_DRAFTS.md)、[桌面管理端](../ADMIN_DESKTOP.md)；是否已验收、合并或部署以任务和历史证据为准。款式、装配及接续按[数字档案规范](digital-catalog.md)，未定专用纠错按[政策提案](../proposals/admin-make-rebuild.md)，不再依靠旧A/B/C/D代号判断权限。

## 7. 验收数据与业务范围

后台列表及工作台默认业务数据；只在系统管理→设置提供全局“开启测试数据”开关，开启后统一使用活动验收批次。普通页面不再提供测试/全部/批次筛选，后端范围参数仅供受控工具和兼容。测试来源固定继承，与生产验证开关分开；关闭开关不能把测试数据变成业务数据。统计、趋势、明细及账户持有应用相同范围。测试批次整批清理只删除本批拥有对象，外部引用阻断并回滚，审计保留；原单条删除仍保留另一侧。测试数据写入仅限明确测试目标，合成状态不证明真实认领/配置/交付/触碰，真实卡单独取证。[操作验收](../ADMIN_DESKTOP.md#9-验收数据包与整批清理)与[接口](../../API_CONTRACT.md#114-验收批次与数据范围)分别维护细节。
