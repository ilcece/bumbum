# 物品草稿：创建与列表验收

目标：用现有管理员建立物品草稿并查询，为后续芯片绑定准备目标。本任务从main 48f039a开发，cece已确认分支测试无问题，草稿创建与列表已验收并合入main；不代表F1-02全部完成。

## 1. 准备与边界

日常使用main，保留配置、账号和数据；本地准备、启动和检查命令只看[本地运行](LOCAL_DEVELOPMENT.md)。先停止旧服务，在GitHub Desktop点击Fetch origin，选择main；如出现Pull origin则继续拉取。核对History最新提交与交付编号一致，再按本地运行手册启动并回归。已有未提交修改时先保留并核对，不强制覆盖。

本小步不改数据库结构、不运行迁移。已有库若连此前芯片升级都未完成，仍按原手册处理，不能重建数据库。香港库不在本次验证范围，不照本手册部署服务器。若运行检查因缺少登记来源字段而失败，先按[本地升级](LOCAL_DEVELOPMENT.md#8-已有测试库升级登记来源)处理；Windows备份目录无权限时见该手册第8.1节，不重建数据库。

物品编号代表一件物品，不能重复；款式编号可空、可重复。创建本身不自动编号、不填写资料或改变状态；本分支在第4节增加服装资料编辑与启停，不绑定芯片、不写卡。profile是接口返回属性，不是item表的列；创建不建立资料行。

## 2. 页面验收

启动后打开本地管理网页，用原账号登录，确认原芯片功能仍正常，并看到物品管理区域（本分支标题为“物品草稿与服装资料管理”）。创建表单与列表筛选独立，按下表操作。编号已存在时换一个未用的演示编号，不删除已有记录。

| 操作 | 应看到什么 |
|---|---|
| 选服装，填FASH-2026-990001，款式留空 | 成功卡片显示编号，列表为草稿、款式为“—” |
| 选饰品，填JEW-2026-990001，款式填DEMO-SKU | 创建饰品草稿 |
| 再建JEW-2026-990002，款式仍填DEMO-SKU | 可重复款式，物品编号不同 |
| 重复原物品编号，改填款式编号 | 提示已存在，没有覆盖原款式、时间或状态 |
| 饰品项目填FASH前缀 | 拒绝并说明格式，原输入保留 |
| 分别填小写前缀、3位年份、5位序号、全角或Unicode数字 | 拒绝并说明ASCII及位数要求 |
| 先设置列表筛选，再成功创建一条 | 成功卡片保留编号；创建表单保留项目、清空编号/款式；列表清筛选、回第一页且最新优先，不自动填关键词 |
| 按DEMO-SKU、物品编号片段查询 | 模糊匹配对应记录；编号与款式都可搜索 |
| 筛选启用、停用或归档 | 按实际数据显示；仅创建草稿而未操作状态时为空属于预期 |
| 点查看全部物品 | 清除筛选、回第一页，按记录ID倒序；共计数量与分页一致 |
| 刷新网页 | 登录仍有效时可查原记录；不依赖成功卡片保存数据 |
| 退出登录 | 隐藏物品和芯片区域 |

每页20条；不足一页时下一页不可点，不需要为测分页批量制造业务数据。分页、倒序、空页及审计均有独立临时MySQL自动检查。

测试示例数据保留是预期，不是脏数据故障；当前没有删除入口。年份0000和序号000000格式允许，但业务不推荐。不要求cece为边界测试在库存中创建全零编号。

## 3. 异常与技术检查

| 现象 | 怎样处理 |
|---|---|
| 登录失效 | 重新登录，先查询原编号确认结果 |
| 操作口令失效 | 刷新页面后重新提交，不自动重发创建请求 |
| 网络超时，结果不确定 | 先按原编号查询，查不到再决定是否重试；重复编号不会覆盖 |
| 创建成功后列表读取失败 | 成功卡片仍说明已创建；重新查询，不当作创建失败 |
| 数据库或审计保存失败 | 显示操作未完成；保留错误，不重建数据库 |

技术检查沿用[本地运行第4节](LOCAL_DEVELOPMENT.md#4-验证这一小步)的--auth-db专属临时MySQL，不连接现有业务库。验证item.create操作记录、目标物品ID、项目信息及IP指纹与创建一起提交；审计/提交失败回滚、两个管理员并发重复只新增一件、权限撤销和CSRF拒绝、输入边界及列表规则。cece的页面验收无需直接查数据库。

成功卡片只在浏览器内存中，刷新后消失是预期；已提交的数据仍在数据库。自动检查、浏览器操作和cece验收分别记录，不把技术检查通过当作cece已验收。


## 4. 服装资料与启停验收

本节验收feat/fashion-item-profile分支，基线main d3449d9，待cece确认、未合并、未部署。本地停止旧服务，在GitHub Desktop获取远端、切换该分支并核对交付提交后，沿用[本地运行](LOCAL_DEVELOPMENT.md)启动；配置和账号保留，无需改表或重建数据库。本节不授权香港部署或真实写卡。

| 验收组 | 操作及成功结果 |
|---|---|
| 首次保存 | 建一件未使用编号的服装草稿，点击编辑资料。名称外可空；保存提示成功，仍是草稿，列表显示名称。关闭重开、刷新后资料仍在。 |
| 修改与图片 | 填介绍/材质/洗护和可公开访问的HTTPS图片地址，每行一张；保存后顺序和换行保留。可选项清空后重开为空。合法但不能加载的图片提示失败，仍可保存；本次不上传。 |
| 边界与未保存 | 空名称、超长或javascript图片地址拒绝并保留输入；修改后关闭/查询/翻页提醒放弃，取消则继续编辑。网络/CSRF故障由AI技术验证覆盖，不要求cece改秘密或停数据库；若出现错误，记录编号、操作和页面提示。 |
| 启用停用 | 无资料不能启用；保存名称后独立启用，再停用、再启用，状态筛选正确。启用/停用时可改资料，保存不改状态。未保存时操作状态须先确认放弃或取消；资料和关联不因停用消失。 |
| 范围及回归 | 饰品无编辑入口；没有尺码表、归档或用户入口。编号/款式不被修改；原登录、草稿创建和芯片登记正常。退出登录隐藏管理资料。 |

失败时保留输入和提示，不删除测试物品。测试资料保留是预期。成功保存后若列表刷新失败，以独立成功提示为准，重新查询；超时结果未确认时重新读取核对，不自动重发。重新读取会替换输入，修改过时先确认。多人编辑以最后成功保存为准；本小步不提供冲突合并。

启用不代表芯片已绑定、写卡完成或防伪通过。本次尚无用户流程，不能声称停用后的用户凭证检查已验收。技术检查使用既有专属临时MySQL覆盖原子保存/审计、权限撤销、并发和不误改旧size_chart；cece无需查库。
