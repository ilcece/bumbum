# Codex 对话访问 BUMBUM 后台验证记录

验证日期为 2026-11-09（北京时间）。本记录用于后续迭代时复验，任务状态见 [TODO](../TODO.md#保留的后续需求)。

## 1. 为什么做这次验证

cece 想知道，**通过 AI 对话访问 BUMBUM 后台，在什么任务上能比逐页操作更省事**。例如只知道「想找棒球帽发行里已售出、但还没有有效触碰的物品」时，能否用一句话跨发行、数字物品和芯片查到结果，继续缩小范围，并打开确切记录。

另一个目标是，**离开电脑时，能否用手机上的 Codex 云端对话处理一些后台事项**。先验证电脑关机时仍能查询和追问，再决定哪些事项值得加入可核对、可确认的办理流程。

**本轮结论**是本机链路可用。对话相对固定菜单的效率优势，仍需用同一任务做对照。手机云端独立访问仍待验证。

## 3. 复验路径与已知问题

1. 在本机 Codex 说「验证 BUMBUM 测试站登录授权」。需要登录时，通过「打开 BUMBUM 测试站登录」在独立 Edge 的官方测试站页面完成验证，再查授权状态。
2. 说「查帽子发行售出后零触碰的物品」。核对当前验收批次、发行候选和统计口径。若只分析一条发行，选定它后说「只看待核验的」，确认仍在同一发行范围内。
3. 说「打开物品」并带上结果中的编号。核对独立 Edge 打开确切记录，拖动窗口验证内容自适应。

| 现象 | 处理与复验依据 |
|---|---|
| 搜「帽子」时没有匹配发行 | 验收款式名是「藏蓝六片棒球帽」，将匹配词改为「棒球帽」。找不到发行与找到发行后零条结果分别报告 |
| 重启后本机授权丢失 | 用合成会话复现 Edge 突然退出时会话未写入。修复版在登录成功后，用 Windows 当前用户加密保存测试站会话，并由测试站核验恢复结果 |
| 点详情链接又出现登录页 | Codex 内置浏览器和 MCP 独立 Edge 各自维护会话。要复用已有授权，使用「打开物品」工具 |
| 放大 Edge 时页面右侧和底部留白 | 可见窗口取消自动化的固定视口，实际验证页面宽高跟随窗口变化 |
| 网页的测试数据开关关闭 | 网页开关控制该标签页的显示范围。MCP 明确查询活动验收批次，两者可分别复验 |

本轮本机 MCP 试验版为 0.4.1。它通过本机进程访问测试站，记录采用验收物品编号及查询结果。测试站登录凭证由用户在站点登录页输入，复用材料保存在本机 Windows 用户的加密授权缓存中。

## 4. 下次迭代时先验证什么

- **对话能否省事。** 选一个真实且跨页面的管理任务，用固定菜单和对话分别做一遍。两边采用同一数据范围和成功条件，记录完成时间、切页次数、条件纠正次数，以及能否接着处理。若多条结果经常需要比较或筛选，再用可操作 UI 试验是否比文字结果更省事。
- **手机能否独立完成查询。** cece 决定启动这条验证线时，先确认所用 Codex 云端环境的接入方式。成功条件是电脑关机后，手机能用独立授权查询指定的测试数据、继续追问并返回可核对的结果。需要评估云端可访问的只读服务和独立授权。
- **手机能否办理少量事项。** 在独立查询通过后，再由 cece 选一个远程处理有实际价值的事项。用测试环境验收对象与影响预览、明确确认、执行结果和回执。
