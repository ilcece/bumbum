# 数字物品装配与 H5 验收清单

验收对象为交付说明指定版本的数字物品装配与H5能力；当前版本与收口状态见[TODO](../TODO.md)，人工反馈与自动检查分别按[CHANGELOG](../CHANGELOG.md)及PR证据核对，不把本清单视为全部细项已通过。先核对后台装配、权益与审计，再核对 H5 认领及预览，最后验证批次替换。自动回归、cece 人工验收、实际测试环境更新和真机验收分别记录。

| 组 | 在哪里操作 | 通过时看到什么 |
|---|---|---|
| 1. 实体装配与芯片 | 数字物品详情 → 安装芯片。登记一个实体编号，选中实物和待绑定芯片，勾选已安装。再试重复编号、同一实物或芯片及未核验启用。 | 详情显示实体编号、规格、芯片 UID 和「已安装 · 待核验」。重复占用及未核验启用被拦截。真实测试卡核验后可启用。配置前纠错可恢复为待安装，审计可追溯原组合。 |
| 2. 标准权益与操作审计 | 打开款式与发行，再打开数字物品「持有人与权益」。核对跨年换新和转售样本。在系统管理 → 操作审计按时间、操作人或物品筛选。 | 发行只展示发行规则，新数字物品显示换新和转售。按北京时间确认生效日计次；转售后的编号不变，实体和持有人切换，年度用量接续。审计能读出谁、何时、对哪个对象做了什么，详情可核对前后值。 |
| 3. H5 账户与首次认领 | 用已授权测试卡碰卡查看。在后台核对首次交付后发码，手机上验证手机号、输入交付码。试错误码、补发后的旧码、过期碰卡资格和另一账户再次认领。 | 可先看资料。补发使旧码失效，碰卡资格过期时提示重新碰卡并保留登录。成功后可从「我的数字物品」回访。两个账户同时提交时，仅一个持有关系成立；物品详情的当前持有人及持有人历史默认显示脱敏手机号。点「查看完整手机号」，关闭弹窗后只显示脱敏号码。到「系统管理 → 操作审计」核对操作人、时间、物品和账户 UID，号码仅出现在查看弹窗。 |
| 4. 后台手机预览 | 打开同一物品详情 → 预览手机页。切换访客、待认领、持有人，并尝试未装卡物品。 | 预览读取已保存资料，编号待核定照实显示，三个模拟视角可切换。关闭后仍在同一后台详情；触碰统计、发码和真实归属都以实际业务事件为准。 |
| 5. 旧模拟批次替换 | 系统管理 → 设置核对目标批次。先预览明确的旧批次及关联，再在已备份的测试目标运行替换。启用新版测试数据查看样本。 | 旧批次状态为已清理，新版样本可用。能找到带实体编号的待安装、待核验、棒球帽售出零触碰、待认领、跨年换新及转售继承用量等案例。存在外部关联时，预览列出冲突，实际替换被拦截。 |

## 测试准备和执行边界

- 从工作台打开「用户动态」，可按时间、发行、物品编号和事件类型查询。物品详情显示同口径的最近十条。有效触碰显示「匿名访客」，真实认领与完成的换新、转售交付显示账户 UUIDv4。点击 UID 打开账户资料，先看脱敏号码。主动查看完整号码后，在操作审计核对操作者、时间、账户或物品，审计仅存引用。

- 账户双标识需要 010 结构。杭州 test 已按确认范围备份并升级，本机用新的独立开发库按 schema 初始化。已有 007 的 `--assembly-h5` 命令只覆盖 008、009。
- 实卡重置后，在物品详情「持有人与权益」点「核对交付后补发」，填写交付核对依据、勾选确认并保存。手机重新碰卡、用已放行的手机号验证、输入新交付码，再到「我的数字物品」核对同一物品。后台「账户与持有」可核对对外 UUIDv4。
- 杭州 test 可用阿里云 `SendSms`，配置和启用见 [杭州部署手册](HANGZHOU_DEPLOYMENT.md#杭州-test-阿里云短信)。只向 cece 安全填写的唯一验收号码发送；真实短信与实卡各取证一次。实卡和真实手机号用测试站的「业务数据」范围，合成批次用于后台和预览验收。
- 用 `python -m core.acceptance_data --admin-username <测试管理员> --replace-batch <旧模拟批次ID>` 预览。仅在确定是目标测试槽、旧批次 `acceptance-v2`、已完成 SQL 和媒体备份、预览无冲突后，追加 `--apply --backup-confirmed`。清理与生成同一事务提交，结果包含被替换批次、新批次和样本清单。失败后先读取实际批次状态和冲突，再决定重试或按备份恢复。
- 模拟样本的配置、归属和交付是合成数据。实际 NFC 验签和短信发送用已授权的测试卡和号码另验。H5 首版产品要求见 [H5 规格](proposals/digital-item-h5-mvp.md)，收费、争议处置和已核验装配的专用纠错规则按独立范围审核。
