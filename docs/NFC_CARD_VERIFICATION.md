# 真实卡核验：先收集信息，再确认测试操作

目的：确认手里的芯片与工具能否实现既定动态防伪方案，避免仅看到链接或扫描登记成功，就当成防伪通过。本页是信息准备与后续验证边界，不是写卡、换钥匙、解锁或恢复出厂的操作说明。当前进度只在[TODO](../TODO.md)维护。

历史扫描依据：先写固定文本cece再批量读卡，6枚卡登记及重扫去重通过；开启随机UID/SUN的卡出现4字节随机标识，不能在登记接口当永久UID。原证据见[技术说明第2.5节](../TECH_SPEC.md#25-手机扫描后自动登记)。设备、App版本和后续两枚424测试卡证据见技术附录第14.1节及CHANGELOG；扫描登记与SUN配置核验不能互相代替。

后续已取得A/B真实读数及工具证据，摘要见[技术附录第14.1节](IMPLEMENTATION_DETAILS.md#141-已有证据与复用来源)，实际进度仍看TODO。以下第1节保留为通用信息收集模板，不再要求cece重复提供已确认信息。NFC.cool文件入口展示权限配置，未展示完整SDM偏移；不要要求cece寻找不存在的详情入口。现阶段用固定工具配置与独立输出验签相互核对，不声称已读回全部底层参数，也不将导出CSV视为完整恢复备份。

## 1. cece先回复这一批信息

先提供已经知道的事实；不确定就写“不知道”。可只查看现有信息页面，不为获取答案点击写入、改密钥、改权限、锁定、格式化或恢复。无需为了回报而读取或复制秘密。

| 信息 | 请提供什么 | 为什么需要 |
|---|---|---|
| 芯片身份 | 购买说明或型号文字；是否明确NTAG424 DNA、TagTamper或其他型号；厂家/供应商公开规格链接若有 | 不同型号和供应商预配置可能影响命令与权限；商品写着“NFC卡”不够判断 |
| 设备及工具 | 手机型号、当前iOS版本、NFC.cool版本；当前订阅级别或相关功能是否可用。已有电脑读写器/其他App则补型号版本，没有就写没有 | 核对当前操作能力，不把旧设备测试结果当作新版能力，也不要求先采购设备 |
| 测试卡数量与用途 | 可单独用于试验的卡有几枚，是否允许后续另行确认后改写；能否预留A/B/C三枚并用贴纸区分 | 先可用一枚探索；完整对照按现有规范需要同项目两枚、另一项目一枚，不等于现在增加饰品用户体验 |
| 各卡当前状态 | 按A/B/C写：空白、固定文本、普通链接或SUN；随机UID开/关/未知；是否改过密钥、是否锁定/只读、是否有原配置记录。密钥只回复“未改/已改且自己有安全备份/已改但未知/不知道”，不提供值 | 防止把未知旧卡当可任意重写的空卡，或覆盖已登记实物的配置。未知不等于可使用出厂默认密钥 |
| 工具可见能力 | 现有页面是否能看到标签信息/版本、真实UID（只报能否看到7字节，不必贴UID）、文件设置、SDM/SUN设置、Key Settings/ChangeKey等入口；可只提供不含秘密的菜单名称 | 区分“能读NDEF文本”“能启用SUN”“能分别配置密钥与权限”。看到入口不等于具备权限或已执行成功 |

回复模板（可直接复制，未知留未知）：

```text
芯片型号／购买说明：
手机型号／iOS：
NFC.cool版本／订阅或功能情况：
其他已有读写工具（无则写无）：
可预留测试卡数量：
A卡：内容类型／随机UID状态／是否改密钥及自己有无备份／锁定情况
B卡：同上
C卡：同上
现有可见的标签信息、SDM和密钥设置入口：
```

不要发送密钥、项目根密钥、全局K1、存储密钥、密码、二维码秘密、认证凭证或可直接访问的完整动态SUN链接。若页面把设置与秘密混在一起，只转述非秘密字段名及选项；不必发整页截图。UID不作为口令，但也不需要为第一轮信息收集公开完整业务卡编号。

## 2. 收到回复后，AI负责核对什么

下面是技术核验清单，供AI查资料和制定单卡测试方案；cece不需要先自行理解或计算这些参数。现阶段保持“待核验”，不预填推测值。

| 核验方向 | 需要固定的内容 | 证据与cece配合 |
|---|---|---|
| 型号和命令支持 | 实际芯片版本、标签类型、支持的NXP命令；供应商是否预配置/锁定 | AI核对型号对应官方资料；cece反馈公开型号或工具已有只读信息 |
| 密钥与权限 | K0管理、全局同版本K1、独立K2的既定职责是否能由实际权限实现；读取、写文件、改设置及换钥匙分别需要什么权限 | AI查具体版本文档；cece只确认有无所需权限和安全保存的原凭证，不在聊天提供密钥 |
| SDM文件设置 | 文件编号、通讯模式、读取/写入/修改权限；SDMMetaRead/SDMFileRead实际映射、UID与计数器镜像及随机UID选项 | 先用公开资料和去秘密的现有设置核对，不靠字段名称猜权限，不先改卡 |
| 动态链接和字节位置 | `/tap?picc_data=...&cmac=...`的完整NDEF编码、参数长度、大小写、各镜像位置、MAC输入起点/输出位置、文件容量及计数器限制 | AI根据目标工具实际编码计算并逐字节核验，不能用界面中文字数估算位置；只用占位或合成样例讨论 |
| 加密计算 | K0/K2/K3/K4派生算法及输入编码；PICC解密、会话密钥、CMAC输入与截断、UID/计数器字节序 | AI选成熟库、核对官方资料及已知答案测试；不自行设计协议或把任意解密结果当真实UID |
| 工具实际能力 | 能否逐项设置上述权限/位置、分别写入密钥、读取配置、验证结果和保留安全操作记录 | 先确认工具能力；缺功能时说明具体缺项和替代工具成本，再对齐，不先采购或切换方案 |
| 失败与恢复前提 | 哪些步骤可能使卡不可再修改，失败时凭什么恢复；原配置/凭证是否安全保存，卡片能否仅用于试验 | AI给出每步成功、失败与停止条件；未知原密钥或锁定状态先停止改写，不承诺恢复出厂能解决 |
| 配置完成证据 | 既有provisioned_at如何与配置版本、核对结果及操作记录对应；怎样区分已生成密钥、写卡完成和验证通过 | 先定义最小记录办法，再判断现有表是否够用；如需改表，单独对齐迁移，不提前新增字段 |
| 测试访问环境 | 手机可访问的HTTPS测试地址、用户路径与管理入口隔离、运行配置与测试库归属 | AI设计本地/测试环境验证；实际服务器检查和部署另行授权，不假设可直连ECS |

已确认的方案不重新开放选择：同版本跨项目共享K1、每枚芯片独立K2；登记接口不临时解密随机UID/SUN卡。具体冲突若被官方资料或实卡证据证实，再说明影响与备选方案。资料来源、版本、日期和结果记入现有技术附录/CHANGELOG，不新建另一套状态记录。

## 3. 后续实测怎样分步通过

收到第1节信息后，AI先给固定参数、工具步骤、影响范围、必要备份和停止/恢复条件，cece确认后才开始真实卡操作。本页不构成对改写、换钥匙或服务器部署的授权。

1. **一枚卡探索**：只用明确可改写的专用测试卡；按批准步骤配置，核对读出的加密数据、真实身份及计数器，形成正确答案对照。能打开网址或读到14位十六进制不算通过。
2. **三枚卡对照**：同项目A/B、另一项目C；验证同版本K1一致、不同卡K2独立，项目与物品匹配。只记录“相同/不同”和安全存放位置，不公开密钥。
3. **正常与失败核验**：真实读数通过；改动防伪码、错误密钥、旧链接、停用和缺少配置不能取得新的有效授权。系统故障显示故障，不显示为假货。
4. **可重复和记录**：再次触碰、刷新旧链接、重启服务后结果符合规则；数据库记录、配置完成证据和人工操作对应。不可用配置不标成写卡完成。

若工具能力、权限或测试卡数量不足，明确哪些已验证、哪些受阻；可以继续绑定和页面联调，不把合成测试计为真实卡验收。

## 4. 密钥与配置联合验收

目的：与芯片绑定一起验收服务器密钥流程，区分已生成、人工配卡、配置已核验。使用交付说明指定的同一任务分支；先按[芯片手册第4节](CHIP_REGISTRATION.md#4-首次绑定物品验收)确认关联，再按[本地运行第10节](LOCAL_DEVELOPMENT.md#10-首次准备本机密钥功能)首次准备空配置并重启后端。密钥流程自身不改表；使用触碰验证版本时先按[本地第11节](LOCAL_DEVELOPMENT.md#11-已有测试库升级触碰记录及后端验收)检查日志升级。本节只检查桌面管理及配置核验，不依赖用户手机资料页；手机页另按第6节验收。

**已改过密钥的测试卡不能按出厂空卡处理。**旧配置的历史样本不能用于确认新生成的目标密钥；不要为了页面验收先覆盖卡片。第三/五组涉及换实卡密钥和权限，须先确认专用卡归属、旧凭证安全备份、逐步操作及停止条件，再确认实际改卡步骤。方案批准或代码推送不代替真实操作授权。卡片以UID核对，A/B和批次名称只是标签，不能用早期会话字母推断本次操作对象；当前核验进度见TODO。

**NFC.cool密钥输入必须选择“十六进制”，不要选择“口令”。**后台提供的是16字节密钥，显示为32个十六进制字符，逐槽位原样填写；口令方式会转换为另一组值，即使输入文字相同也不匹配。换钥认证使用卡上当前有效密钥，新密钥才填写后台目标值，二者不能混用；K0最后处理。若此前误用口令，先保留App仍可用的当前凭证和安全备份，再对齐修正步骤，不删凭证、不猜默认值。

| 验收组 | 操作与成功结果 | 失败或未具备条件时 |
|---|---|---|
| 1. 生成及保护 | 登录→芯片管理；未绑定行没有密钥入口。选择已正确绑定的专用样本→密钥与配置→生成密钥。提示已加密保存、尚未写入卡片；列表为已生成／未核验。刷新再打开仍有记录，不能再次生成覆盖 | 提示配置未就绪时检查第10节是否首次准备及重启；反馈固定错误和错误编号，不发.env或密钥。后台并发、未分配、密文非明文由隔离测试覆盖，不要求cece查库 |
| 2. 受控查看与清理 | 未勾全局K1确认时不能查看；勾选后主动查看五项密钥。可选中某项手动复制到已确认工具；隐藏、关闭或退出后页面不保留，重开需重新确认查看并记录审计。生成/查看不是写卡成功 | 不截图可见秘密；截图反馈前先隐藏。401回登录，403提示刷新且不自动重发；审计存在与失败保护由技术测试覆盖 |
| 3. 首枚卡目标配置及确认 | 仅在实卡步骤确认后，先一枚、再另一枚，保留对照并核对实际UID。用十六进制输入目标密钥，固定/tap、加密SUN/Key 1/Key 2，检查K0认证及文件权限；不要把所有槽位设成同一个值。系统触碰通知取得两条新链接，按先后粘贴，勾选已人工检查，点确认配置核验。成功后列表已核验、链接输入清空，物品原状态保留 | 不确定当前密钥、误用口令模式、某步失败或工具不能证明新K0认证时停止，不勾人工确认，不猜默认值、不盲重跑CSV。系统不会替cece写卡、验证K3/K4或读取全部硬件权限 |
| 4. 错误与结果恢复 | 未填两条链接或未人工确认不能提交。错误/其他芯片读数拒绝，不产生完成记录。超时/503显示未确认，先点查询实际记录；已生成或已核验结果会显示，不自动重发。已核验不能再次确认重置计数 | 无须人为断网或攻击真实卡；回执丢失、数据库故障、重复提交、错误/旧读数由技术测试注入覆盖。人工操作遇到时反馈UID、操作及错误编号，先隐藏秘密和完整链接 |
| 5. 双卡对照及回归 | 首枚通过后按确认步骤配置另一枚，核对同版本K1相同、K2不同，并各取得正确读数。原绑定关系、物品资料/状态、首次来源和批次保留；登录、登记、列表正常 | 只有两枚424时不宣称跨项目三卡实测通过。用户防重放/短时凭证按第5节单独验收；手机资料页按第6节独立验收，不能用后台确认替代 |

NFC.cool当前可见设置：固定URL、加密/明文SUN、元数据/文件密钥槽位；文件入口只提供read/write/readwrite/change权限，未显示底层偏移。目标CC/NDEF为free读取、其他权限K0，专有文件四项权限K0；不改随机UID、LRP、永久性选项或失败次数限制。具体受控改卡步骤先核对工具当前行为，K0最后更换并认证；这段是核对目标，不是允许立即换钥。导出CSV可能缺项或保留旧地址，必须结合实际系统触碰输出核验，不宣称可完整恢复。

绑定、生成及核验样例会保留，没有删除、解绑、换绑、覆盖密钥或重配入口。未知提交结果先查询，不用清库或恢复旧库解决；若根密钥/K1丢失或变化，停止并找回原配置，不运行首次初始化代替恢复。服务端代码回退不会恢复已经写入的卡片，也不能丢弃已保存的计数基线。构建和纯软件检查、cece页面验收、目标密钥实卡通过及云部署分别记录。


## 5. 触碰验证后端验收

本节只验证接口和五分钟查看凭证，不代替手机页面或工作台统计验收。准备：使用交付分支，按[本地运行第11节](LOCAL_DEVELOPMENT.md#11-已有测试库升级触碰记录及后端验收)检查升级，再启动后端；保留现有密钥、两卡配置和资料，不重新生成或配卡。输入与请求命令只在本地手册维护，避免复制两套。每组失败反馈操作、摘要reason或error_id，不分享密钥、完整链接或token。

| 验收组 | 操作与预期 | 证据边界 |
|---|---|---|
| 1. 正确对应 | 核对专用卡UID、已绑定物品和已核验标记；启用有资料的服装物品，另取系统触碰新链接，使用本地手册输入段。verified=True，项目/物品编号对应，许可300秒 | 配置确认旧链接不是新读数；两个项目自动测试覆盖，饰品实卡仍另取证 |
| 2. 重复与再次触碰 | 同一请求主动重发一次返回replay_suspect；重新真实触碰再输入新链接可成功。两张服装卡分别对应自己的物品 | 并发只一个成功、乱序和故障由技术测试覆盖，不要求人工攻击卡片 |
| 3. 资料许可 | 首次成功后五分钟内，按手册GET查看，名称/物品对应；重复GET仍可读，不增加有效次数 | 跨物品、已消耗、严格过期边界由自动测试覆盖，无需人工等待五分钟 |
| 4. 不可用状态 | 在管理页暂时停用自己这件测试服装，再取新链接验证，返回disabled；原许可也不能查看。之后恢复启用，再次真实触碰可成功 | 原资料和计数保留；不要求通过改库模拟芯片停用，后续启停入口独立交付 |
| 5. 保留与回归 | 按原方式停止/重启本机项目；原账号、绑定/配置/资料仍在，使用过的链接仍不能换新凭证；登记和列表可用 | 数据库每阶段失败、回执丢失、多进程限流、事件去重及隐私由技术测试覆盖。公网和手机页未部署不算通过 |

有效次数仅指服务器接受的新验证事件；上述正常验收会产生真实测试记录，后台配置核验、失败和重复GET不计入。有效触碰次数可在对应环境的工作台核对，不要求cece直接查库；统计操作见[桌面管理端第7节](ADMIN_DESKTOP.md#7-工作台有效触碰统计)。两枚服装实卡通过也不能记作饰品实卡通过。

## 6. 手机服装资料页与自动更新验收

使用交付分支及原专用卡，不需重新配卡或换密钥。本机先按[本地第12节](LOCAL_DEVELOPMENT.md#12-已有测试库升级及手机资料页本机验收)完成004及电脑页面准备；真正手机移动网络测试须先按[云测试第10节](CLOUD_TEST_DEPLOYMENT.md#10-手机用户站点公开部署与验收)授权部署并核对云端数据。两套结果分开记录，不把电脑窄窗口当作iOS/Android实卡通过。
