# 数字服装 NFC 项目需求与验收文档

版本：V0.2　日期：2026年10月13日
面向：无开发经验的产品经理与执行编码的 Codex
状态：手机、数据库引擎与 ECS 基础配置已确认；可开始本地开发，云端连通与实体芯片尚待验证

## 1 项目目标与第一版决策

用现有两个 NTAG424 DNA 标签验证完整流程：管理员录入两件服装和两个芯片 → 每个芯片写入独立入口网址 → 手机触碰标签并按系统提示打开网页 → 服务器查询当前绑定 → 展示对应服装详情 → 管理员修改资料、所有者或芯片绑定 → 再次触碰看到最新结果。

第一版采用“固定 NFC 入口网址 + 服务器动态映射”。这里的动态跳转指服务器根据最新数据库记录选择服装页面，不要求芯片每次生成不同网址。页面展示的是一件实体服装实例，款式相同的两件衣服仍应有两个实例编号。

所有者手机号由管理员手工记录，仅表示后台登记关系，不证明该手机号本人已同意、拥有服装或完成身份认证。手机触碰不改变所有者。公开页面默认不展示手机号，包括脱敏手机号；显示“已登记所有者”或“未登记所有者”。

第一版不实现付款、交易、NFT、区块链、用户注册、短信验证、用户自助认领、转让审批、复杂多角色权限、SUN 验真和原生手机 App。后台仅一个管理员角色，手机端是可公开访问的网页。

### 1.1 完成标准

1. 两个真实标签分别打开服装 A 与 B，不串号。
2. 同一个标签 URL 不变，修改资料后重新打开能看到新资料。
3. 同一个标签 URL 不变，将绑定从 A 改为 B 后重新触碰打开 B。
4. 管理员修改所有者手机号可保存并留痕，公开响应中不存在完整手机号。
5. 停用、解绑、下架与未知标签均有明确页面，不出现内部报错。
6. 未登录访问管理接口不能读写数据。
7. 重启服务后服装、标签与所有者记录仍存在。

## 3 NFC 工作方式与能力边界

### 3.1 固定入口的设计

示例标签网址：`https://你的子域名/t/随机入口码`。入口码由服务器使用密码学安全随机数生成，建议至少 128 位随机性，以 Base64URL 或十六进制表示，不使用顺序编号、手机号或 UID 作为公开地址。

普通读写工具将网址写成 NDEF URI 记录。浏览器打开该 URL 后，服务器用入口码找到标签记录，再找到对应服装。UID 在管理员登记标签时录入并保存，作为硬件资产信息；V0.1 不声称网页已读取或验证真实 UID。浏览器收到的只是网址，不能因后台登记了 UID 就判定此次访问来自原标签。

后台必须展示完整可复制入口 URL 和“未写入／已人工核对”记录。后台生成 URL 不等于已经把 URL 写进标签，写入需要实际手机或 NFC 读写设备。

### 3.2 硬件事实与产品限制

NXP 数据表将 NTAG424 DNA 描述为支持 NDEF 的 Type 4 标签，并支持 SUN 与 SDM 安全能力；NDEF 文件容量为 256 字节。[S1] URL 写入前应按真实 NDEF 编码计算字节数及开销，不以中文字符数判断容量。

普通入口 URL 可以被复制，因此第一版页面只能称“服装信息”，不能显示“正品认证成功”。启用 SUN／SDM 需要标签配置、密钥管理和服务器校验，不能靠拼接 UID 参数实现。[S1][S2]

本次测试手机为 iPhone 14，按“点亮并解锁手机 → 手机顶部靠近标签 → 点击系统 NFC 通知 → 浏览器打开服装页”进行人工验证。标签需正确写入 NDEF URI；读取网页不要求安装项目 App，写入需使用兼容读写工具。具体手机可能先出现系统通知，用户点击后才打开浏览器；验收定义为“识别标签后能按系统提示进入页面”，不承诺每台手机触碰即无交互打开。手机兼容性与写入工具以实际设备测试为准。

芯片 UID 与部分读卡场景下的随机 ID 应区分。实际 UID 的来源、格式和随机 ID 配置需核对，不把变化的读卡 ID 当成实体标签 UID。V0.1 录入真实 7 字节 UID，以 14 位十六进制标准格式保存。[S1]

## 4 用户场景与页面需求

### 4.1 公开服装详情页

路径：`/g/:garmentId`。移动端优先，支持 360px 宽屏幕，无横向滚动。

展示：服装名称、实例编号、主图、品牌、款式编号、颜色、尺码、材质、简介、养护说明、登记状态。隐藏空的可选字段；图片加载失败展示占位图；简介按纯文本渲染，不能执行管理员输入的 HTML。首屏以名称与图片为主，长说明置于下方。

所有者仅展示登记状态。页面不提供所有者修改按钮，不返回真实 UID、入口码、管理员信息、手机号或内部审计信息。公开服装编号与后台技术 ID 可不同，但都不能作为访问权限凭证。

### 4.2 管理员登录

路径：`/admin/login`。单管理员账号由初始化命令创建，密码安全散列存储，无默认线上密码。提供登录、退出；会话闲置 30 分钟过期。失败提示统一为“账号或密码错误”。

管理页和接口均检查会话，不能仅隐藏按钮。登录失败需限速，初始规则为每 IP 与账号组合 15 分钟内最多 5 次失败；返回明确的稍后重试信息。会话 Cookie 使用 HttpOnly、线上 Secure、SameSite；写接口进行 CSRF 防护或严格来源校验。

### 4.3 服装列表与编辑

路径：`/admin/garments`，`/admin/garments/new`，`/admin/garments/:id`。

列表：名称、实例编号、公开状态、所有者手机号的脱敏值、绑定标签状态、更新时间；按名称／实例编号搜索，默认按更新时间倒序，默认每页 20 条。详情页仅管理员可查看完整手机号。

创建与编辑：必填名称及唯一实例编号；其余服装字段可选。保存有加载状态，重复点击不能重复创建；校验错误保留已输入内容，成功返回可见提示。草稿默认不公开；管理员选择“发布”后公共详情可访问；可以下架，保留数据。

状态：DRAFT 草稿、PUBLISHED 已发布、ARCHIVED 已下架。第一版不提供永久删除，避免误删硬件绑定与变更记录。

### 4.4 标签管理

路径：`/admin/tags`，`/admin/tags/new`，`/admin/tags/:id`。

录入真实 UID、备注和可选服装绑定。输入 UID 去除空格、冒号及短横线后转换为大写，必须满足 14 位十六进制；重复 UID 返回 409，不能新建第二条。UID 首次录入后不直接改写：错误登记应停用旧记录并重新登记，防止误认芯片。

服务器生成唯一不可编辑入口码，创建后默认启用且“未人工核对写入”。支持复制完整 URL、绑定、解绑、停用、重新启用；停用不删除记录。允许将标签绑定到草稿，但后台提示“尚未公开，触碰不会显示详情”。

标签有效条件为启用、已绑定且目标服装已发布。停用或解绑必须立即影响下一次入口请求。

### 4.5 所有者修改

以服装实例为单位登记，不登记在标签上。更换标签不会自动转移或清空服装所有者；标签改绑另一件服装时展示新服装自己的登记状态。

后台独立“修改所有者”操作：旧手机号、新手机号、变更原因、最终确认。初版以中国大陆手机号为约定：允许空值表示未登记；非空值按 11 位、以 1 开头进行基础校验，不声称已验证号码真实归属。后续支持国际号码时应调整统一格式。

变更原因必填，1–200 字；修改成功后展示新状态并写审计；新旧相同不写重复变更。失败时手机号和审计记录均不能出现部分成功。公开页面的文字为“后台已登记”，不使用“已验证所有者”。

## 5 绑定规则与异常行为

一件服装最多绑定一个标签；一个标签最多绑定一件服装。已有目标绑定时返回冲突，不静默把另一个标签挤掉。需要替换时管理员先解绑原标签，再绑定新标签；操作需明确展示涉及的服装和 UID。将当前标签从 A 改到 B 可以在一次操作中完成，但 B 必须无其他标签。

绑定修改、所有者修改和审计写入分别通过数据库事务实现。并发编辑携带 version，版本过旧返回 409，提示刷新后重试，禁止无提示覆盖。

| 情况 | 入口响应 | 可见信息 |
| --- | --- | --- |
| 启用、已绑定、已发布 | 302 到站内服装地址 | 正常详情 |
| 未知入口码或格式错误 | 404 | 未找到服装信息 |
| 已停用 | 410 | 此服装标签已停用 |
| 已启用但未绑定 | 409 | 此标签尚未关联服装 |
| 目标为草稿或已下架 | 404 | 此服装信息暂不可用 |
| 数据库不可用 | 503 | 暂时无法加载，请稍后重试 |
| 修改时版本冲突 | 管理 API 409 | 信息已被更新，请刷新后重试 |

异常页必须是可读 HTML，手机可查看，不直接打印 JSON、数据库错误或堆栈。所有公开错误页面使用 no-store。

## 6 核心跳转与缓存规则

入口 `GET /t/:entryCode` 查询当前数据库映射，成功返回 302，Location 由服务器根据服装 ID 构造为站内相对路径 `/g/:id`。禁止从 query 参数取跳转目标；第一版不支持任意外链跳转。

入口响应、详情 HTML 和公共详情 API 都设置 `Cache-Control: no-store`；应用框架、反向代理及 CDN 不得缓存这些动态结果。禁止用 301 或 308 固化服装映射。发布修改后的新请求应读取已提交的数据。

已打开的网页不自动实时更新；重新触碰、刷新或重新打开网址后读取最新数据。数据库在两次请求之间被修改时，详情页再次校验公开状态，避免入口通过后仍显示已下架内容。

公网服务使用 HTTPS。后台绑定或登记行为不通过 GET 修改数据；公开触碰不触发所有权变更。

## 7 数据模型

建议 UUID 作为内部主键；数据库唯一约束为最终防线，不能只用前端检测。

| 表 | 核心字段 | 约束与用途 |
| --- | --- | --- |
| garments | id、item_code、name、brand、style_code、color、size、material、description、care_instructions、image_url、status、owner_phone、version、created_at、updated_at | item_code 唯一；owner_phone 可空；软下架 |
| tags | id、uid、entry_code、garment_id、enabled、write_verified_at、notes、version、created_at、updated_at | uid、entry_code 分别唯一；garment_id 可空且非空唯一；外键到 garments |
| admins | id、username、password_hash、created_at | username 唯一；不保存明文密码 |
| admin_sessions | id、admin_id、token_hash、expires_at、last_seen_at | 会话令牌散列；支持退出使会话失效 |
| audit_logs | id、admin_id、action、entity_type、entity_id、before_json、after_json、reason、request_id、created_at | 仅追加；与关键业务修改同事务 |

时间统一保存为 UTC，后台按 Asia/Shanghai 显示。审计内容仅包含所需变更字段；审计不存密码、会话令牌、芯片密钥。所有者审计含手机号时按敏感数据限制访问，列表展示脱敏，详情仅管理员可访问；调试日志不得打印完整手机号。第一版不记录公众 IP 与精确位置，也不将网页请求次数称为真实触碰次数。

字段长度：名称 1–100 字；实例编号 1–64 字；品牌／款式／颜色／尺码／材质各不超过 100 字；简介 2000 字；养护说明 1000 字；备注 500 字；图片 URL 不超过 2048 字。实例编号统一去首尾空白并采用明确大小写规则，推荐转大写。限制由前后端共同执行。

图片 URL 仅允许 HTTPS，拒绝 javascript、data 和 file 协议。V0.1 浏览器直接加载可信图片，服务器不主动抓取任意地址；避免引入图片代理与服务端请求风险。

## 8 接口契约

统一 JSON 错误：`{ "error": { "code": "TAG_ALREADY_BOUND", "message": "目标服装已绑定其他标签", "requestId": "..." } }`。客户端只显示可读信息，requestId 供排错。列表参数页码从 1 开始，pageSize 默认 20、最大 100。

| 方法与路径 | 输入或返回 | 权限 |
| --- | --- | --- |
| POST /api/admin/login | username、password；设置会话 Cookie | 未登录；限速 |
| POST /api/admin/logout | 撤销当前会话 | 管理员 |
| GET /api/admin/me | 当前管理员基本信息 | 管理员 |
| GET /api/admin/garments | q、page、pageSize；列表与总数 | 管理员 |
| POST /api/admin/garments | 服装字段，不含 owner_phone；返回 201 | 管理员 |
| GET /api/admin/garments/:id | 完整详情与 version | 管理员 |
| PATCH /api/admin/garments/:id | 可编辑服装字段、status、version；不能直接改所有者 | 管理员 |
| PATCH /api/admin/garments/:id/owner | phone 可空、reason、version；同时写审计 | 管理员 |
| GET /api/admin/tags | 分页标签列表 | 管理员 |
| POST /api/admin/tags | uid、notes、可选 garmentId；生成入口码 | 管理员 |
| GET /api/admin/tags/:id | 标签详情与完整入口 URL | 管理员 |
| PATCH /api/admin/tags/:id | enabled、notes、version | 管理员 |
| PUT /api/admin/tags/:id/binding | garmentId 或 null、reason、version | 管理员 |
| POST /api/admin/tags/:id/write-verification | 标记人工回读核对完成，不执行真实写卡 | 管理员 |
| GET /api/admin/audit-logs | 实体筛选与分页 | 管理员 |
| GET /api/public/garments/:id | 已发布服装的公开字段白名单 | 公开 |
| GET /t/:entryCode | 302 或异常 HTML | 公开 |
| GET /health | 最小健康状态，无凭证和内部配置 | 公开 |

创建成功 201；校验失败 400；无会话 401；无权限／来源校验失败 403；资源缺失 404；唯一性、绑定或版本冲突 409；限速 429；依赖不可用 503；未预期异常 500。API 和页面错误表达不同，但对应业务规则相同。

后台服装编辑接口拒绝 owner_phone 等未允许字段，防止绕开专用所有者流程。公开 API 必须显式构造字段白名单，不将 ORM 整条对象直接返回。

## 9 技术方案与部署条件

已确认部署基线为中国香港 ECS（Ubuntu 22.04 64 位、2 vCPU、4 GiB 内存）及同地域、同 VPC 的 MySQL 8.0。以下应用技术栈为实施建议：采用一个 TypeScript Web 项目，例如 Next.js 统一实现网页与服务端 API，使用成熟的数据库访问和迁移工具，使用成熟密码散列与会话组件；具体依赖版本由 Codex 实施时核对官方文档并锁定。不拆微服务，不引入消息队列、Redis 或独立手机应用。

数据库引擎已确认为 MySQL 8.0。本地使用隔离的 MySQL 8.0（可通过 Docker 启动），云端迁移与驱动也以 MySQL 8.0 为目标，不再将 PostgreSQL 或 SQLite 作为本版验收数据库。使用 InnoDB 支持事务、外键和唯一约束，字符集采用 utf8mb4；连接地址、账号与权限确认后再执行云端迁移。不能用本地测试通过就宣称阿里云连接通过。数据库连接只能发生在服务端，不能放到浏览器代码。

配置至少包括 DATABASE_URL、PUBLIC_BASE_URL、SESSION_SECRET 和管理员初始化参数；提供 .env.example，真实配置放在受保护环境。已部署且写入标签后不随意更换入口域名或路径。

推荐部署步骤：
1. 复核已确认的香港 ECS 与 MySQL 8.0，完成第 2.1 节的内网连通、账号和域名检查。
2. 部署测试环境，使用独立数据库或独立 schema，不能直接迁移未知生产数据。
3. 使用最小权限应用数据库账号与单独迁移账号；数据库不向全公网开放。
4. 配置 DNS、HTTPS、反向代理与动态路径缓存规则。
5. 执行迁移、创建管理员、导入虚拟服装 A/B。
6. 从手机移动网络访问 HTTPS 入口；本地 localhost 无法作为两台设备通用入口。
7. 软件验收通过后再写两个真实标签。

交付必须含启动与停止命令、迁移命令、管理员创建命令、测试命令、环境变量说明、构建步骤、备份与恢复说明。配置不完整时给出具体缺项，不假装已上线。上线前备份，恢复先在隔离数据库验证；停用标签是运营止损手段，不替代数据库恢复。

## 10 芯片初始化与写入操作

先将两个标签标记为 A、B，并保留供应商信息。若只有裸芯片，需要天线及合适封装才能用手机验证；不要提前认定两个芯片可直接触碰。

操作顺序：
1. 核对手机 NFC、标签类型、真实 UID、现有 NDEF、访问权限与是否开启随机 ID。记录当前配置。
2. 若读写权限或密钥未知，联系供应商确认；停止试改密钥和试锁定。
3. 在后台登记 A 的 UID，绑定服装 A，复制入口 URL。
4. 先在手机浏览器手动打开 URL，确认正确跳转与详情。
5. 使用已确认支持该标签当前配置的工具，写入单个 HTTPS NDEF URI 记录。不把用户手机号写进标签。
6. 回读已写入 NDEF，逐字核对 URL；系统能按提示进入网页后，在后台标记人工核对完成。
7. A 成功后再执行 B，避免同时改两个标签导致难以定位问题。
8. 在拟嵌入服装的位置重复读取；靠近金属配件、不同天线朝向可能影响效果，按实际结果调整位置。

V0.1 验证期间不锁死标签、不随意改 AES 密钥、不启用复杂 SDM 配置。当前文档未指定未经设备验证的写卡 App，也未执行任何真实标签操作。写入失败先记录错误码和工具版本，不继续连续改配置。

### 12.1 真实测试记录模板

每次记录：用例 ID／标签 A 或 B／手机型号／系统版本／时间／网络 Wi-Fi 或移动网络／标签位置／是否出现通知／是否点击通知／最终网址／页面服装编号／结果／截图编号／错误现象。

目标：每个已声明支持的实测设备，两标签各 10 次独立读取至少 9 次成功识别；已打开页面必须 100% 指向正确服装。识别失败与网页加载失败分开统计；错误服装属于阻断问题。该阈值是本项目验收建议，不是芯片厂商性能保证。

性能建议：在记录清楚的正常网络与测试部署条件下，从点击系统通知到首屏内容可见，10 次测试中至少 9 次不超过 3 秒。出现波动分别记录 DNS／TLS／服务器／图片耗时，不将网络问题直接归为芯片问题。

## 13 排错指南

| 现象 | 首先检查 |
| --- | --- |
| 手机完全没有反应 | 手机 NFC 能力与设置、是否裸芯片、天线、摆放、金属干扰、现有 NDEF |
| 出现通知但打不开 | URL 回读是否一致、HTTPS、DNS、手机移动网络能否手动访问 |
| 打开错误服装 | 后台入口码与标签对应、写入是否串卡、当前绑定、Location、缓存 |
| 修改后仍是旧信息 | 是否已保存成功、页面是否重新请求、no-store、框架与 CDN 缓存 |
| UID 读取值变化 | 是否 Random ID、读卡工具返回字段是否真实 UID |
| 标签无法写入 | 工具是否支持 Type 4、当前写权限、供应商密钥、错误码 |
| 云数据库连不上 | 引擎驱动、连接地址、端口、VPC／白名单、账号权限、TLS |
| 后台能改但日志没有 | 检查事务实现，不能将该状态视为成功 |

## 15 后续版本 SUN 验真

只有 V0.1 软件与实体触碰闭环通过后再实施。SDM 让标签读取时生成动态认证数据；服务器需要按配置校验，而不只检查参数存在。[S1][S2]

后续需求应单独明确：每标签密钥与安全保存、初始化工具、密钥备份、配置偏移、官方测试向量、CMAC 校验、读取计数器与重放策略、浏览器重复请求／预取处理、配置失败的恢复流程。页面刷新可能复用同一条 URL，不能简单把“计数器没增加”的所有请求都判为假货。

验真结论应表述为“标签认证通过”，不能自动推导衣服本体为真、标签未被移植，或当前扫码者是所有者。正式密钥不得进入前端、公开日志或仓库。两个现有标签中先选一个做试验，另一个保留可工作的 V0.1 流程。
