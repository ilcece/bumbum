# 手串 NFC 数字体验与权益探索

> 2026-11-02：cece已决定废弃旧祈愿 PRD，并授权整理复盘与文档调整。本文件记录方向重置及待验证问题，不是新 PRD，也不代表候选体验已获批准。当前任务、分支及下一步只维护在 [TODO](../TODO.md)。

## 1. 重新回答的问题

用户买到一条 BUMBUM 手串后，碰一碰应该获得什么，才能觉得这条手串更值得拥有、佩戴或长期保留？

先判断用户所得和实体联系，再决定打开什么页面。祈愿、情绪安放、数字作品、小世界、收藏、成长或产品权益都不能预先成为答案；不预设必须每天使用。当前只讨论普通手串使用者，不关联婚礼伴手礼；该机会具体需求另行讨论。

长期愿景仍见 [PRODUCT](../PRODUCT.md)。本次没有开发、部署、写芯片、改数据库或联系第三方的授权。

## 2. 两版体验与反馈证据

两版均为 Lovable 模拟 Demo。cece明确认为两版“没意思”；第二版仅获准独立模拟探索，没有据此修改正式 PRD。本文根据会话交接与反馈整理，不声称重新实测了两版 Demo，也不作为真实 NFC 或生产验收。

| 问题 | 第一版：每日一碰一签 | 第二版：表达—安放—回应—回望 | 产品判断 |
|---|---|---|---|
| 用户参与 | 默念、点击、领取通用福卡 | 选择四种意图，获得对应回应和可选小行动 | 动作主要决定领取或文案分类，没有形成用户在意的影响 |
| 仪式过程 | 触碰→默念→生成→收下 | 表达→安放→回应→回望 | 操作顺序完整，但尚未证明过程会产生感受 |
| 当次结果 | 一张祝福卡 | 更贴切、更温柔的回应 | 结果容易预料和替代，缺少值得期待的回报 |
| 再次使用 | 明天再领一张 | 回来标记“还在路上、有了变化、想留在这里” | 上次经历没有产生用户关心的后续，复访主要依靠规定或手动记账 |
| 长期积累 | 愿力与历史卡 | 心愿状态和回望记录 | 数据被保存不等于值得回看、珍藏或依恋 |
| 实体联系 | 手串打开领卡网页 | 手串打开情绪安放流程 | 更换成普通网页，主要内容仍成立，实体没有获得足够明确的新价值 |

第一版流程为模拟触碰→心中默念→点击→通用祝福卡→收下→愿力及历史。第二版四种意图为“愿有所成、愿心安定、愿人安好、记住此刻”。改善分类与文案没有证明核心吸引力改善。

根本问题是太早确定祈愿机制，再优化领取流程；用户收到什么被设计得很完整，为什么在意尚未成立。AI过早把方向带向情绪安放，未证明这符合使用者需求。不收集具体心愿时，系统不能声称理解并回应了具体心情。

以上是基于两版方案及cece反馈的诊断，不是广泛用户研究，不能推导所有用户都不需要数字祈愿。

## 3. 撤回的默认假设

- 手串有祝愿寓意，因此数字体验必须是祈愿或情绪安放。
- 用户需要每天触碰，日活是首要价值证明。
- 祝福文案和福卡足以成为核心回报。
- 愿力和历史数量增加，会自然形成收藏价值。
- 增加选择、温柔文案、动画或仪式步骤，就能补足参与感。
- 必须先建立持续使用机制，产品才有价值；低频但有实际价值的权益也应参与比较。

“这件信物有自己的小世界”“放灯后看它照亮哪里”等仅是会话提案，未获方向认可或开发授权，不能默认替代旧 PRD。

## 4. 旧规则如何处理

[旧 PRD](NFC_PRAYER_H5_PRD.md)原文保留，但整体退出当前需求依据；旧文档分支补充决定仅供追溯，不继续等待交互确认或合入。历史评审记录由本次方向重置替代，不改写过去发生的事实。

| 类别 | 规则 | 本轮处理 |
|---|---|---|
| 旧体验机制 | 每天一张、愿力累计、收下、回向、七天去重、节日优先、卡池与福卡分享 | 随旧方案退出当前需求，不机械迁入新体验 |
| 旧生成权限 | 当日认证、30分钟生成资格、跨日生成与重试口径 | 是福卡专属规则，不作为新业务默认权限；现有共用认证与接口不因文档调整改变 |
| 旧排期 | 11月底祈愿 MVP、12月种子反馈及依赖旧方案的后续成长 | 原交付内容失效；新范围、日期和验证方式待重评，不自动延期或承诺新日期 |
| 继续遵守的原则 | 芯片认证不等于所有权；最小化数据；保护认证秘密；真实反馈成功/失败；不承诺祈愿现实效果 | 保留，不因旧方案废弃而放宽 |
| 探索阶段沿用的边界 | 无个人账户、记录归信物、其他触碰者可能看到、不收集私密心愿 | 先尊重这些边界；若候选权益确需个人身份、私密记录或核销资格，单独说明必要性并评审，不默默改变 |

共用基础能力、服装主线及长期权益流转愿景保持原有范围与验收边界，不借本次重置新增工程工作。

## 5. 待比较的价值方向

下列是比较框架及举例，不是已选功能、已提供服务或对外权益承诺，也不是要把三类功能全部塞进首页。

| 候选价值 | 用户可能具体获得什么 | 必须验证什么 |
|---|---|---|
| 更了解、更会使用手串 | 对应款式的材料、工艺、设计来历、佩戴与养护内容 | 是否增加对实物的认可，普通说明页是否已足够，内容来源是否可信 |
| 值得经历或保留的内容 | 与手串有关、用户能实质参与的作品、故事或体验 | 内容本身是否吸引人，参与会改变什么，为什么与这条手串有关 |
| 明确的产品权益 | 实际能够交付的养护、换绳、维修服务，或有明确范围的后续数字作品 | 谁提供、次数与期限、成本、资格及核销边界；不能用“未来福利”代替交付 |

比较具体方案时，至少讲清：谁在什么情况下拿起手串、触碰后做什么、系统发生什么、用户获得什么、为什么不用普通网页替代，以及BUMBUM的内容或履约成本。

首次回报、再次触碰理由、长期保留价值分别验证，不能互相替代。若方案只适合低频使用，应按该使用周期判断价值，不强造每日任务。权益不得靠芯片认证直接推定所有权。

## 6. 下一步的判断标准

先用少量具体体验描述比较候选价值，不立即生成 Demo。用户应能说明“碰完得到了什么”“为何与这条手串有关”；只得到“页面漂亮”的反馈不足以证明成立。

方向经cece认可后，再做体验样例与验证，明确成本和最小范围，随后按既有流程整理新 PRD、交互及技术方案。未获相应授权前，不开发业务、不调整生产，也不以本探索说明代替新需求评审。
