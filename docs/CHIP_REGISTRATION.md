# 芯片管理：登记、查询、详情与批次维护

目标：管理员能找到确切芯片、核对关联物品，并维护批次；登记、绑定、密钥生成、实卡配置和真伪验证仍分别处理。当前任务版本及人工验收/合并状态看[TODO](../TODO.md)，历史证据看[CHANGELOG](../CHANGELOG.md)。手机扫描与当前云端入口按[杭州手册](HANGZHOU_DEPLOYMENT.md)核对，香港旧配置仅供历史追溯。

## 1. 更新并打开页面

日常使用main；任务分支只按交付说明验证。芯片查询/批次增量本身不额外改表；完整新版结构须按交付版本核对，旧库不得直接重建。图片配套备份恢复门槛及依赖准备见[本地运行第13节](LOCAL_DEVELOPMENT.md#13-a方案生效门槛组件冒烟与图片离线恢复)，常规启动方式仍只在[本地手册](LOCAL_DEVELOPMENT.md)维护。

使用交付版本启动后，打开[管理网页](http://localhost:5174)，用原账号和当前Authenticator验证码登录，从菜单进入“芯片管理”。页面使用Ant Design官方筛选、表格、表单和确认弹窗，Figma只作参考。保留原配置、账号及记录，不为验收重建现有数据库。

## 2. 按顺序验收

以下合成UID仅供隔离测试，不代表真实卡；真实库存UID从芯片读取。示例已存在就换未用样本，不删除原数据。下面保留旧登记/绑定页面的回归步骤；新版从物品详情“安装芯片”关联实体与芯片，按[数字物品与H5清单](DIGITAL_ITEM_ASSEMBLY_H5_ACCEPTANCE.md)执行。旧列表分页及绑定弹窗名称不作为新版定位依据。

| 验收组 | 操作 | 应看到什么及失败反馈 |
|---|---|---|
| 查询与刷新 | 关键词输入UID片段（可去冒号/忽略大小写）或关联物品编号/名称；按项目/状态查询，展开后组合批次、来源、关联/密钥/配置及北京时间日期；提交、翻页、刷新、重置 | 条件在服务端完整生效，显示关键词匹配来源；URL与刷新保留已提交条件，重置清空，非法日期明确提示。查询无结果与读取失败分开。反馈条件、预期/实际和错误编号即可 |
| 登记与继续 | 登记未用UID，如04:A2:7F:1B:5E:80:12，项目未分配、批次可空；登记并继续，再查看该芯片。用同UID重复登记不同批次；原项目非空时另选其他项目 | 成功后保留项目、清空UID/批次，提供确切新/原记录入口；原列表条件不改变，关闭后按原条件刷新。重复不覆盖，项目冲突明确拒绝；不能靠重复登记分配项目 |
| 详情、关联与返回 | 从筛选列表打开详情，点击关联物品编号，再返回；刷新详情或直接打开该记录地址 | 按真实ID读详情，不猜第一行；可回原芯片和原查询/页码。无关联/资料为空明确说明，目标失效提示原因，不跳其他记录 |
| 批次编辑与离开 | 对照详情进入编辑，修改/清空批次；保留未保存输入后点击菜单、关联或浏览器后退，分别取消、保存后继续、放弃继续 | 同一业务字段完整保留，只开放批次（去首尾空白、最多64字符）；UID/项目/关联/来源/状态及配置时间只读并解释。取消保留输入，保存后继续先确认保存，放弃不写入；提交中禁止重复和离开 |
| 故障与保护 | 正常保存后返回原筛选；自然出现超时则先核对保存结果，登录失效重新登录；绑定/密钥按下节及实卡手册回归 | 保存成功与后续刷新失败分开，原条件不再匹配时可调整查询。未知结果先按ID读，不自动重发；401隐藏资料，CSRF更新后手动再提交。故障、并发、审计回滚和合成读数由AI隔离测试，不要求人为停库或改真实卡 |

UID仅接受14位十六进制或7组冒号格式，统一大写冒号展示。项目可未分配，首次绑定按目标物品确定；批次登记时可空，维护时可清空。来源由实际登记入口确定，重复登记不改变来源。列表默认20条，可用官方分页切换；每次过滤后重新计数，超范围页回最后有效页，空结果为第1页。

## 3. 失败时先看什么

| 看到什么 | 下一步 |
|---|---|
| 登录或来源校验失败 | 按[登录排查](ADMIN_LOGIN.md#5-失败时先看什么)核对；本地用localhost:5174，不发配置或凭证 |
| 操作口令已更新 | 输入保留，核对后手动再提交，不自动重发 |
| 读取失败或记录不存在 | 重试读取或返回原查询，不用另一行替代 |
| 结果尚未确认 | 保存按芯片ID核对；登记按本次完整UID核对，不能直接解释为没有保存 |
| 数据库未就绪 | 按交付版本对应的[本地升级](LOCAL_DEVELOPMENT.md)处理；不删库或用空库schema覆盖旧库 |

自动检查使用专属临时MySQL，不操作已有测试或生产数据库。验收样本会保留；生产验证对象的直接删除须按已确认范围另行操作，不为重做验收删除现有记录。

## 4. 首次绑定物品验收

候选列表已排除任何芯片仍关联的物品，包括原芯片停用或丢失的情形；总数和分页按剩余结果计算，普通物品管理列表仍保留这些物品。验证时选一件已有绑定的物品编号，在绑定弹窗按该编号查询，应显示“没有符合条件的可绑定物品”；回到物品管理仍能查到原记录。未占用的归档物品仍显示但禁选，原有状态规则不变；查询后发生争抢仍在提交时拒绝。

目标：把已登记芯片与已创建物品建立关联，并能查到同一关系；不写卡、不生成密钥、不改变物品状态或所有权。先按交付说明选择任务分支及版本，按[本地运行](LOCAL_DEVELOPMENT.md)停止旧服务后启动；使用原配置和管理员，无需新增迁移或重建数据库。当前代码、自动检查和cece验收分别看TODO/CHANGELOG。

本步没有解绑或换绑入口，使用专用样例，绑定会保留。可按[物品手册](ITEM_DRAFTS.md)创建一个未用服装编号，如FASH-2026-890001，再登记一个未用的测试UID，如04:00:00:00:00:00:61，项目留空，批次注明“绑定验收样例”。这只是后台关系测试，不证明样例UID属于真实卡，不拿样例生成生产密钥或写真实卡。编号或UID已存在就换未用样例，不删除原记录。

| 验收组 | 操作位置与步骤 | 通过条件及失败反馈 |
|---|---|---|
| 正常绑定和保留 | 芯片管理找到样例UID → 查看详情 → 绑定物品 → 查询样例物品编号 → 单选 → 核对完整UID/项目/编号 → 勾选确认 → 确认绑定；随后刷新和重新登录 | 成功提示与芯片详情展示绑定结果，芯片为已绑定、项目按物品确定、关联编号正确；原物品仍为草稿。错误时记录实际提示和双方编号，不反复重试 |
| 项目和候选选择 | 用已分配服装项目的另一测试芯片打开弹窗；查询、翻页及改变条件；需要时以饰品草稿验证共用规则 | 已定项目不能切换到另一项目，未分配时可选择项目；无默认选中，换条件/页会清除选择，归档不可选。状态样例不足由技术检查覆盖，不手动改库造数据 |
| 重复与占用保护 | 已绑定记录的绑定入口不可用；另一枚待绑定芯片选择已被占用的物品；需要测试重复提交时，事先在两个窗口打开同一芯片和目标，先后确认 | 第二次请求提示已有绑定或目标已占用，不覆盖、不改来源/批次。不要用换绑或删除来恢复样例；先按UID查询真实关系 |
| 取消、提交与故障 | 选择后点关闭，先取消放弃、再确认放弃；再次打开重新选择。正常提交时观察控件；若自然出现超时/服务错误按提示查询此芯片 | 取消不保存；提交中禁用重复提交和离开；不自动重发。查询到原目标显示确认结果，异目标明确冲突，未查到不冒充未保存。故障模拟、登录失效及CSRF由AI隔离测试，cece不必停库或改密码制造故障 |
| 原有功能与边界 | 回归登录、芯片登记和重复登记、物品资料保存/启停；查看绑定成功后记录 | 原功能仍可用，绑定不改物品启停、不生成密钥或写卡、不表示用户认领；详情重读失败与保存成功分开提示。失败反馈页面、操作、预期/实际及错误编号即可，不发凭证或完整日志 |

查询物品支持编号或款式关键词，每页20条；物品名称为空显示“未填写”，不能按名称搜索。候选出现不等于保证可绑定，确认时仍会检查占用。看到“结果尚未确认”时先查询，不自动更换目标或提交补偿；当前未绑定也可能是原请求仍处理中，须重新核对后才能手动重试同一目标。重新查询仍失败就保留反馈，不清空库或擅自修复关系。

真实误绑定先停止该芯片的后续写卡并反馈双方编号，受限纠错另立任务；回退网页代码不能撤销已保存关联。并发、审计、回滚及升级后约束由AI在专属临时MySQL验证，不要求cece查库。
