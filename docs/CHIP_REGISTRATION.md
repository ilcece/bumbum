# 芯片登记：先跑通新增和查询

目标：登录后填写芯片UID，项目和批次可留空，保存后能在列表查到；重复登记不新增、不改原项目。UID就是芯片的固定编号。本小步不生成密钥、不写卡，也不判断芯片真伪；手机扫描另见[香港云测试](CLOUD_TEST_DEPLOYMENT.md)，物品绑定后续接入。

cece已完成本手册的芯片登记与列表验收，包括可空项目和重复提示，代码已合入main。以下步骤保留供以后回归；手动登记通过不代表NFC.cool手机扫描已接入。

## 1. 更新并打开页面

在GitHub Desktop选择 `main`，Fetch origin后有更新再点Pull origin。先停止旧后端和网页，保留原 `.env`、管理员账号及数据库。旧库按[本地升级](LOCAL_DEVELOPMENT.md#7-已有测试库升级允许芯片暂不分配项目)检查，确需升级时脚本先自动备份再改表；已升级的无需重做，没有新增依赖，不重建环境、账号或数据库。

main已包含Windows双击工具和芯片登记，无需再切回旧任务分支。旧库检查或升级完成后可双击“启动项目”，使用方法统一见本地运行说明第0节；停止仍用“停止项目”。

按 [本地运行说明第3节](LOCAL_DEVELOPMENT.md#3-启动后端和网页) 启动后端和网页，打开 [http://localhost:5174](http://localhost:5174)。不要改用127.0.0.1，管理端会检查网页来源。用已有账号和手机当前验证码登录，看到“芯片登记与列表”才开始验收。

## 2. 按顺序验收

以下编号仅用于本机演示；真实库存的UID应从芯片读取，不能自己编造。示例已存在时换一个演示编号，不清空数据库。

| 操作 | 应看到什么 |
|---|---|
| 用原账号登录，点“查看全部” | 原有记录还在，原项目与批次不变 |
| UID填 `04:A2:7F:1B:5E:80:12`，保持默认“暂不分配”，批次可留空，点登记 | 登记成功；列表显示项目“未分配”、状态“待绑定” |
| 重复登记该UID，改选“服装”，批次随意填 | 提示“该 UID 已登记，已显示原记录，无需重复登记”；仍是未分配，批次等原资料不变，不靠重复登记分配项目 |
| UID填 `04:A2:7F:1B:5E:80:10`，选“服装”，批次填 `DEMO-01`，点登记 | 提示登记成功；列表定位该UID，状态“待绑定”，批次DEMO-01 |
| 刷新网页 | 登录仍有效，记录仍在 |
| 用 `04a27f1b5e8010` 再登记，仍选“服装”，批次改成 `DEMO-02` | 提示已经登记；仍只有一条，批次保留DEMO-01 |
| 同一个服装UID改选“饰品”再登记 | 提示“该 UID 已登记，所属项目与本次选择不同。原记录未修改，请按 UID 查询。”；原记录不变 |
| 同一个服装UID改为“暂不分配”再登记 | 显示原记录，仍属于服装，不清空项目 |
| UID换成 `04:A2:7F:1B:5E:80:11`，选“饰品”，批次留空 | 成功新增另一条，批次显示“—” |
| 点“查看全部”，再分别筛选“未分配”、服装、饰品、待绑定状态、UID关键词 | 全部包含未分配记录；各筛选只显示符合条件的记录 |
| 退出登录 | 登记和列表区域隐藏，回到登录表单 |

UID允许14位十六进制连续文字，或7组冒号分隔的两位字符；大小写都接受，统一显示为冒号分隔的大写。UID格式不完整时应拒绝保存。批次可留空，填写时最长64个字符。

登记后会自动定位该UID，查看其他记录时点“查看全部”。列表每页20条，最新登记优先；数据不足20条时“下一页”不可点，属于正常情况。窄屏下可在表格内部横向滚动。

暂未分配项目的芯片，后续在绑定物品时按物品确定项目，不能直接生成密钥或写卡。当前物品绑定尚未实现，页面不提供分配项目按钮；重复登记只返回原记录。

## 3. 失败时先看什么

| 现象 | 下一步 |
|---|---|
| 登录后没有芯片登记区域 | 确认main已拉取最新代码，并重启后端和网页 |
| 提示必须来自允许的管理网页 | 使用localhost:5174，按 [登录排查](ADMIN_LOGIN.md#5-失败时先看什么) 核对来源配置 |
| 提示操作口令已更新 | 口令已重新读取，手动再点一次登记；页面不会自动重发写请求 |
| 提示登录失效 | 重新登录，再查询原UID确认结果 |
| 网络中断，无法确认登记结果 | 先按UID查询；相同UID重复登记不会覆盖旧记录 |
| 提示数据库暂时无法完成操作 | 按本地说明检查数据库；失败不会保留一半的登记或操作记录，不要删库重来 |
| 更新后数据库未就绪，或暂不分配时报错 | 先完成第1节链接的旧库升级，再重启服务；只更新schema文件不会升级已有库 |

数据库自动检查仍使用 [本地说明第4节](LOCAL_DEVELOPMENT.md#4-验证这一小步) 的 `--auth-db`，在独立临时数据库中同时检查认证和芯片管理，不写你的测试库。手动验收产生的演示记录会保留，当前没有物理删除入口。
