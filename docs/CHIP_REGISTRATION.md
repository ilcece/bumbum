# 芯片登记：先跑通新增和查询

目标：登录后填写芯片UID，项目和批次可留空，保存后能在列表查到；重复登记不新增、不改原项目。UID就是芯片的固定编号。本小步不生成密钥、不写卡，也不判断芯片真伪；手机扫描另见[香港云测试](CLOUD_TEST_DEPLOYMENT.md)，首次绑定步骤见第4节。

以下步骤用于芯片登记与列表回归；手机批量扫描操作见[香港云测试](CLOUD_TEST_DEPLOYMENT.md)，历史验收见[CHANGELOG](../CHANGELOG.md)。

当前main桌面管理端登录后先进入“芯片管理”，点击“登记芯片”打开表单，原字段和验收规则保留；其他页面操作见[管理端验收](ADMIN_DESKTOP.md)。

## 1. 更新并打开页面

日常使用main；验收新功能时在GitHub Desktop按交付说明选择任务分支，Fetch origin后有更新再点Pull origin，并核对交付版本。先停止旧后端和网页，保留原 `.env`、管理员账号及数据库。旧库按[本地升级](LOCAL_DEVELOPMENT.md#7-已有测试库升级允许芯片暂不分配项目)检查，确需升级时脚本先自动备份再改表；已升级的无需重做，没有新增依赖，不重建环境、账号或数据库。

main已包含Windows双击工具和芯片登记，无需再切回旧任务分支。旧库检查或升级完成后可双击“启动项目”，使用方法统一见本地运行说明第0节；停止仍用“停止项目”。

按 [本地运行说明第3节](LOCAL_DEVELOPMENT.md#3-启动后端和网页) 启动后端和网页，打开 [http://localhost:5174](http://localhost:5174)。不要改用127.0.0.1，管理端会检查网页来源。用已有账号和手机当前验证码登录，看到“芯片登记与列表”才开始验收。

已有本机库先按[来源升级](LOCAL_DEVELOPMENT.md#8-已有测试库升级登记来源)执行，香港按[云端升级](CLOUD_TEST_DEPLOYMENT.md#91-已有云测试库升级登记来源)。网页新增显示“网页手工”，手机新增显示“手机扫描”，历史无证据显示“历史未知”，跨入口重复不改首次来源；不保存或展示卡内内容和手机时间。

## 2. 按顺序验收

以下编号仅用于本机演示；真实库存的UID应从芯片读取，不能自己编造。示例已存在时换一个演示编号，不清空数据库。

| 操作 | 应看到什么 |
|---|---|
| 用原账号登录，点“查看全部” | 原有记录还在，原项目与批次不变 |
| UID填 `04:A2:7F:1B:5E:80:12`，保持默认“暂不分配”，批次可留空，点登记 | 登记成功；列表显示项目“未分配”、状态“待绑定” |
| 重复登记该UID，改选“服装”，批次随意填 | 提示“该 UID 已登记，已显示原记录，无需重复登记”；仍是未分配，批次等原资料不变，不靠重复登记分配项目 |
| UID填 `04:A2:7F:1B:5E:80:10`，选“服装”，批次填 `DEMO-01`，点登记 | 提示登记成功；列表定位该UID，状态“待绑定”，批次DEMO-01 |
| 刷新网页 | 登录仍有效，记录仍在 |
| 用 `04a27f1b5e8010` 再登记，仍选“服装”，批次改成 `DEMO-02` | 提示已经登记；仍只有一条，批次保留DEMO-01 |
| 同一个服装UID改选“饰品”再登记 | 提示“该 UID 已登记，所属项目与本次选择不同。原记录未修改，请按 UID 查询。”；原记录不变 |
| 同一个服装UID改为“暂不分配”再登记 | 显示原记录，仍属于服装，不清空项目 |
| UID换成 `04:A2:7F:1B:5E:80:11`，选“饰品”，批次留空 | 成功新增另一条，批次显示“—” |
| 点“查看全部”，再分别筛选“未分配”、服装、饰品、待绑定状态、UID关键词 | 全部包含未分配记录；各筛选只显示符合条件的记录 |
| 退出登录 | 登记和列表区域隐藏，回到登录表单 |

UID允许14位十六进制连续文字，或7组冒号分隔的两位字符；大小写都接受，统一显示为冒号分隔的大写。UID格式不完整时应拒绝保存。批次可留空，填写时最长64个字符。

登记后会自动定位该UID，查看其他记录时点“查看全部”。列表每页20条，最新登记优先；数据不足20条时“下一页”不可点，属于正常情况。窄屏下可在表格内部横向滚动。

暂未分配项目的芯片，后续在绑定物品时按物品确定项目，不能直接生成密钥或写卡。项目在首次绑定中确定，登记页面不提供独立分配项目按钮；重复登记只返回原记录。

## 3. 失败时先看什么

| 现象 | 下一步 |
|---|---|
| 登录后没有芯片登记区域 | 确认main已拉取最新代码，并重启后端和网页 |
| 提示必须来自允许的管理网页 | 使用localhost:5174，按 [登录排查](ADMIN_LOGIN.md#5-失败时先看什么) 核对来源配置 |
| 提示操作口令已更新 | 口令已重新读取，手动再点一次登记；页面不会自动重发写请求 |
| 提示登录失效 | 重新登录，再查询原UID确认结果 |
| 网络中断，无法确认登记结果 | 先按UID查询；相同UID重复登记不会覆盖旧记录 |
| 提示数据库暂时无法完成操作 | 按本地说明检查数据库；失败不会保留一半的登记或操作记录，不要删库重来 |
| 更新后数据库未就绪，或暂不分配时报错 | 先完成第1节链接的旧库升级，再重启服务；只更新schema文件不会升级已有库 |

数据库自动检查仍使用 [本地说明第4节](LOCAL_DEVELOPMENT.md#4-验证这一小步) 的 `--auth-db`，在独立临时数据库中同时检查认证和芯片管理，不写你的测试库。手动验收产生的演示记录会保留，当前没有物理删除入口。

## 4. 首次绑定物品验收

候选列表已排除任何芯片仍关联的物品，包括原芯片停用或丢失的情形；总数和分页按剩余结果计算，普通物品管理列表仍保留这些物品。验证时选一件已有绑定的物品编号，在绑定弹窗按该编号查询，应显示“没有符合条件的可绑定物品”；回到物品管理仍能查到原记录。未占用的归档物品仍显示但禁选，原有状态规则不变；查询后发生争抢仍在提交时拒绝。

目标：把已登记芯片与已创建物品建立关联，并能查到同一关系；不写卡、不生成密钥、不改变物品状态或所有权。先按交付说明选择任务分支及版本，按[本地运行](LOCAL_DEVELOPMENT.md)停止旧服务后启动；使用原配置和管理员，无需新增迁移或重建数据库。当前代码、自动检查和cece验收分别看TODO/CHANGELOG。

本步没有解绑或换绑入口，使用专用样例，绑定会保留。可按[物品手册](ITEM_DRAFTS.md)创建一个未用服装编号，如FASH-2026-890001，再登记一个未用的测试UID，如04:00:00:00:00:00:61，项目留空，批次注明“绑定验收样例”。这只是后台关系测试，不证明样例UID属于真实卡，不拿样例生成生产密钥或写真实卡。编号或UID已存在就换未用样例，不删除原记录。

| 验收组 | 操作位置与步骤 | 通过条件及失败反馈 |
|---|---|---|
| 正常绑定和保留 | 芯片管理找到样例UID → 绑定物品 → 查询样例物品编号 → 单选 → 核对完整UID/项目/编号 → 勾选确认 → 确认绑定；随后刷新和重新登录 | 成功提示含双方编号，列表定位此UID，芯片为已绑定、项目按物品确定、关联编号正确；原物品仍为草稿。错误时记录实际提示和双方编号，不反复重试 |
| 项目和候选选择 | 用已分配服装项目的另一测试芯片打开弹窗；查询、翻页及改变条件；需要时以饰品草稿验证共用规则 | 已定项目不能切换到另一项目，未分配时可选择项目；无默认选中，换条件/页会清除选择，归档不可选。状态样例不足由技术检查覆盖，不手动改库造数据 |
| 重复与占用保护 | 已绑定记录不再显示绑定入口；另一枚待绑定芯片选择已被占用的物品；需要测试重复提交时，事先在两个窗口打开同一芯片和目标，先后确认 | 第二次请求提示已有绑定或目标已占用，不覆盖、不改来源/批次。不要用换绑或删除来恢复样例；先按UID查询真实关系 |
| 取消、提交与故障 | 选择后点关闭，先取消放弃、再确认放弃；再次打开重新选择。正常提交时观察控件；若自然出现超时/服务错误按提示查询此芯片 | 取消不保存；提交中禁用重复提交和离开；不自动重发。查询到原目标显示确认结果，异目标明确冲突，未查到不冒充未保存。故障模拟、登录失效及CSRF由AI隔离测试，cece不必停库或改密码制造故障 |
| 原有功能与边界 | 回归登录、芯片登记和重复登记、物品资料保存/启停；查看绑定成功后记录 | 原功能仍可用，绑定不改物品启停、不生成密钥或写卡、不表示用户认领；列表刷新失败与保存成功分开提示。失败反馈页面、操作、预期/实际及错误编号即可，不发凭证或完整日志 |

查询物品支持编号或款式关键词，每页20条；物品名称为空显示“未填写”，不能按名称搜索。候选出现不等于保证可绑定，确认时仍会检查占用。看到“结果尚未确认”时先查询，不自动更换目标或提交补偿；当前未绑定也可能是原请求仍处理中，须重新核对后才能手动重试同一目标。重新查询仍失败就保留反馈，不清空库或擅自修复关系。

真实误绑定先停止该芯片的后续写卡并反馈双方编号，受限纠错另立任务；回退网页代码不能撤销已保存关联。并发、审计、回滚及升级后约束由AI在专属临时MySQL验证，不要求cece查库。
