# 项目优先级与过度工程化事故复盘

记录日期：2026-10-31（Asia/Shanghai）。本复盘记录一次明确的需求与优先级判断失误，供未来AI会话先读；不是新的工程项目或授权平台计划。现行长期规则以 [AGENTS](../AGENTS.md) 为准，当前任务只看 [TODO](../TODO.md)，实际阶段证据保留在 [CHANGELOG](../CHANGELOG.md)。

## 1. 最初要解决的问题

cece需要新ChatGPT会话主动读取GitHub项目文件，与Codex恢复统一项目基线，知道当前在做什么、哪些已验收/合并/部署、下一步谁负责。目的在于减少重复交接，继续BUMBUM的产品和商业工作。

BUMBUM是一人创业项目。cece是唯一负责人，ChatGPT承担产品经理、架构顾问、项目协调和质量审查，Codex承担工程实现与测试。有限的时间、注意力和创业资金应优先用于产品里程碑与客户验证。

## 2. 实际怎样偏离

基线读取逐步扩展到分支创建/删除、PR创建/关闭/合并、Actions触发/重跑、独立任务授权、持久化审计和未知操作恢复。随后又围绕授权签发、客户端和自动化管理继续讨论，工具本身成为需要持续设计、实现、测试和审查的项目。

| 内容 | 本次复盘确认的事实 |
|---|---|
| 已在独立Worktree实现 | 统一CLI、管理操作预览、写入口硬关闭、Authorization声明、JSONL审计与只读恢复、专属模拟测试及操作手册 |
| 已有验证 | 只读查询和安全预览验收；阶段二至四的专项/回归和审核证据保留在CHANGELOG |
| 没有取得的结果 | 没有真实GitHub写入验证，没有把平台发布或部署到生产；不能把mock通过等同真实能力已可用 |
| 尚未实施或仅属后续设想 | 可信授权适配器、Windows独立授权客户端、Ed25519签发平台、独立云端授权服务、分布式授权消费及完整人工审计恢复机制 |

不能把后续设想写成已经建成的系统，也不能因为部分实现通过了很多测试，就认定继续建设有产品价值。

## 3. 判断失误与原因

这是ChatGPT在需求判断、范围控制和优先级管理上的失误，不归咎于用户需求不清。cece需要的是项目上下文同步，AI却不断把技术上可以扩展的能力转化为后续任务。Codex在实现和细化时也应主动指出投入与主线价值不相称，而不是仅把既有批准视作继续扩张的理由。

- 把技术完整性误当作项目价值，围绕“怎样安全实现写入”持续加固，却没有及时重新问“现在是否需要这个写入平台”。
- 没有持续检查对当前创业里程碑的贡献，让工程工具压过祈愿体验和商业验证。
- 将未来假设提前转化成授权、客户端、服务和恢复机制等当前建设议题。
- 没有充分保护cece的时间和注意力，增加了阅读方案、理解安全机制、复制材料和反复审查的负担。
- 受到沉没成本影响，容易把已经写完和通过测试当作保留代码的理由。

## 4. 实际影响

增加了与创业主线无关的工程工作，消耗cece的时间、注意力和创业资源，使工程管理工具本身成为需要管理的项目。材料跨会话读取和交付还造成额外操作负担。

这里不编造具体损失金额或工时，也不声称已经造成生产事故；可确认的问题是任务范围与投入偏离了最初的基线读取目标。

## 5. 本次纠正决定

1. 正式回归“BUMBUM项目基线同步（Project Context Sync）”，只读main/任务分支、完整分支及比较、PR、权威文件并恢复项目上下文。
2. 优先现有GitHub连接器；不足时复用已有gh。当前Codex会话没有连接器工具，但gh已实测能完成必要读取，因此不保留重复Python封装。
3. 停止分支/PR/Actions自动管理、独立授权签发、客户端、云端服务、分布式授权及复杂审计恢复平台建设；取消原GitHub Ops阶段五，不另建替代平台。
4. 依赖盘点后清理不再有价值的专属代码、测试和缓存；不因历史投入保留废弃骨架。业务认证、业务审计、NFC、杭州部署工具、公共依赖和CI仍保留。
5. 正常工程开发、提交、分支推送和PR工作按原授权规则继续；PR合并须审查并获cece明确批准，生产部署另行授权。取消平台不等于取消工程流程。

连接器是否能在另一个ChatGPT会话中工作，必须在那个会话实际核对。仓库文件也不会自动给任意新会话增加连接权限；未提交或未合入main的规则只能标为本地草稿，不能冒称GitHub已更新。

## 6. 九条长期原则

以下保存本次决定的原则摘要，长期约束统一维护在AGENTS第0.5节：

1. **创业目标优先：**所有工作服务BUMBUM产品愿景与商业目标。
2. **里程碑优先：**当前产品里程碑优先于工程工具建设。
3. **小步快跑：**每次只解决目标、边界、验收标准明确的一小步。
4. **当前问题优先：**没有实际需求的未来能力不提前建设。
5. **最简单可行方案：**优先复用现有工具、环境和人工流程。
6. **保护创业资源：**保护cece的时间、注意力和资金，不增加不必要的管理工作。
7. **不受沉没成本影响：**没有实际价值的功能可以停止或删除，过去投入不是维护理由。
8. **严格控制任务范围：**不擅自增加架构、自动化和授权系统；未来风险不自动成为当前任务。
9. **主动判断是否值得做：**不值得就明确建议不做或暂缓，不继续设计实现。

## 7. 未来会话怎样避免重犯

新的ChatGPT和Codex会话必须先阅读本复盘，并遵守AGENTS的创业目标优先原则，再主动恢复GitHub当前基线。提出技术建议或启动工程任务前，先回答服务哪个产品/商业目标、为何现在必须做、不做的实际影响、更简单低成本的替代，以及是否值得占用cece的资源。

没有现实影响的风险可以保留说明，但不自动进入当前待办；上下文同步够用就回到产品和客户。未来确有能力缺口时，只提出解决当前问题的最小方案，不重新启动被取消的平台。

本次复盘不要求cece额外维护台账、授权客户端或例行工具操作；AI负责读取和核对，下一步任务由现有TODO反映。
