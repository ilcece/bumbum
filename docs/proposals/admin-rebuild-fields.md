# 管理后台重构方案：业务字段表

从[主方案](admin-make-rebuild.md)进入。本表已随方案通过审核，用于核对“要维护什么、谁提供、何时必填、能否修改”；不是数据库DDL或已开放API清单。已有字段长度、格式、图片限制及查询契约继续按[API](../../API_CONTRACT.md#04-当前能做到哪一步)执行，新增字段的技术存储和校验随获批技术方案明确。

“录入”指管理员提供，“引用”指选择已有记录，“系统”指真实业务结果或计算，不再手填。所有档案有内部记录ID及必要创建/更新时间，系统生成；确认/绑定/接续等操作另记录操作者、时间和结果，不允许表单回填假历史。

## 1. 款式资料

一个款式服务多件数字物品。类别只维护一次，共用内容不复制到每件物品；旧数据归并须人工核对冲突，不能用相同款式文字直接合并。

| 字段 | 含义与来源 | 录入/必填 | 修改及使用边界 |
|---|---|---|---|
| 款式编号 | 识别一款商品，不是单件身份 | 建款录入，必填 | 同类别内避免重复；已有引用后的改码范围须核对，不改物品ID |
| 物品类别 | 服装、饰品等当前支持类别 | 建款选择，必填 | 唯一维护来源；被发行/物品引用后不可普通改类别；技术project仍需适配 |
| 款式名称 | 共用展示名称 | 必填 | 保存影响全部引用物品，显示引用及已启用数量 |
| 介绍、材质、养护/寓意 | 与该商品适用的共用内容 | 按需维护 | 不为手串/T恤/帽子分别做流程；不追改发行承诺或实体事实 |
| 参考图片 | 共用商品图片 | 选填，使用真实Upload | 暂存、预览和正式关联分开；取消不删除已保存图，读取受原资格约束 |
| 适用规格/尺码表 | 供实体准备选择/核对的规格 | 适用时维护 | 无尺码物品不强制填写；实体实际规格另存，旧实际值不随资料更新改变 |
| 引用发行/物品数量 | 看本次保存影响范围 | 系统只读 | 可跳转真实引用，不维护另一份关联名单 |

## 2. 发行约定

每次发行关联一个款式；同款多次发行分别保留承诺。发行资料不承载店铺和订单。

| 字段 | 含义与来源 | 录入/必填 | 修改及使用边界 |
|---|---|---|---|
| 发行名称 | 识别本次约定 | 草案必填 | 不是必须建立一个销售任务 |
| 关联款式 | 本次发行适用的商品 | 草案必选 | 名称/类别只读引用；确认后不能普通换款 |
| 系列归类 | 方便按系列查找 | 选填 | 只归类，不自动共用多款编号池 |
| 发行方式 | 固定总量、限时按销量定量、非限定 | 必选 | 确认规则后受保护，待定总量不能显示为非限定 |
| 固定发行总量 | 固定模式的数字身份上限 | 固定模式必填正整数 | 与实体生产/售后件数分开；确认后不普通增减 |
| 销售起止时间 | 限时模式对外约定窗口 | 限时模式必填，界面北京时间 | 只保存发行必要条件，不记录各店上架/停售过程 |
| 有效数量核定规则 | 限时模式如何从外部核对得到最终数量，含取消/退款/跨期处理口径 | 限时确认规则前必填 | 不能只填“实际销量”；规则确认后不在销售中临时重写 |
| 最终发行总量 | 经外部核定的限时结果，例如137 | 限时确认结果时必填 | 未确定显示待核定；不把预估100当上限。零销售及多建/冲突不强行生成发行结果 |
| 最终数量依据 | 外部核定来源的引用或简短说明 | 限时确认结果时必填 | 不要求上传订单/物流/客户明细；只做人工核定记录，不声称自动验证全部销量 |
| 发行说明 | 限定承诺、规格/颜色限制和允许例外等 | 确认前必填 | 颜色条款并入说明，不再重复独立颜色表单；不解析文字自动推导全部资格 |
| 适用权益版本 | 对外确认时适用的数字物品权益规则 | 确认时系统确定，发行页只读 | 数量与编号由发行定义；每件物品记录适用权益，见数字物品档案 |
| 确认状态、标识、时间 | 草案/规则确认及必要核定结果 | 系统只读 | 管理员不填版本号；规则确认和限时封版分别记录 |
| 当前/历史引用 | 是否曾被物品引用及引用明细 | 系统只读 | 已引用不可硬删；从未引用的独立约定可按已确认规则二次确认删除并留原摘要/审计 |

本件序号在每次发行内唯一；数字物品的系统编号另行唯一。限时模式移除订单排序后的建议分配方法及准备草稿超量边界，见[主方案流程](admin-make-rebuild.md#flows)，本轮已通过，按该规则构建原型及当前分支正式代码，实际接口见API第11节。历史已经确认/封版的编号不重排。

## 3. 数字物品档案

| 字段 | 含义与来源 | 录入/必填 | 修改及使用边界 |
|---|---|---|---|
| 系统物品编号 | 一件稳定数字身份的业务编号 | 建档必填，去首尾空白后1–32字符、不含控制字符、全局唯一；不限制编号格式，FASH/JEW格式仅作建议 | 不随换卡/换人重建；普通编辑不能改号。编号建议不代替服务端唯一校验 |
| 关联发行约定 | 这件身份适用的承诺 | 新建必选已确认约定 | 固定/限时/非限定都要关联；已有正确身份不普通重分配 |
| 款式与类别 | 共用内容及分类 | 从发行引用，只读 | 不提供可冲突的第二组选择，不独立输入类别 |
| 本件正式序号 | 限定如#01/50，非限定如#001 | 固定/非限定建档必填；新限时封版前待定 | 只保存正整数序号、发行内唯一、固定/封版不超总量；前端未知总量补三位如#001，已知总量按其位数显示如#1/9、#01/50、#001/200、#0002/2000；正式确定后不可普通重排 |
| 生产验证标记 | 是否属于生产验证对象 | 新建可选，详情开关维护；默认关闭 | 有标记即可直接删除，不按业务状态设资格；关联/审计/统计处理见主方案第2.6节 |
| 数字身份档案启用状态 | 草稿、启用、停用及适用归档 | 系统记录独立动作 | 资料保存不启用；启用检查名称/发行/可用芯片和配置核验，停用不改持有人 |
| 当前芯片/配置摘要 | 当前有效关系及核验是否就绪 | 从真实绑定/配置引用 | 未配置也能看到已绑定芯片及待核验，不伪造当前实体完成事实 |
| 当前整套物品与实际规格 | 正式生效的某代实物＋配套芯片 | 引用整套物品记录 | 与数字身份分开；准备新物品不提前替换当前物品 |
| 当前整套物品状态 | 待准备、正常、已挂失等 | 从当前代物品取得，只读 | 挂失从物品操作发起，芯片服务随之停止；不把该状态永久附在稳定身份上 |
| 售出确认、首次售出时间 | 有效外部成交对应到具体数字身份，管理员确认 | 首次确认可填有依据的实际成交时间（默认当前、不晚于当前），支持批量；已有首次时间只读 | 与认领分开，换新/转售不重置；撤销销售标记留审计，不改变归属或删除历史 |
| 当前持有人、首次归属时间 | 所有权业务结果 | 接入服务后只读 | 无当前归属显示“暂无持有人”；有关系显示“已有持有人”，不当作首次认领完成；未接入不造用户。首次配卡时间不是首次归属时间 |
| 权益与年度摘要 | 换新、转售及各自的适用状态、规则版本、年度使用及待核状态 | 新发行建档时带入两项标准权益；年度摘要从有效记录计算 | 转售接续该物品的年度使用记录及剩余额度 |
| 历史入口 | 旧实体/芯片、接续、持有人变化 | 系统只读 | 与当前事实分开；必要审计不因不做独立台账而删除 |
| 原发行补齐依据 | 已有物品确实缺失关联时的核对说明 | 专用补齐时提供 | 同款、非归档、只补原承诺；有持有人/已绑定也可核对，不变更原身份/实体/归属/年度事实 |

共用名称、图片和介绍在详情可读并可进入款式维护，物品页不再复制一份编辑表单。未定义的单件内容覆盖不提前加入。

## 4. 芯片档案

| 字段 | 含义与来源 | 录入/必填 | 修改及使用边界 |
|---|---|---|---|
| 芯片UID | 真实芯片硬件身份 | 扫描/手工/Webhook登记必填 | 规范化去重，不重复建卡或覆盖原记录，普通维护不能改 |
| 批次 | 方便登记后补录与查询 | 选填，可补录/清空 | 沿用64字符上限；修改批次不改变登记时间/来源 |
| 首次来源、登记时间 | 首次登记的真实来源及时间 | 系统只读 | 重复回调不改来源/时间，不能从来源猜测所有失败请求 |
| 关联物品/实体 | 当前关联与必要历史 | 绑定/接续产生 | 可点真实物品；更换不能仅覆盖关联或绕过占用检查 |
| 物品类别/名称 | 展示所属数字物品的内容 | 经物品取得款式，只读 | 登记芯片不另填业务类别；未关联明确显示。现有技术project迁移另审 |
| 密钥与配置摘要 | 是否生成密钥、是否核验、核验时间 | 系统只读 | 普通详情不显示秘密；受控查看和真实写卡/双链接核验继续原规则 |
| 服务状态及可执行动作 | 待绑定/已绑定、技术停用、随物品挂失停用、退役等事实 | 技术维护或物品业务同步更新 | 不提供独立芯片挂失；不能通过技术恢复解除整套物品挂失或复活退役授权 |
| 生产验证标记 | 是否属于生产验证对象 | 新建可选，详情开关维护；默认关闭 | 标记后直接删除，不按绑定/配置/状态/历史拦截；清理关联并保留另一侧档案和审计 |

## 5. 当前与历代整套物品（实物＋芯片）

### 实体物品独立档案

| 字段 | 必填时点 | 说明 |
|---|---|---|
| 实体编号 | 登记时必填且全局唯一 | 用于与实物或随件标签核对；与发行序号、数字物品编号、芯片 UID 分开 |
| 款式 | 登记时必选 | 共用名称和类别从款式取得 |
| 实际规格 | 尺码、颜色等适用时必填 | 保存真实的单件差异；用于安装、换新和转售交付核对 |
| 批次、供应商序列号 | 有可追溯来源时选填 | 作为外部来源记录 |
| 当前装配、档案时间 | 系统记录 | 由装配关系展示当前与历史状态，登记后可按实体编号查询 |

### 装配记录与历代整套

| 字段 | 含义与来源 | 录入/必填 | 修改及使用边界 |
|---|---|---|---|
| 整套物品记录ID、所属身份与代次 | 区分同一数字身份下每一代实物＋芯片 | 系统产生，无需管理员另录编号 | 首套、新换新/转售物品分别记录；代次不是发行编号，不增加数字身份发行量 |
| 独立实体及实际规格 | 引用实体编号并显示当次交付规格 | 安装确认时必选实体 | 核对款式、实际规格、装配状态及发行例外；保存当次交付的可追溯事实 |
| 本次芯片、安装确认及核验引用 | 实际安装的芯片及技术核验 | 安装确认时必选芯片，系统记录操作人及时间；启用或确认替换交付前通过核验 | 安装、配置核验、生效独立展示；候选组合交付后接续授权 |
| 生效/退出时间与原因 | 哪一件是当前实体，旧实体何时退出 | 明确操作结果自动记录 | 不按最近建档/发货猜当前；旧实体不回收也不保留当前数字授权 |
| 挂失状态、时间与依据 | 当时那一代整套物品的挂失事实 | 从物品详情确认时记录 | 同步停止该代配套芯片服务；旧代挂失在替换后保留，新代不继承。旧会话只有芯片挂失事实时标旧记录未知时间，不补造 |
| 来源操作 | 由首次准备或哪次整套物品交付生效产生 | 系统引用 | 与操作记录共用事实，不录第二套可改结果 |

删去工厂、样品/供货合同、来货物流、逐轮质检和顾客快递字段。必要实物对应核对放到绑定/接续确认中；不把一次配置核验说成供应链质量认证。

## 6. 物品准备、挂失、换新和转售表单

挂失、换新和转售只从物品详情发起；芯片页提供技术维护及回物品入口。首套物品可从身份或待配套芯片进入，不建独立订单或交付模块。普通确认先只读核对，必要操作再录入。

| 字段 | 含义与来源 | 必填时点 | 修改及使用边界 |
|---|---|---|---|
| 目标物品、业务类型 | 首次安装/定期换新/挂失换新/后台转售等 | 发起时确认 | 携带当前上下文，不重复填稳定编号；未定义的同实体修卡不自动开放 |
| 原持有人、原整套物品 | 操作前物品的记录ID、代次、规格及配套芯片 | 系统带出 | 准备时锁定原物品记录，提交时重查；完成后仍按记录ID显示当时原新对应，不按当前芯片反推 |
| 接收账户 | 转售后的持有人 | 转售准备/确认时核对 | 双方为不同的已验证手机号账户，分别确认转出及接收；有争议或身份无法对应时触发实名 |
| 适用权益、年度资格摘要 | 该物品的规则和当前余额 | 换新/转售核对 | 首次绑定不消耗换新额度；转售不扣减/不重置 |
| 目标规格 | 新实体实际准备的规格 | 适用时填写 | 换新可先选目标尺码；转售在准备实体时填，发行颜色限制继续有效 |
| 准备的新整套物品及配置 | 实体编号、实际规格、装配记录 ID 与代次、配套芯片及配置结果 | 保存准备时记录；生效前核验 | 先准备新物品，芯片配置是其中一步；未确认交付不切换当前授权或持有人 |
| 资格/接收对象核对依据 | 为什么可办理，核对谁接收 | 准备阶段必填依据，转售另录双方确认依据 | 使用业务引用或必要说明，受限核验资料单独保存 |
| 已核验实际交付及对应关系 | 最终确认新实体已交付、对应物品/卡/人无误 | 正式接续前确认，留必要依据 | 不自动用签收推定接续；最终一起反映新旧授权和必要归属 |
| 停用/挂失等处理说明 | 明确保护原因和影响 | 按动作后果确定要求 | 不把原因必填扩大到每次普通保存；解除/恢复资格须另核对 |
| 操作人、时间、结果及历史 | 对象、动作、前后事实和确认结果 | 系统记录 | 历史只读；未知结果先核对，不以本地状态显示成功 |

准备记录可以保存并继续；已完成不可再次切换。准备定期换新后原整套发生挂失，保留同一新物品准备，改按挂失换新继续；不增加办理、不提前扣次数。新方案不提供发货/运输步骤。换新按北京时间确认交付生效日归入自然年，提交时重查该年额度；冻结及取消/争议处置仍待独立定稿。

## 7. 用户、持有关系与权益只读视图

| 字段/视图 | 含义与来源 | 后台范围 | 保护边界 |
|---|---|---|---|
| 稳定用户 UID、账户状态、创建时间、昵称 | UID、状态和创建时间由系统记录，昵称选填 | 后台按权限查账户与持有关系 | 持有关系引用 UID，手机号换绑后账户身份延续 |
| 已验证手机号、验证时间 | 建立账户时必填，验证时间由系统记录 | 运营列表默认脱敏 | 碰卡访客仅获取允许公开的物品资料 |
| 实名核验 | 触发时记录办理单、目的、用户 UID、核验状态；完成时记录时间与凭证引用 | 真实姓名、证件类型、证件号按确需场景采集 | 优先留核验结果和引用，完整证件号确有必要时单独受限保存 |
| 首次交付认领码 | 发放必填物品及交付依据，系统记录操作人、发放时间、状态和失效时间 | 详情展示发放、补发、失效、已核销状态 | 有效期 30 天，补发需重核交付，旧码失效，详见 [H5 首版](digital-item-h5-mvp.md#3-发放确认与异常恢复) |
| 当前持有物品 | 有效归属记录汇总 | 从物品/统计查看必要明细 | 不是另一份手工清单；不以碰卡推定持有 |
| 历任持有人和起止/来源 | 首次认领、正式转售等真实业务产生 | 物品详情按权限只读 | 同持有人换新不伪造所有权转移；用户公开摘要另按允许字段返回 |
| 权益规则 | 数字物品的权益类型、适用状态、规则版本或历史承诺依据 | 在物品档案核对；发行页只读参考版本 | 本轮新发行标准包含换新、转售。真实历史物品按原承诺 |
| 年度使用/剩余/待核事实 | 物品＋自然年＋共享规则的有效记录 | 查看规则、使用来源和待核原因 | 转售接续余额；换新完成后按北京时间确认交付生效日计次 |

首次认领的触碰资格、真实短信及唯一当前所有者方向保留，具体经营衔接未交付。未接入时显示未接入；不将演示账户写入正式服务。

## 8. 核心统计字段与含义

| 指标 | 含义/计算对象 | 必要维度 | 不代表什么 |
|---|---|---|---|
| 数字物品总数与状态数 | 稳定数字身份；状态按实际分类 | 款式、发行、类别 | 不是实物生产数、订单数或触碰数 |
| 芯片总数与准备/服务状态 | 唯一已登记UID；绑定/配置进度和服务状态分开 | 批次、来源、关联物品、类别 | 未绑定不等于未配置；退役/挂失不作为空闲库存 |
| 售出后触碰 | 已售出身份且事件时间不早于首次售出 | 物品/芯片、时间、发行/款式 | 默认使用口径，不以所有者绑定推断售出；生命周期另查 |
| 有效触碰次数 | 服务端接受的有效触碰事件 | 北京时间、款式/发行、物品、芯片 | 不用计数器差值；配置核验、重复读数/刷新不新增 |
| 被触碰物品数 | 时间范围内有效事件对应的稳定物品去重数 | 同上 | 不是独立用户数，换芯片后同物品不重复计成两件 |
| 日趋势 | 按北京时间自然日汇总有效事件 | 近7日/30日/累计，数据截至时间 | 不把设备时区或当前归属改写事件历史 |
| 已认领物品数 | 统计时点存在有效当前持有关系的物品数 | 款式、发行等允许维度 | 不根据发货、签收或芯片绑定推算 |
| 当前持有人数 | 当前有效持有关系的稳定用户ID去重数 | 同一统计时点及范围 | 不等于注册数、访问数或活跃数；账户未接入不以0冒充 |
| 用户持有明细/新增认领趋势 | 已交付账户/归属服务产生的明细/事件 | 按实际可用时间范围 | 未交付事件不从现状态倒推历史；不新增画像和运营漏斗 |

正式触碰事件按发生时的物品关系保留；物品维度延续，芯片维度可分别追溯。历史访问者只在事件真实存在可用账户依据时归集，不能把所有旧触碰划给当前持有人。生产验证开关本身不改变统计；直接删除对象时清理对应触碰事件，统计随真实剩余事件更新，见主方案第2.6节。

## 9. 审计和受控维护字段

审计最少记录操作者、对象、动作、时间、结果和必要前后事实/依据；不记录密码、密钥、验证码、认证头、完整动态参数、认领原码或完整证件号码。对象编号及必要前后值随事件保存，业务展示见 [操作审计](admin-make-rebuild.md#business-audit)。普通保存、正式接续及必要历史的一致性由服务端保证，不能只靠前端禁用按钮。

生产验证开关与直接删除按[主方案第2.6节](admin-make-rebuild.md#26-清理纠错和旧资料补齐)执行，不再套用原L1/L2资格表单。身份纠错/解绑专用路径仍待定；当前原型不执行真实清库、改号、写卡或生产操作。
