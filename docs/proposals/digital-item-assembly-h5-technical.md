# 数字物品装配与 H5 首版技术方案

产品与技术方案已由 cece 确认，见 [后台装配流程](admin-make-rebuild.md#assembly)、[业务字段表](admin-rebuild-fields.md)和 [H5 首版](digital-item-h5-mvp.md)。实施顺序为后台装配、权益和审计，随后 H5 认领及预览，最后模拟批次替换。实际交付和人工验收见 [验收清单](../DIGITAL_ITEM_ASSEMBLY_H5_ACCEPTANCE.md)。保留 Flask、MySQL、Umi 管理端及现有独立 React H5 工程。

## 1. 后台装配、权益和审计

现有 `whole_item` 保存每代整套物品和芯片，`item_handover` 保存候选整套物品和办理单。现有触碰验证仍从芯片的当前物品关联判断资格。建议按下表增量修改。

| 业务规则 | 实现建议与数据约束 |
|---|---|
| 实体档案 | 新增 `physical_item`，全局唯一实体编号，引用款式，保存实际规格及可选批次。共用内容按款式读取，装配记录保存当次规格摘要。 |
| 安装和候选 | 在 `whole_item` 记录实体引用、安装确认人与时间；在 `item_handover` 增加候选实体引用及安装确认。首次安装、换新和转售选择同一套实体与芯片字段。已有候选配卡资格沿用其办理单上下文。 |
| 唯一性与授权 | 写入时锁住数字物品、实体和芯片，重查装配及候选占用，防止同件实物或同枚芯片被并发分配。首次安装保留待核验装配，芯片认证成功还要求物品已启用、芯片配置通过且当前有效。替换组合由交付事务接续，原有效芯片退出，旧许可随现有撤销机制失效。 |
| 标准权益 | 新增物品级权益记录，以物品和权益类型唯一，记录适用状态、来源和规则版本。BUMBUM 标准规则按生效时间匹配对外发行确认时间，建档时把两项权益及匹配的版本写入物品记录。发行表单和发行接口的目标字段只承载发行规则，办理资格从物品级记录校验。已有真实数据如需升级，先核对历史承诺。 |
| 换新计次 | 确认交付时从同一服务端生效时间计算北京时间自然年。用已生效的换新办理记录保存计次事实，物品行串行化校验该年共享额度。转售继续引用同一个数字身份及年度记录。交付和持有切换复用既有受保护的管理写入和请求回执。 |
| 业务审计 | 在现有审计记录中保留操作者、业务编号快照、动作、结果、前后值和办理单引用。列表返回业务摘要，详情显示受控依据。确认结果成功后写入对应审计；关键拦截单独记录。旧记录按实际保存的字段展示。 |

安装确认、配置核验、启用分开更新。装配冲突时返回具体对象及需刷新提示，已核验或生效组合的纠错入口按专项权限审核。原有实卡密钥、配置核验、有效触碰和管理登录继续作为技术基线。

## 2. H5 账户、认领及读取权限

| 能力 | 数据、入口与权限建议 |
|---|---|
| 账户和会话 | 用户表以 UUIDv7 为主键，内部外键引用同一值。首次建账同时分配独立的 UUIDv4 作为对外 UID。两者在手机号换绑后保持。手机号继续唯一。历史账户的验证时间以实际验证结果写入。新增独立用户会话记录，保存会话摘要、用户、有效期及撤销时间。用户凭真实短信完成登录或建账，使用独立于管理员的用户会话。会话凭证保存在安全 Cookie，写请求做来源校验，退出时撤销会话。短信沿用 60 秒发送间隔，具体服务接入及上线凭据在测试发布前核对。 |
| 交付发码 | 增加按物品记录的一次性认领码、有效期、状态、发放及交付依据。后台受权限保护地发放或补发，原码只在成功响应中交给发码操作人，服务端持久化用途隔离的校验摘要。管理写请求回执只保存发码记录 ID 与状态；响应丢失时先核对发码结果，需要重新取得码时走受控补发。有效期 30 天，补发时事务内使前一码失效。 |
| 近期碰卡资格 | 复用现有短时触碰凭证的物品和芯片绑定。技术实现须为认领校验当前有效装配、凭证用途与时效；持续查看凭证仅授予资料读取资格。首次认领通过前仍可正常查看公开资料。 |
| 确认认领 | 服务端依次校验当前用户会话、近期有效碰卡、交付码和可认领状态。在同一事务锁定物品和凭证，检查无现任持有人，写入持有及历史，核销认领码与认领资格。已有同账户归属返回已完成，其他账户仅收到已认领状态。错误尝试由服务端限流。 |
| 我的物品和公开详情 | 公开详情从碰卡读取明确允许展示的资料。我的物品按当前会话关联的内部 UUIDv7 查询有效持有关系，所有详情都验证当前归属。转售生效后按新归属读列表。历史持有人信息、芯片 UID 及凭证属于受控数据。 |
| 场景实名 | 办理单按规则记录核验目的、关联用户、状态、时间及核验引用。核验结果足以处理时保存结果与引用。确需留完整证件号的具体场景、存储权限与期限单独审核。 |

### 拟用接口与权限

| 入口 | 必要输入与结果 |
|---|---|
| 管理端 `GET /api/admin/catalog/physical-items` | 按编号、款式和装配状态查询，返回可核对的实体摘要。沿用管理端会话。 |
| 管理端 `POST /api/admin/catalog/actions/{action}` | 沿用请求 ID 和管理写权限。拟增 `createPhysicalItem`、`installAssembly`、`issueClaimCode`、`reissueClaimCode`。安装提交物品、实体、芯片 ID 与明确确认；准备和交付继续使用现有 `prepare`、`complete`。发码提交物品 ID 与交付依据。 |
| 公共 `POST /api/public/sms/send` 与 `POST /api/public/sms/verify` | 发送提交手机号，返回挑战引用和重发提示。验证提交挑战引用和验证码，成功建立用户会话，返回本人账户摘要。 |
| 用户 `GET /api/public/account/session` 与 `POST /api/public/account/logout` | 检查本人会话、获取脱敏手机号或撤销当前会话。 |
| 用户 `POST /api/public/items/{id}/claim` | 使用登录会话，提交短时碰卡凭证与交付码。返回认领结果和物品引用。错误区分需要登录、需要重新碰卡、码有误或需补发、已认领和请求频率限制。 |
| 用户 `GET /api/public/items/{id}/claim-status` | 已登录用户用于恢复未知结果，只返回与本人相关的归属结果及允许公开的认领状态。 |
| 用户 `GET /api/public/me/items` 与 `GET /api/public/me/items/{id}` | 列表按当前账户持有关系查询；详情先验证当前归属，返回允许本人查看的摘要。 |
| 管理端 `GET /api/admin/catalog/items/{id}/h5-preview` | 仅在管理员能读取该物品时返回已保存的展示资料。模拟状态由预览界面提供。 |

现有 [API 历史预留](../../API_CONTRACT.md#101-短信与首次认领预留) 用于核对兼容。验收关注权限、必要输入、失败语义和重试结果，逐字段接口契约、架构和数据规范随实现同步。凭证通过请求体或适用的会话机制提交，查询地址和审计使用可公开的业务引用。

## 3. 后台预览

管理端从物品详情打开侧栏。使用管理权限读取指定物品的已保存公开资料，把资料与预设访客、待认领、持有人状态传入和 H5 共用的展示组件。先抽出小范围共用展示层，用户端的触碰、会话、短信和写操作保留在用户端流程。预览内的按钮推进模拟页面，后台详情分区及滚动位置在关闭后保留。检查未装卡、编号待核定、资料缺失及三种状态的展示。

## 4. 数据升级、批次替换与回退

1. 在隔离的同版本 MySQL 库验证增量迁移、回退前提和现有数据读取。已有非模拟记录保留，其实体编号缺失时展示待核对，补齐应由可追溯的实物资料驱动。测试专属的数据替换通过验收批次机制。
2. 测试环境执行前检查清理预览、实际对象归属、跨批次依赖和 SQL／媒体备份。清理范围扩展到属于目标批次的实体、认领凭证和新关联，用户及芯片继续按同批次关系和冲突检查处理。原备份对应的版本与恢复条件一起记录。
3. 生成新版模拟批次并核对安装前后、售出后零触碰、待认领、已认领、跨年换新和转售继承额度等样本。失败时核对当前批次状态及剩余对象，按已批准的恢复步骤处理。数据库与媒体恢复、代码回退、实卡状态分别核对。
4. 真实短信、测试环境部署、实际批次清理及实卡操作按各自范围授权和取证。模拟数据验证服务状态和界面，真实端到端验收使用已授权测试卡和真实短信。

## 5. 验收与审核点

| 核对项 | 通过依据 |
|---|---|
| 装配及接续 | 同件实体或芯片并发选择只能成功一次。待核验组合无法取得有效触碰；核验、启用、挂失、接续按各自状态生效。 |
| 权益及审计 | 跨年按确认生效日归年；定期和挂失共享一次；转售后年度用量延续。业务摘要、前后值及保留的历史对象编号正确。 |
| H5 | 访客可先看资料；有效交付对象可认领。错码、补发、过期、并发、重复提交及断网后核对符合产品规则。登录后能回访我的物品，权限隔离覆盖其他账户。 |
| 预览及批次 | 三视角可用，预览与真实写操作及统计隔离。批次预览、冲突保护、重建和新样本查询均可核对。 |

本稿中的增量表结构、账户和认领权限、实施顺序及批次回退边界已经审核；实现与验收范围分别见API、TODO和CHANGELOG，不把方案批准当成各细项验收。费用、冻结、争议处置和已核验装配纠错的细则继续单独定稿。
