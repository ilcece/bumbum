# 数字物品接续与纠错：待定政策

现行后台规则已纳入[数字档案规范](../product/digital-catalog.md)，字段在[业务字段](../product/admin-fields.md)，用户账户、认领、找回及办理记录在[用户 H5 规范](../product/user-h5.md)。原方案与批准证据保留在[归档快照](../archive/admin-make-rebuild-2026-11-17.md)。本文的 review 仅针对下列未决政策，不撤回已批准或已实现的规则，不代表已授权新增构建或发布。

<a id="flows"></a>

旧核心流程入口 → [现行发行、装配、交付与接续流程](../product/digital-catalog.md#flows)。

<a id="item-rights"></a>

旧权益入口 → [现行数字物品权益](../product/digital-catalog.md#item-rights)。旧链接只用于导航，详细规则仍维护在现行规范。

## 1. 已决定，不重新待审

- 换新与转售沿用稳定数字身份、发行编号和原首次售出事实；新整套物品经确认交付后接续，保留历代实体、芯片及持有人历史。
- 定期与挂失换新共享每个北京时间自然年一次额度，以确认交付生效日计次；转售继承物品该年用量和余量。
- 常规转售核对双方已验证手机号账户及转出、接收同意。有争议或身份无法对应时转入实名核验，不能跳过既定核验。
- 生产验证开关与专用直接删除、配置前草稿装配的受限 undoInstall、找回设置及取消挂失已有明确规则，按现行规范和实际接口执行。
- 首批逐次报价、人工受理的方式已确认，取消/退款/争议先人工处理，不自动撤销已生效交付；详细规则只在[现行服务受理](../product/digital-catalog.md#manual-rights-service)维护，金额和具体处理细则仍待明确。

## 2. 仍需独立确认

| 政策 | 需明确的边界 | 确认前如何处理 |
|---|---|---|
| 换新及转售具体费用 | 每次报价金额、适用项目及取消退费条件 | 按已确认的人工受理方式逐次核对，不预设价格、免费范围或自动收退费流程 |
| 资格冻结与争议处置 | 谁可冻结、条件、持续时间、解除及证据 | 不把临时技术停用当作业务冻结，不自动改变持有人 |
| 办理取消与异常恢复 | 换新/转售准备中的取消、实际交付异常及失败恢复 | 不覆盖已成交/交付事实，不自动恢复挂失物品或复活撤销资格 |
| 身份与已核验装配纠错 | 错 UID、错类别/项目、错发行/序号、已核验误绑定的专用授权、历史及恢复前提 | 不临时改数据库关联，不用已批准的草稿 undoInstall 扩大纠错范围 |
| 退役旧卡与单独芯片维修 | 退役旧卡的其他展示、同一实物只换芯片的服务政策 | 退役不获普通触碰授权；不把整套换新流程当作芯片维修已开放 |
| 超量准备草稿 | 限时发行封版时超量草稿怎样退出、冲突处理及恢复 | 保留真实对象和历史，不能自动删身份凑数量或重排已确认编号 |
| 受限身份资料 | 确需保留完整证件号的场景、权限和期限 | 优先只留核验结果与受控引用，不因字段预留扩大采集 |

## 3. 跨年准备的待确认选择

计次按北京时间的实际确认交付年，已经批准，本轮不重新待审。本次核对发现：`core/catalog/inventory.py` 的 `prepare` 还会按准备当年检查余量，`complete` 才按实际生效年复核。因此，“今年已用完，想先准备明年交付”会在准备阶段被挡住。以下只讨论准备阶段的受理边界，不改现行计次规则。

| 选择 | 用户和管理员怎样理解 | 取舍 |
|---|---|---|
| 建议：允许提前准备 | 今年额度已用完，也可准备预计明年交付的换新；在办理依据中说明预期，不提前扣次、不预留下一年资格。正式生效仍按实际交付年的可用次数检查 | 便于提前备货；须说明“已准备”不等于已获交付资格，不承诺一定能在某天办结 |
| 备选：等下一年再准备 | 准备时当年没有余量就不受理，跨年后重新核对 | 沿用当前准备限制，操作简单；用户不能提前安排下一年的准备 |

cece 选择前，两项均不写入现行 approved 规范，也不把代码中的当前预检当作新的业务决定。若选择提前准备，最小实现优先复用现有办理依据和交付复核，不为此增加额度预约系统或计划年份表。

验收应覆盖：当年已用完时准备次年交付；12月准备、1月生效只计新年；准备后实际仍在本年交付且本年已无余量时拒绝生效；新年确认前余量已变化时重查。准备不切换当前实物、持有人或有效芯片，转售继续继承原物品年度事实。

<a name="4-首批权益受理的待确认选择"></a>

## 4. 人工受理已确认后的执行缺口

cece 已选择[逐次报价、人工受理](../product/digital-catalog.md#manual-rights-service)，本节不再保留“仅演练”的待选方案，也不重复维护受理规则。仍需解决的是具体费用及异常怎样实际办结：

- **报价与取消费用：**受理时说明适用费用和交付条件；哪些时点可取消、已发生费用如何结算、退款条件及凭据范围仍需明确，不由AI补定金额或比例。
- **未生效办理的安全结束：**当前没有通用取消入口。停止继续履约后，系统如何保留取消依据、释放准备中的实物和芯片、处理原挂失状态，须另定最小安全范围和验收；不临时改库、删办理记录或用“确认交付”代替取消。
- **未知结果及已生效争议：**先核对原办理、请求回执和实际交付依据，不自动重发或切换持有人。已生效交付按人工核对结论处理，需要数据更正的个案另行核定，不能直接恢复旧芯片、删除归属或重置额度。

实际报价和交付确认可沿用现有业务依据，只保留必要引用。尚未发生的报价、收费、取消、退款或试用不得补写成已完成。服务方式获确认不自动授权新增支付系统、生产发布、短信开放或真实数据/芯片操作。
