## 1 目标、证据与状态

已确认的方向：

1. 芯片、物品管理均不好用，要统一列表、创建、详情、编辑的组件规范、设计风格与交互行为，管理后台采用Ant Design。
2. 不可编辑字段只读展示，说明原因及纠错办法；普通批次、款式等维护字段纳入本轮，不因没有错填事故排除。
3. 查询覆盖实际管理所需业务字段，基础条件加展开筛选，不只提供少数现成条件。
4. cece需要必要的生产测试与验证，也需要正式的测试数据清理办法；普通测试仍在测试环境进行。
5. 芯片挂失、新实体及新芯片接续原数字身份和约定权益是明确业务需求，独立提高方案优先级。**当前转售必须换新实体及相应新芯片；未来只有实际业务需求变化并重新评审才调整，不列为待决定项。** 转售和同一持有人的丢失换新分别定义。

## 2 分开推进的工作流

| 工作流 | 已确认需要解决什么 | 本轮产品设计范围／后续交付边界 |
|---|---|---|
| A 日常后台改版与维护 | 操作割裂、信息难理解、维护与查询不完整 | 统一交互、创建到详情/编辑、只读解释、批次/款式维护、业务查询覆盖及图片上传；按Ant Design官方模式分页面实施 |
| B 生产验证与数据清理 | 生产验证结束后有正式退出与清理办法 | 覆盖草稿、已配置/触碰的验证记录和真实用户数据边界；先决定清理规则与统计口径，再独立实现，不限于草稿删除 |

## 3 Ant Design与统一操作原则

采用Ant Design与ProComponents作为管理端首选复用组合，统一布局、字段分组、表格、表单、按钮、校验、弹层、通知、加载与错误行为；覆盖芯片与物品核心流程，不以只换几个控件后长期混搭作为完成。保留现有React + Vite + TypeScript工程与认证机制，交互和页面组织优先采用Ant Design Pro官方模式；不自动迁入完整脚手架、引入Umi或重写后端。具体组件版本和兼容性在技术方案核对，用户H5另行设计。

**业务与设计的分工：** PRD定义字段含义、查询覆盖、可编辑权限、关联关系、状态、操作结果及异常保护。列表筛选与查询、表单详情的只读态与编辑态、校验反馈、布局及控件交互，优先采用Ant Design与ProComponents的官方规范、组件和推荐模式；原型与官方方案有差异时以官方方案为准，同时满足本稿业务规则。不另写一套控件设计规范，不要求cece逐项决定控件或像素样式；确有业务缺口再说明最小补充。

创建、详情、编辑共享清楚的身份区、资料区、关联与状态区。抽屉、弹窗或页面依官方适用模式选用，同类任务保持一致；原型中的统一右侧抽屉不构成实施约束。保存/取消、返回与键盘行为复用官方能力，并保留本稿要求的工作上下文及未保存保护。危险动作独立说明，不层层套弹窗。主按钮对应当前任务，不能让用户靠大段技术警告理解操作。

移除未实现的所有权、设置、通知、导出、空“更多”等日常入口，必要处直接说明待开放；修正“绑定后续接入”等过时说明。系统检查保留真实入口。字段只读也必须可见，解释为什么不能改，并提供当前可执行办法或明确标注专用流程待交付；不能以不存在的纠错按钮伪造可用能力。

保留既有未保存离开确认、防重复提交、未知结果核对、会话/CSRF检查及必要审计。迁移组件不得退化已有正确行为。1280×720、1440×900桌面可完成核心任务，键盘焦点及返回正确，按钮不裁切、宽表格内部滚动；手机后台另排。现有控件在迁移期间可短暂并存，整条已交付流程须完成统一及回归。

### 3.1 官方复用、定制与迁移约定（已确认）

**复用顺序：** 官方现成能力 → 配置与组合 → 最小业务补充。已有组件能通过配置、组合或主题调整满足需求时，不手写同类表格分页、表单校验框架、弹层或通知系统。必要的接口适配、字段定义与业务动作仍须开发，“少写重复代码”不等于不写业务代码或直接复制示例数据。

| 后台任务 | 优先评估的现成组件／模式 | 体验与业务边界 |
|---|---|---|
| 导航、菜单、面包屑、页面容器 | ProLayout、PageContainer | 菜单只列已交付能力，路由与会话继续受控，不整包引入示例页 |
| 列表、查询、分页及筛选 | ProTable；简单场景可用Table | 同类列表共享查询/重置/分页模式；条件与总数以服务端全量过滤结果为准 |
| 创建、编辑、字段校验 | ProForm、Form及官方字段组件 | 两模块相同字段分组和校验反馈；表单切换到新记录须重置旧值；服务端重复校验业务规则 |
| 详情、只读信息 | ProDescriptions、Descriptions | 身份和不可改字段仍展示原因与替代处理，不把只读理解为隐藏 |
| 页面或弹层里的表单 | Modal、Drawer与官方表单容器组合 | 容器形态按官方适用模式选用；保存/取消/关闭与未保存保护一致，不每页自创一种操作 |
| 状态、提示、加载与失败 | Tag、Badge、Alert、Result、Message、Notification、Spin、Skeleton、Empty | 同类结果用一致样式及文字；真实保存结果来自后端，不用动画、定时器或本地状态伪造成功 |
| 挂失、核验、接续步骤与历史 | Steps、Timeline | 只展示真实业务进度；点下一步不等于实卡完成、授权切换或权益迁移 |
| 图片维护与预览 | Upload、Image及官方图片列表模式 | 以选择本地图片上传并预览为业务目标；现有图片可继续查看，真实上传接口、存储及失败处理须在技术方案落实，不把组件展示当作上传成功 |

**同类任务同一模式：** 列表工具栏、查询提交/重置、字段组织、主要按钮、保存取消、空/失败/成功反馈形成统一约定；不让芯片、物品管理各自维护一套。创建与详情允许信息密度不同，不能为了视觉相同损害任务连续性。

**主题集中配置：** 品牌色、字号、间距、圆角、尺寸与危险样式优先通过官方主题和Design Token统一设置，避免逐控件大范围覆盖内部CSS；弹窗、通知也须继承同一主题、中文与反馈上下文。具体ConfigProvider/App接入维护在技术方案，不要求cece选择API调用方式。

**复用不自动扩大功能：** 行选择、批量操作、导出、保存视图等即使组件自带，也只按已批准范围开放；危险动作的确认、依赖检查和访问控制以BUMBUM业务规则为准。禁用字段/隐藏按钮不能代替后端权限；远程查询不能降级为仅筛当前页。业务规则由本项目已确认的PRD定义。

**定制须说明缺口：** 技术方案对每个必要定制列明任务、已评估的官方能力、不能满足的具体原因、最小补充及维护影响；配置能解决的不另外建设组件库或通用后台框架。该说明放在对应技术方案，不新增独立审批平台；也不因内部实现换组件反复要求产品确认。

**按完整任务迁移验收：** 以“列表 → 创建/详情 → 编辑 → 返回”的完整流程为交付单元，保留已有认证、接口适配、安全检查及业务测试；流程交付时移除其已被替代的旧控件、重复样式和无用依赖，先核对跨页面共用依赖再删除。不默认推倒重写整个后台；不以组件安装成功或几处截图变好看当迁移完成。

官方参考：[Ant Design设计规范](https://ant.design/docs/spec/introduce-cn)、[组件总览](https://ant.design/components/overview/)、[Table](https://ant.design/components/table/)、[Form](https://ant.design/components/form/)、[Upload](https://ant.design/components/upload/)、[主题配置](https://ant.design/docs/react/customize-theme/)、[ProComponents](https://procomponents.ant.design/components/)、[Ant Design Pro](https://github.com/ant-design/ant-design-pro)。版本锁定、具体导出及React兼容以实施时技术核对为准，以上是复用方向，不表示依赖已经安装。

## 4 列表、创建、详情与编辑的连续流程

| 位置 | 内容与动作 | 完成后去向 |
|---|---|---|
| 芯片列表/详情 | UID及复制、项目、批次、首次来源、状态、关联物品、密钥生成/核验摘要、登记时间；不直接展示秘密 | 查询/登记后可直接看该卡，详情进入可编辑字段；关联可跳转，关闭恢复列表位置 |
| 物品列表/详情 | 编号、名称或未填写、项目、款式、状态、关联芯片及配置摘要；服装资料可编辑；饰品资料模板仍另定 | 创建成功按实际返回记录直接查看/完善，也能继续创建；不靠“最新第一行”猜记录 |
| 普通编辑 | 明确区分可编辑资料与只读身份；已有值、字段校验、保存/取消一致 | 成功刷新确切记录，关闭回原列表；无修改不提交，出错保留输入 |
| 专用处理 | 停用、纠错、清理、挂失/接续按已交付能力展示，含影响说明 | 未交付时只给说明或受控人工处理指引，不以普通编辑替代 |

**详情与编辑字段一致：** 对同一芯片或物品，详情与编辑展示相同的适用业务字段，字段含义、名称和取值一致；详情全部只读，编辑仅开放第5节批准维护的字段，其余仍只读展示，不隐藏或省略。状态、时间、关联对象和配置摘要等只读内容也保留；没有值时显示未填写、未关联等明确含义。该要求不包含秘密、内部诊断字段或尚未定义的饰品资料模板。只读态与编辑态的样式和交互采用官方模式，不强制把只读值显示成禁用输入框。

**关联是引用：** 芯片绑定物品后，关联物品以可点击引用展示，按真实绑定关系打开该物品的只读详情，而非复制一份可单独修改的物品资料，也不靠关键词或列表第一行猜对象。物品详情中的关联芯片同理；返回恢复来源记录及列表上下文，有未保存输入时沿用离开保护。未关联时明确显示未关联；目标不存在、不可访问或读取失败时说明原因并可返回，不能跳到其他记录。点击引用不改变绑定关系，也不开放解绑、换绑或纠错权限。

创建成功保留项目、清空已提交编号及款式供继续创建；另提供查看/完善新记录入口，不丢原列表条件。编辑成功但记录不再符合当前筛选时提示原因，不暗改条件。列表刷新失败不将已保存改报失败。删除后当前页为空则回前一有效页。

列表条件、已提交关键词、页码及详情返回位置可恢复，刷新与浏览器前后退不无故丢工作上下文；具体URL/路由方案由技术设计确定，链接不含凭证。区分空库、查询无结果、读取失败；分别给创建引导、清条件、重试。沿用每页默认20的业务基线，分页控件和列配置按官方模式实现，50条及列偏好不作为本轮必备能力。

## 5 查询覆盖与可编辑字段

下表是**已确认的A目标查询覆盖范围**，不是现有API已支持清单。常用条件为关键词、项目、状态，其余条件可按官方查询表单模式折叠；提交、重置、展开收起及控件状态遵循官方推荐交互，不照搬原型布局。查询在服务端按完整条件过滤并计算总数，再分页。日期按北京时间、包含起止日，非法范围明确提示。不同查询方式不能改变写权限。

**图片维护目标：** 使用Ant Design Upload等官方图片上传组件选择本地图片，展示上传状态与失败反馈，成功后可预览并维护物品图片；详情只读预览，编辑态允许上传、移除并随资料保存。上传失败不能显示成功或覆盖原图片，取消编辑不改变已保存的图片关联。现有图片地址需兼容保留，数量及资料校验沿用现行规则；排序、裁剪等扩展不自动纳入。当前实现仅保存和预览图片URL，尚无真实文件上传接口与存储；接收文件、访问方式、文件限制和未保存文件处理等由技术方案明确并审核，不在PRD指定存储产品或自创上传交互。

普通资料编辑不强制填原因。保存资料与启停等动作分开；有未保存输入时选择保存后继续、放弃继续或取消，不隐式保存。危险确认强度在对应工作流决定，不默认所有操作都填原因和完整编号。

## 6 权限、异常与统计保护

现有登录、会话、CSRF及服务端业务检查保留；每次写入重查条件，不仅隐藏按钮。失效会话隐藏管理资料，CSRF失败不自动重放危险写入；未知结果先查询再决定重试。普通编辑的变更与必要审计一起成功或失败；跨实卡/履约流程则分步骤保留可恢复进度，不宣称数据库事务能回退芯片。

记录必要操作者、对象、动作、时间及变更依据；不记录密钥、密码、认证头、完整动态参数或凭证。清理历史不清掉阻止旧身份/旧卡复活所需证据。真实有效触碰发生时的物品归属保留，不随换卡移到另一数字身份；测试统计与清理规则在B确认前沿用现行统计，不暗改累计数。

## 7 分工作流验收与技术前置核对

以下为计划，不是已通过；新写能力先在隔离环境用样例验证，生产仅在明确授权下做必要验证及按规则退出。

| 验收组 | 可独立检查的任务与结果 |
|---|---|
| 1 A统一流程 | 芯片/物品查找→确切记录→详情→编辑→返回/继续创建；按[对应规则](admin-management-update.md#31-官方复用定制与迁移约定已确认)复用官方模式，视觉和行为含主题/通知一致，以业务结果及官方规范验收，不要求复刻原型；详情/编辑的适用业务字段、名称及取值一致，不可编辑字段只读保留；关联引用打开真实绑定对象详情，返回位置及失败反馈正确；移除假入口，键盘及矮窗口可用，记录切换不带旧值，旧重复控件退出 |
| 2 A字段与查询 | 批次/款式/服装资料合法编辑；不可任改身份；图片选择、上传成功/失败、只读预览、移除保存及取消不改变已保存关联按批准的技术方案验证，不以组件展示代替真实上传；覆盖表逐项核对关键词、选项、日期及不支持原因，含跨页总数、无结果及筛选返回，不以当前页过滤冒充全库 |
| 3 B验证退出/清理 | 分别用L1、L2、L3样例：预览依赖及保留内容、清理/拒绝、编号与实卡再用、资格及统计；失败可核对，不删真实用户历史，不以删草稿替代L2 |
| 4 C纠错 | 未配/已配两类误建误绑，合法路径与拒绝原因清楚；历史、密钥、实卡与身份一致，不出现改库成功但实物失效的假完成 |
| 5 D接续及共用回归 | 挂失后旧资格拒绝、新卡准备不授权益、正式接续仅一个有效卡、旧卡恢复无效；准备/切换失败及并发安全；转售强制新实体、所有权独立验证；已有扫码去重/绑定/密钥/核验/统计及权限回归保留 |

每条工作流定稿后按需补充必要交互说明及不超过必要组数的人工验收；A不再调整参考原型。故障与竞态由AI在隔离环境检验，不要求cece破坏生产。D不因A验收通过被标完成。

技术前置：当前字段来源与查询性能、关联详情读取、图片上传与存储；生产验证标识作用范围及历史补标；清理依赖和安全记录；当前/历史载体映射与资格永久撤销；准备卡核验与正式激活隔离；Ant Design版本、React 19、旧Radix/Tailwind统一迁移边界。API、schema、迁移、备份/回退只在对应技术提案明确，本次不虚构已实现接口或改表。
