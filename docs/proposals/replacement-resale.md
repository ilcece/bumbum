# D：挂失、换新与转售接续

审批范围：需求方向及正文明确标注的原则已确认，其余具体规则待cece审核。文档整理获批不等于本业务方案全部获批；本稿承载尚未纳入现行规范的改动，不能据此推定实现、验收、合并或部署。当前进展只看[TODO](../../TODO.md)，现行规则从[产品入口](../../PRD.md)查阅。

## 1 D：挂失、换新与转售的独立业务方案

**已确认目标：** 原数字身份及约定可接续权益保留 → 旧芯片挂失/停止服务 → 新实体及新芯片准备、配置、核验 → 正式接续 → 保留历史。转售必须换新实体；挂失换新通常是同持有人，转售则另有所有权变化，不能用换绑替代所有权转移。

| 概念 | 产品含义与当前限制 |
|---|---|
| 数字身份 | 可跨实体/芯片延续的数字对象；不能直接假定现有item已完整实现 |
| 实体载体 | 某一件实际服装/饰品，可能损坏/丢失/被替换；需辨识每次载体更换 |
| 芯片 | 某载体的认证入口；验签不证明合法持有人；同一数字身份同一时刻最多一个有效芯片，允许挂失后暂时没有有效芯片 |
| 当前持有人 | 经约定方式确认的权利主体，不能从碰卡或管理员录入直接推定；完整认领/所有权能力尚未交付 |
| 历次关联 | 哪枚芯片、哪件实体在何时承载过哪个数字身份，保留追溯但不授予历史卡当前访问权 |

cece本轮进一步确认：限定物品换新/转售后，其数字身份和专属编号继承，例如T恤`#001/100`保持不变；替换实体不增加发行数量。必须记录历次所有人，用户侧展示作隐私处理。业务场景与页面职责见[最新Make方案](admin-make-rebuild.md)，展示遵守[后台设计与交互规范](../ADMIN_UI_GUIDELINES.md)。操作靠近相关信息分区，不放在物品详情抽屉最上方；复杂处理界面及公开摘要仍须逐项对齐。

现有schema在chip.item_id上唯一，停用/丢失也保留占用；首次绑定拒绝已被另一卡占用的物品。它支持现有唯一绑定，不足以直接表达“历次关联＋唯一当前授权”。技术方案需决定item与数字身份/实体载体的职责，不能仅去掉唯一约束或清空旧关联，不能把预留ownership/history表当已验收所有权服务。

| 必要业务动作 | 必须达到的结果／待设计部分 |
|---|---|
| 临时停用/恢复 | 阻断当前服务但保留关联，不代表丢失或替换；恢复检查对象、关联及当前授权。是否永久撤销停用前资格作为独立规则确认，不能因恢复自动假定安全 |
| 挂失/解除挂失 | 先按资格证据确认申请者，再阻断旧卡和已有资格；解除仅在尚未替换、无退役/争议等条件下考虑，资格与审批待定 |
| 永久退役 | 旧芯片不再获得该数字身份授权；不能通过普通“恢复”或重新登记生效 |
| 新芯片准备与核验 | 登记、配置、实卡验证是准备步骤，不等于对真实用户启用；需有不授予当前业务权益的核验路径，具体技术另审 |
| 正式接续 | 唯一当前授权切换与必要记录一致生效；旧卡永久退出，资格撤销不随状态恢复复活；不得留下双有效载体 |
| 接续失败/取消 | 明确发生在准备前、准备中或正式切换后；默认保持旧卡已挂失及新卡未激活的安全状态，恢复需明确条件，不自动让丢失旧卡复活 |

现有短凭证与持续查看资格都需覆盖；“每次查当前状态”不等于永久撤销。接续前已签发资格即使未使用也必须按规则失效；新卡正式接续后重新签发资格。方案需验证并发、响应丢失及恢复后的旧凭证，不只测新碰卡能打开网页。

同持有人换新不自动改变所有权，但须核对申请资格。转售必须按新实体履约及所有权确认规则处理，旧卡退役和持有人变更的完成时点要一致可解释；申请、支付/订单（如需要）、发货、签收与正式切换不预设同一时刻。哪些公开档案/权益延续、消耗型权益是否补回、私人资料是否隔离必须列清单，不复制旧芯片全部数据。当前无自动继承全部权益的承诺。

剩余待决见第5节。**转售必须换新实体已确定，不再列待选项。** 状态名称数量由业务动作推导，不自动增加一串枚举或完整交易平台。

## 2. 已确认的业务定义与暂定规则

2026-11-04 cece确认下列方向及暂定细则；仍属待实施提案，不代表现有接口已支持。

| 场景 | 定义、后台处理与边界 |
|---|---|
| 挂失 | 确认申请资格后阻断当前旧芯片的服务/资格，保留数字身份、持有人及历史。挂失是保护操作，不等于换新申请、实体交付或扣除换新次数；解除条件另定 |
| 定期换新 | 同一持有人使用约定的付费权益获得新实体及新芯片，数字身份与限定编号延续；准备、交付、正式接续分阶段，不用普通编辑覆盖旧实体 |
| 挂失换新 | 挂失后使用付费换新权益完成新实体交付及接续；办理期间旧卡保持阻断，不能因取消申请或运输异常自动恢复 |
| 转售 | 转售数字内容及约定可转移权益，旧实体由原持有人保留，品牌交付新实体/新芯片。当前仅由后台办理；用户侧只查看流转信息，不开放转售发起入口 |
| 旧实体 | 换新后的旧实体无需回收，转售旧实体同样保留。正式接续后旧芯片退出当前数字身份/权益授权，保留历史；“无需回收”不等于允许双有效芯片，也不把旧实物直接判为假货 |

### 2.1 数字权益与身份的关系

数字权益作为独立对象定义，包括付费定期换新、付费挂失换新、转售数字内容及可转移权益，以及后续明确批准的权益。权益规则与每次申请/费用/准备/履约记录分开；身份和限定编号不是消耗型权益，个人账户资料与私人内容不自动转移。未约定的权益不默认继承。

### 2.2 尺码、颜色及维护位置

- **尺码允许调整。** 款式/发行资料统一维护尺码表及允许选择范围；具体实体保存实际交付尺码；换新申请填写目标尺码并在交付时写入新实体快照，不覆盖旧实体尺码。
- **颜色不允许调整，除非发行时物品说明已有明确约定。** 发行资料维护颜色和例外规则，实体保存交付颜色；管理员不能在办理换新时临时改发行说明以绕过限制。
- 普通物品资料可引用款式/发行资料，不为本阶段立即另建一级“款式管理”菜单；维护入口随后续具体页面方案对齐。
- 费用另行讨论，不预设价格、支付平台或退款规则。仅更换芯片而保留原实体属于另一种维修可能，是否提供及如何计费/计次尚未确定。

### 2.3 “一年一次”的暂定口径

| 条目 | 暂定规则 |
|---|---|
| 年度 | 自然年，不是从绑定日滚动计算12个月；年度切换时区待明确 |
| 首次起算 | 首次绑定所有人后开始具备相应资格；未绑定前不消耗或累积历史年度次数 |
| 次数 | 定期换新与挂失换新共用每年一次额度，不各给一次 |
| 转售履约 | 转售交付新实体不计入换新次数，不应改变接收人的后续自然年周期 |
| 旧实体 | 换新后无需回收，不以回收作为履约或正式接续前提 |

自然年边界示例：12月31日首次绑定，次年1月1日已进入下一自然年；这允许相邻年度的换新间隔很短，不能在实现时擅改为“满一年”。“首次绑定”不是每次转售都重启一个滚动年度。

**cece已明确：额度随数字物品按自然年记录。** 接收人继承该物品当年剩余额度，转售不扣减，也不重置已使用次数。例：甲今年已换新一次，再转售给乙，乙今年不能再次换新，次年恢复一次；不能通过换持有人获得同年度额外额度。

**实施前还需明确：** 建议正式换新接续完成时记为使用一次，申请时保留额度以防并行超用，取消/失败不扣次数；跨年办理按申请年还是完成年占用、统一时区须进一步确认。不能从“自然年一次”自行推导这些政策。

## 3. 履约与正式接续时点

已同意采用“确认收到新实体后，由后台管理员核验交付并明确确认正式接续”的方向；准备完成、发货或物流显示签收本身均不自动切换。原因是准备不代表送达、发货存在丢件、物流签收可能是代签。暂不为此新增用户操作入口或物流平台集成，具体核验证据仍须定稿。

| 阶段 | 应达到的业务结果 |
|---|---|
| 受理 | 核对物品、持有人、业务类型、权益和接收对象；转售受理后的冻结范围/准确时点仍待定 |
| 准备完成 | 新实体、目标尺码/颜色、新芯片及配置核验就绪，作为候选载体，尚不获得当前数字权益 |
| 发货/签收 | 记录履约进度和证据；运输中或物流签收不自动改变当前持有人与授权 |
| 核验交付并正式接续 | 管理员核对实际收货及接收对象后明确确认；新载体激活、旧芯片退出、必要所有权变更及历史一致生效，不能留下半完成或双有效状态 |

定期换新在正式切换前原则上保留旧载体服务；挂失换新保持旧卡阻断。转售应区分“受理后冻结权益”和“正式变更持有人”，不把旧芯片/持有人信息在发货时提前覆盖。

取消、丢件、拒收、重复提交及结果未知需按阶段处理：不盲目重试正式切换，不自动复活挂失/退役旧卡；是否继续保留旧载体服务或解除转售冻结，须按对应资格和争议规则决定，不能套用一个恢复按钮。

## 4. 后台场景与用户侧展示

界面统一称“实体”，当前/历次实体与共用发行资料、稳定数字身份分层，字段归属及只读/编辑范围见[重构提案](admin-make-rebuild.md#24-已同意的三层信息与字段展示)。本稿既有“载体”描述指同一真实实体概念，不改变接续、授权和保留历史规则。

后台以数字物品为稳定业务对象核对身份/权益，从关联分区发起相应处理，芯片页携带关联上下文进入同一流程。简单挂失可采用聚焦确认；换新和转售用专门处理界面承载准备、履约与接续。具体入口/字段/步骤先与cece对齐，不能直接修改原型。

后台保存历任持有人、载体、芯片、申请/处理人、时间和必要证据。用户侧仅按可见权限查看流转摘要，不暴露前任账号、手机号、私人内容、资格证明及内部原因；公开/本人/管理员三层可见范围和时间粒度另定。旧卡碰触后应如何展示历史及服务退出说明仍需定义，不能承诺当前已有该页面。

## 5. 剩余待决与下一步

- 持有人绑定、挂失申请与接收人资格证明，管理员交付核验证据；解除挂失条件。
- 跨年办理额度归属、扣减/保留时点和时区；转售继承物品当年余额已确认，不再待选。
- 费用、可转移权益清单、转售冻结范围及准确时点；取消、丢件、拒收、退款和争议处置。
- 公开流转字段及隐私边界，专门处理界面的入口/字段/步骤；芯片维修是否另行提供。

已确认事项不重新列待选；未决细则在对应流程技术实施前明确。后续接口、独立实体模型、所有权、权益/履约记录、唯一当前授权和额度并发保护需整理技术方案，不在本次文档任务中实施。
