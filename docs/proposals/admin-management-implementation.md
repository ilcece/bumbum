# A：管理后台改版技术方案

本稿承接[已确认的A业务规则](admin-management-update.md)。2026-11-03 cece有条件批准本技术方案，条件为React 19显式组件冒烟，以及图片备份恢复的元数据—文件一致性和离线上传服务恢复验证；具体生效门槛见下文。批准允许完成门槛所需的实现与验证，不能把文档批准写成门槛已通过；全部门槛通过后才按本方案继续完整业务构建。原型只作参考，按Ant Design官方设计规范和交互模式实现，不再补画；人工验收、合并main和生产部署分别处理，当前进度只维护在[TODO](../../TODO.md)。

## 1 推荐方案与审核重点

本轮解决管理员查找、核对和维护芯片/物品的实际任务。复用现有React + Vite + TypeScript、Flask和MySQL工程，保留认证、首次绑定、密钥、配置核验、触碰和统计规则。业务字段、接口适配及权限检查由项目实现；控件、布局、查询表单和只读/编辑体验尽可能交给官方组件。

有条件批准范围：

1. **组件组合：** 使用Ant Design 5.29.3 + ProComponents 2.8.10，接入官方React 19兼容补丁；当前ProComponents稳定版未声明兼容Ant Design 6，不强制忽略依赖冲突。
2. **管理能力：** 补芯片独立详情、批次/款式编辑、目标查询覆盖和关联详情读取；详情与编辑共用业务字段定义，普通资料一次保存，不将一个保存按钮拆成多个可能部分成功的写请求。
3. **图片落地：** 使用Upload组件和现有ECS的独立持久目录，新增一张图片元数据表。图片不设公开静态目录，读取沿用管理员会话或用户查看资格。新增文件需要与数据库配套备份；不新增OSS、CDN、Redis、队列或媒体管理平台。

**生效必要门槛：** 第2.2节的React 19显式冒烟和第6节的图片配套备份恢复必须有实际通过证据，缺一项、失败或跳过均不视为本方案已生效，不进入完整业务迁移，也不得生产启用上传。这是有条件批准的前提，不是发布时可略过的普通检查；未通过前仅推进取得这些证据所必需的隔离实现和验证。通过后仍不自动获得合并或生产部署授权。

### 1.1 有实质差异的选项

| 事项 | 推荐 | 替代与代价 |
|---|---|---|
| 组件版本 | antd 5 + ProComponents稳定版，使用官方React 19补丁 | antd 6可直接支持React 19，但当前ProComponents稳定版peerDependencies仅列4/5；只用6的基础组件需要更多页面组合。待ProComponents正式支持6时另评估升级，本轮不同时承担跨主版本适配 |
| 图片存储 | 现有ECS独立目录，应用鉴权读取，适合当前单机、小规模维护 | OSS私有桶更适合后续扩容及多实例，但要新增资源、身份权限、SDK和存储/请求费用。当前没有必须增加这项云服务的证据；仅保留URL输入更省事，但不能完成本地图片上传目标 |

推荐方案不增加独立服务订阅，仍消耗ECS磁盘、带宽及备份空间，不等于零成本。磁盘故障会损失未备份图片；跨实例共享、异地图片备份和大规模分发不包含在本次实现中。生产启用前须核实可用空间及备份去向，不能只凭构建通过上线。

### 2.2 React 19补丁的显式冒烟门槛

使用上述锁定组合和真实浏览器执行以下矩阵，构建成功不代替运行证据。Modal、Notification覆盖静态调用及实际使用的App/Hook上下文调用；Upload和Form没有对应的静态弹层API，分别验证其真实上传回调和Form.useForm等官方接口，不编造不存在的方法。

| 对象 | 必须实际触发的操作 | 通过依据 |
|---|---|---|
| Upload | 选文件、customRequest成功/失败/取消、受控fileList更新及删除 | 对应回调和列表状态正确，失败不变成功，取消后晚到响应不恢复已移除文件；冒烟用隔离HTTP服务，不冒充业务上传接口验收 |
| Modal | Modal.confirm及关联静态打开/更新/销毁、确认/取消；App/Hook实例同类动作 | 弹层真实挂载与卸载、按钮和回调正常，关闭后无残留遮罩、焦点可返回；不出现ReactDOM.render不兼容错误 |
| Notification | notification.open/success等静态调用、更新/关闭/销毁；App上下文实例同类动作 | 通知真实显示、更新和移除，中文与上下文配置按所用方式生效，无残留节点或不兼容异常 |
| Form | Form.useForm配合setFieldsValue、validateFields、resetFields、提交与错误滚动定位 | 必填拒绝、合法提交、切换记录/重置不带旧值，readonly展示和可编辑字段行为正确；不因无异常就推定校验通过 |

自动记录各场景结果和浏览器pageerror/console error，识别官方静态方法不继承上下文的既有限制，不将限制误报为主题继承已通过；业务界面优先App上下文方式。缺依赖、无法启动浏览器或任一场景失败时保留未通过结论并暂停依赖该组合的迁移。

可重复执行的[组件冒烟](../../tests/test_antd_compatibility.py)使用独立测试页面，不加入正式入口；操作与依赖准备见[本地运行第13节](../LOCAL_DEVELOPMENT.md#13-a方案生效门槛组件冒烟与图片离线恢复)。通过证据不外推为业务上传、权限或整条后台流程验收。

## 3 前端复用与连续流程

### 3.1 官方能力与最小业务适配

| 任务 | 官方实现 | 本项目只补什么 |
|---|---|---|
| 页面框架 | ConfigProvider、App、ProLayout、PageContainer | 一个中文与主题入口、已交付菜单和现有会话门禁；工作台统计图和真实运行检查保留 |
| 列表查询 | ProTable的查询表单、request及分页 | 将已提交条件转换为API参数、结果校验、错误处理；返回`data/success/total`，不复制一套筛选/分页控件 |
| 详情与编辑 | ProDescriptions、ProForm及官方readonly字段 | 芯片、物品各有一份带类型的字段定义，详情/编辑均由它生成；编辑仅放开白名单，图片、关联等用官方组件组合。不是数据库驱动的通用表单系统 |
| 创建 | 官方ModalForm/DrawerForm或页面表单 | 现行编号校验、重复结果、确切记录定位、继续创建清空；容器按官方适用模式选用，不照搬Figma抽屉 |
| 图片 | Upload受控fileList、customRequest、Image预览 | 上传/取消/重试请求适配，区分暂存与已保存关联；不自制上传列表或媒体库 |
| 反馈和确认 | App上下文内的Message/Notification、Modal、Alert、Empty、Result等 | 业务结果、只读原因、会话失效及未知结果核对；不重写弹层或通知系统 |
| 返回与离开保护 | React Router的数据路由、useBlocker、浏览器beforeunload | 保存后继续／放弃继续／取消的业务分支，以及来源记录和列表位置；刷新/关闭使用浏览器原生提醒 |

集中配置品牌主题与Token，不覆盖大批官方内部CSS。详情与编辑使用相同的适用业务字段、名称和数据来源；只读字段可复制、可跳转，不靠隐藏或禁用输入框代替完整详情。饰品保留现有可读资料，不新增尚未定义的编辑模板；尺码表按现有数据只读展示并在保存时保留。

按流程替换ChipPanel、ItemPanel、ItemProfileEditor和相关绑定/密钥弹层中的外观组件，复用其API调用及业务规则。登录、共享框架、真实工作台和检查入口使用同一主题与基础组件；不借此重写统计聚合、图表算法或认证。整条流程交付后删除其已替代控件/样式；只有rg和构建确认无其他引用才移除旧依赖，不提前删共享Radix/Tailwind实现。

### 3.2 查询、关联与保存状态

- 采用普通管理路由，如`/chips`、`/chips/:id`、`/chips/:id/edit`及对应`/items`路由。已提交查询、项目、状态、页码放URL；滚动位置和安全的站内返回位置放路由state。返回目标只接受本管理端已知路由，不接受外站URL或凭证。直接打开详情无来源时返回对应列表。
- 表单输入和未提交筛选保留在当前组件；不把密码、CSRF、密钥、SUN读数或编辑草稿写入URL/localStorage。刷新恢复已提交查询和详情位置，未保存输入按离开保护处理，不承诺跨刷新恢复草稿。
- 查询/重置按官方表单模式执行，条件变化回第1页。关联通过接口返回的真实对象ID读取，不按关键词或“第一行”推测；记录切换以ID重置表单，旧请求取消或忽略，避免慢响应覆盖新对象。
- 创建成功使用返回ID查看确切记录；继续创建保留项目，清空已提交身份、款式及本次输入，不修改原列表条件。普通保存成功更新详情并按原条件刷新列表；记录不再匹配时解释原因。刷新失败只报刷新失败，不能将已确认保存改报失败。
- 保存期间阻止重复提交；有上传中的文件时不提交资料。401隐藏管理资料并回登录；CSRF失效只更新会话，保留输入让管理员再提交，不自动重放写请求。超时/断网先按对象ID核对，创建按唯一业务编号核对；不能确认时明确显示未知结果，不盲目重试。

## 5 图片上传、读取与持久化

### 5.1 存储与文件限制

图片后端已按[API第4.1节](../../API_CONTRACT.md#41-私有图片上传暂存与读取)和[附录第9节](../IMPLEMENTATION_DETAILS.md#9-服装资料与启停实现)纳入当前定义，不在提案重复维护限制。实测发现16MP透明WebP超出256MiB配额，已依据本方案“测量后修订、不自动扩容”的约定收紧为8MP；JPEG/PNG保持16MP。对应上限必须在容器中实测正常处理、超限提前拒绝及无OOM，不能只凭构建或像素估算。生产仍须落实第6节实际备份前提。

### 5.2 元数据与保存关系

005元数据结构、uploading/pending/attached/retired/deleting生命周期、文件先完成再关联和短事务锁规则已转入上述API/附录。默认预览的到期技术维护见[本地第14节](../LOCAL_DEVELOPMENT.md#14-物品与私有图片后端升级)，不执行B数据清理、不新增定时服务。完整Upload页面仍须按第3节区分暂存/保存、失败/取消/未知结果，不自动重放写请求。

### 5.3 接口与访问资格

管理上传和状态/预览、用户tap Cookie或兼容令牌读取均见API第4.1节。只对精确multipart入口放行，原JSON认证及正文限制保留；用户读图不续期/计数/消费资格。没有匿名图片目录、任意路径读取或服务端远程抓图。

### 5.4 兼容现有URL与用户页

稳定引用按元数据精确识别，读取按配置映射当前管理或用户入口；不批量改写旧外部URL，也不将用户H5迁入Ant Design。部署准备见[杭州第10节](../HANGZHOU_DEPLOYMENT.md#10-私有图片的升级与持久目录准备)，实际升级/部署/启用仍独立授权，不因模板已改就宣称服务器已变更。

## 6 数据库升级、文件备份与回退

普通批次/款式/查询和关联摘要使用现有表，不改身份、绑定约束或状态枚举。图片部分新增005_media_assets.sql及对应空库schema，升级入口、/api/ready结构识别和隔离测试同步更新。只新增媒体表及明确索引，不重建库、不迁移历史图、不执行B清理。新表须先建好再运行包含该schema的新后端；MEDIA_ENABLED=false只关闭文件写入，不跳过数据库版本检查。

已有库按环境手册先核目标、结构、备份可读及回退前提，再执行另行获准的迁移；MySQL DDL不宣称可整笔回滚。升级后检查列、主键、外键、唯一键及生效CHECK，ready只读，不自动修复未知结构。实施时更新本地与杭州迁移入口，不把香港旧库步骤套到RDS。

媒体目录由部署准备显式创建，核对所属环境、非符号链接和10001可写权限；不自动修改已有未知目录。容器重建/镜像切换不删目录，不用`down -v`清理。上传关闭时已有图片读取仍可用；启用后目录或容量检查异常须可见，不报假成功。

**配套备份恢复是本方案生效的必要门槛，不能后移为普通部署检查。** 先在独立测试目标用合成图和对应数据库记录验证“profile引用 + media_asset元数据 + 图片目录”的可恢复性，且满足两个维度：

1. **元数据—文件一致性：** 暂停上传/图片关联变更与媒体清理并等待在途写入结束，从同一冻结窗口取得数据库和文件备份。备份清单记录对象归属、引用、大小与sha256；恢复到全新隔离目标后，从每个已保存引用核对元数据、文件存在、内容摘要及可读性，不能只数文件或只看数据库行。缺图、坏图、错对象和错时间点组合均应被识别并阻止宣告恢复成功；失败不覆盖已有目标或损坏备份源。
2. **恢复不依赖上传服务在线：** 备份完成后停止源上传HTTP服务，在目标侧关闭上传入口并使其不可访问；仅使用数据库恢复工具、文件备份和独立校验命令完成恢复。不调用上传API、不经上传重新生成图片、不依赖源服务查询补齐元数据。先完成离线一致性校验，再按需启动只读服务核对图片可读；整个恢复期间上传入口保持关闭。

两维度都须有实际通过证据，并包含至少一组缺失/篡改文件的拒绝对照；只有操作说明、单独数据库备份、重新上传成功或构建通过都不满足门槛。验证操作与结果分别纳入现有运行手册和CHANGELOG，未通过/跳过时在TODO保持阻塞，默认关闭上传，不得声称方案已生效。

离线核对由[媒体备份模块](../../core/media_backup.py)和[独立命令](../../scripts/media_backup.py)实现，数据库原生转储/恢复与文件还原分开；[隔离恢复测试](../../tests/test_media_backup.py)验证新库、上传服务停止及错误拒绝。工具不启动业务/上传服务，只在数据库元数据与备份匹配后向新目录还原文件；冻结写入仍须操作者实际落实。具体命令只维护在[本地运行第13节](../LOCAL_DEVELOPMENT.md#13-a方案生效门槛组件冒烟与图片离线恢复)。

生产侧还必须有可用的配套备份与恢复前提，备份去向不能只在同一故障磁盘；保留范围、去向和实际费用在生产启用前核实。隔离演练不能代替真实目标的资源准备，缺少这些前提仍不得生产启用上传。该验证只覆盖本功能，不将其写成杭州整库PITR专项已通过。

回退优先关闭新上传、保留新读取能力，必要时仅回退管理UI；已经保存新图后，直接切回不认识媒体路由的旧后端会造成图片不可用，须先准备含媒体读取的兼容回退版本。新增表/文件原地保留，不删库、不删图片、不覆盖后来业务记录。真正数据库或文件恢复要明确恢复窗口和后来写入的处理，另行授权；代码回退不代替数据恢复。

## 7 构建顺序与验收

按完整任务分步构建，方便发现问题，不减少A整体范围：

1. 先严格解析锁定依赖，完成第2.2节显式冒烟及第6节所必需的隔离媒体/恢复实现与验证；两项门槛均通过后，建立统一主题与路由并推进下列完整流程。
2. 完成芯片查询→详情→批次编辑→返回/继续创建，并迁移原首次绑定、密钥和配置动作的外观，保持原业务检查。
3. 完成物品查询→详情→款式/服装资料原子编辑→关联往返，并实现图片元数据、上传与受控读取；补迁移/备份/回退入口。
4. 核对共享框架、登录、真实统计和运行检查回归，退出已替代的重复控件；提交完整技术证据，交cece验收。

| 验证组 | 构建阶段需取得的证据 |
|---|---|
| 1 官方组件与流程 | 必须有第2.2节Upload、Modal、Notification、Form显式运行矩阵证据，覆盖所列静态调用；两个前端构建只证明可编译。管理端另在1280×720、1440×900检查查询/重置/分页、详情与编辑字段一致、只读、焦点与键盘、返回和创建清空；不以截图像原型判定通过 |
| 2 查询与普通事务 | 独立MySQL验证每个目标条件、北京时间边界、跨页总数与一致性、特殊字符、无关联/无资料、页码修正；编辑/审计一起成功或失败、只读字段拒绝、空值/重复款式、归档/项目限制及旧接口兼容 |
| 3 图片生命周期与权限 | 合成JPEG/PNG/WebP及伪格式/损坏/过大/多帧样例；限额、跨worker并发、内存/耗时；上传失败/未知结果/取消/保存/移除/过期清理；路径/归属/CSRF/失效会话、跨物品Cookie或token拒绝，普通JSON限制不被放宽 |
| 4 网关与已有业务回归 | 浏览器、独立数据库及受影响TLS网关检查；精确上传体积限制、20张图正常读取、无匿名目录与管理路由泄露；已有登记、绑定占用、密钥配置、验证去重、统计及查看资格规则回归，不碰真实卡或生产记录 |
| 5 持久化与交付 | 第6节配套备份恢复的元数据—文件一致性、源上传服务停止/目标上传关闭仍可恢复及缺失/篡改拒绝证据，须先于本方案生效取得；另检查隔离环境重建容器后图片仍在、005升级/未知结构拒绝及保留图片读取的回退。cece按芯片维护、物品维护及图片/异常三组验收，真实服务器另行授权验证 |

测试补进已有管理、视图、认证、浏览器、杭州和用户网关测试，图片独立模块按需新增针对性测试；使用现有pytest/MySQL/Playwright和CI，不新建测试平台。命令仍集中在LOCAL_DEVELOPMENT，操作/验收补入现有手册。图片目录备份不是RDS PITR、实卡、量产或全服务器灾难恢复的替代证据。

## 8 实施时的文档同步与审批边界

按有条件批准的范围及门槛，随实际实现同步API_CONTRACT、TECH_SPEC/技术附录、schema/迁移、依赖锁、配置示例、本地/杭州运行和相关验收手册；产品提案随实现交付纳入现行模块规范，避免并存两套规则。批准条件、门槛证据、人工验收和正式发布不能互相替代。

cece已附条件批准第1节的范围及第5节的文件限制/保留规则，不重新索要同一批准；AI负责取得门槛证据并在生效后完成范围内构建。常规官方组件配置、字段适配和文件拆分由AI处理，不逐项索要确认。当前批准不涵盖B生产验证清理、C纠错、D换新、未定义的饰品资料、批量/导出、图片排序或裁剪；合并和生产资源/数据操作仍按[协作授权规则](../../AGENTS.md#3-哪些可以继续做哪些需要确认)。
