# 管理后台 UI/UE 一致性复盘

2026-11-10。本次复盘针对已经交付的后台界面。完整功能和待验收状态分别见[桌面走查](ADMIN_DESKTOP.md#全后台-uiue-走查范围)与[待办](../TODO.md)。现行交互规则维护在[后台设计与交互规范](ADMIN_UI_GUIDELINES.md)。

## 结论

最主要的原因是以单页或单功能为交付单位，缺少跨模块的交互样板和验收门槛。其次，我把组件已选型、元素存在和功能可用当成了界面通过。遇到反馈后又先改被指出的页面，扩大了局部实现的差异。更换 CSS 工具可以让视觉参数更容易检查，但这一条工作链仍需修正。

## 为什么当时没发现

我从现有页面和接口反推界面，跳过了从管理员要办的事情和操作对象出发的设计步骤。每页都可以独立写成一种看似合理的做法。如果在写代码前做一次同类入口对照，指标卡的两种点击范围就会直接暴露。查看手机号也应先问“这个动作改变哪一项信息的可见性”，再决定放在哪，权限和审计仍由原接口负责。

测试也重复了同一个视角。原检查点是“能打开详情”和“能查看完整手机号并生成审计”。即便按钮位置、整卡命中范围与邻近页面完全不同，这些检查也能通过。前端联调跑通后，我缺少一次独立的视觉与交互检查，没有按实际屏幕上的信息层级、操作归属和点击预期回看，最终把功能通过报成了整体通过。

## 前后端分离与本次问题的关系

现行[架构](../TECH_SPEC.md)把网页和业务服务分开，前端通过接口取得字段、权限和状态。这个边界决定谁负责数据和规则。库存指标与触碰指标的点击位置、手机号查看动作的位置、同类表单的布局，都由前端自己决定。相同的接口结果可以供同一套组件使用，也可以被不同页面各自排版。本次修复复用同一份接口返回就能统一两种指标卡，说明差异来自前端实现与交付流程。

前后端分离确实容易放大一个排期问题。如果先以接口可调用为完成点，设计和真实联调再分别排到末尾，视觉走查就容易被压缩。仓库现行规则已经明确统一协作责任，并要求核对正式界面的真实视觉和交互。缺口在执行。应保留架构边界，按一条用户任务一起交付设计样板、接口状态和真实页面验收。可用合成数据先对齐布局与交互，再用真实接口验证加载、成功、失败和权限。[项目协作规范](../AGENTS.md) · [前端协作](FRONTEND_COLLABORATION.md)

## Ant Design 与 Tailwind 的判断

Ant Design 的组件属性、组件 Token、ProComponents 封装和局部 CSS 分布在不同层，追查一个间距或焦点表现确实比读简单 HTML 的 utility class 更费工。检查时应沿现有组件的公开属性、项目主题配置、实际 DOM 和最终截图逐层核对。我能读取这些层。这次已经确认的两项问题都能从项目 JSX 直接看出，指标卡有不同的点击入口，手机号动作在卡片底栏。代码阅读的复杂度增加了核查成本，漏掉同类对照和动作归属才是这两项返工的直接原因。[Ant Design 主题文档](https://ant.design/docs/react/customize-theme/)

Tailwind 的 `@theme` 适合集中维护颜色、字号、间距和圆角，让这些值和 utility class 的对应关系更直接。它能降低定位样式的成本。点击范围、信息层级、表单是否可离开和敏感动作的位置仍由项目组件及交互规则决定。全后台换成 Tailwind 后，还要明确表格、表单、抽屉和弹窗分别复用哪些组件，并重新验证分页、关联回填、焦点、返回和权限等行为。[Tailwind 主题变量](https://tailwindcss.com/docs/theme)

**本阶段继续用现有 Ant Design / ProComponents。** 主题层沿用现有 Token，把颜色、密度、字号和边框集中维护。业务层先收口指标卡、字段动作、列表、详情、录入与确认。以用户认可的现有视觉稿或本轮标准样板作为验收参照。后续若某类页面确实难以实现参考效果，可以选一个真实页面，在同数据、同状态、同尺寸下比较两种实现的视觉结果、代码维护点和业务回归成本，再决定是否迁移该层。

## 执行顺序与交付门槛

1. **先盘点同类入口。** 检查工作台、订单、数字物品与实体、款式与发行、芯片、用户、系统与登录。标记每个动作的对象、容器、成功去向、空态和错误处理。
2. **选可复用的参考。** 用现有参考稿或真实页面确定指标、列表、抽屉、表单、确认和字段动作的样板。确定后批量改共享实现，并清点全部调用点。
3. **按证据交付。** 1920×1080 稳定截图检查层级和一致性，浏览器操作验证点击范围、键盘、回填与返回，业务回归验证数据和审计。待验项目保留明确状态。
4. **把步骤固化到项目 Skill。** `bumbum-admin-ui` 将后台修改引到同一规范、同类入口盘点和分层验收。它是项目规则的执行入口，结果仍由真实页面和业务证据验证。
