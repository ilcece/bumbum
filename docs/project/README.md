## 项目当前结论

- 当前执行方向：香港ECS、Ubuntu22.04 LTS 64位、单实例TypeScript Web应用、SQLite、Docker Compose、Caddy、NTAG424 DNA AES-SDM。
- 历史交付软件v1.2.1，支持nfc.cool的`picc_data/cmac`及原`p/m`参数；本地保留源码和原始交付ZIP。
- **2026-10-23核对发现：[仓库](https://github.com/ilcece/bumbum)的main现为`fdbeb4a`，仅含初始README，不含应用源码。不要把当前main下载包当成可部署的v1.2.1。** 本资料采用本地保存的`6b333f4`代码基线，在线资料另存独立归档分支，不覆盖main。
- 用户已提供新ECS成功建表/检查、第一枚标签PENDING配置、nfc.cool SUN成功及只读文件设置证据。
- 尚未收到“用户ECS已运行v1.2.1 → 服务器新读数校验成功 → 后台ACTIVE → 再次触碰成功”的完整现场确认。不能把软件测试或App内绿色标记当作这条闭环已完成。
- 主密钥派生、批量导入、管理员独立域名和Figma改版是讨论方案，尚未实现。

## 归档约定

这不是逐字聊天记录，而是按当前事实整理的项目资料。早期需求V0.2属于固定入口/MySQL阶段；后续用户明确扩展到SQLite与真实动态验真，新增范围以本资料包为准。

- “代码已实现”：从v1.2.1源码核对。
- “开发测试通过”：此前隔离环境实际验证，有日期和版本，不代表今天重新测试或生产已验收。
- “现场确认”：用户提供的终端/手机结果，不代表维护者拥有ECS或手机远程控制权。
- “待确认”：会话没有完整证据；不以默认值补齐。
- 文档不收录真实密钥、管理员密码、SESSION_SECRET、可直接消费的动态读数或基础设施登录凭证。仅保留必要的非秘密资产编号与公开域名。

## 文档使用提醒

命令分为全新安装、现有升级、备份恢复、只读诊断四类，不要从头到尾全部执行。已经有数据的ECS不要重新生成配置、删除密钥或清空数据库。

历史文档保留在本地v1.2.1源码归档的docs目录；当前远端main不含这些文件。查阅历史时以对应版本为限，尤其不要拿早期“不启用SUN”或旧p/m偏移覆盖现有nfc.cool配置。
